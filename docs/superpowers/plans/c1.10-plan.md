### 确定性算法代码块（实现必须逐条满足）

以下不是新的对外接口，而是 T2 实现必须固定的投影顺序；实现可以拆私有函数，但不得改变这些输入/输出和先后关系：

```ts
const domainTable = input.organization === 'best' && input.best
  ? input.best.domains
  : input.baseline.domains ?? {}

const containerDomain = (containerId: string): string => input.organization === 'best'
  ? input.best?.containers[containerId] ?? ''
  : input.baseline.containers[containerId]?.domain ?? ''

const selectedContainerIds = new Set(
  Object.keys(input.baseline.containers).filter((id) => containerDomain(id) === input.domainId),
)

const declaration = input.decls?.[input.domainId]
const totalDomainCount = Object.keys(input.best?.domains ?? input.baseline.domains ?? {}).length
const declaredDomainCount = Object.keys(input.best?.domains ?? input.baseline.domains ?? {})
  .filter((id) => input.decls?.[id] !== undefined).length

const activeEdges = input.baseline.edges.filter(([from, to]) => {
  const fromNode = input.baseline.nodes[from]
  const toNode = input.baseline.nodes[to]
  if (!fromNode || !toNode) return false
  const fromDomain = containerDomain(fromNode.container)
  const toDomain = containerDomain(toNode.container)
  return fromDomain !== '' && toDomain !== '' && fromDomain !== toDomain
})

const inboundEdges = activeEdges.filter(([from, to]) => {
  const fromNode = input.baseline.nodes[from]
  const toNode = input.baseline.nodes[to]
  return toNode !== undefined && containerDomain(toNode.container) === input.domainId
    && fromNode !== undefined && containerDomain(fromNode.container) !== input.domainId
})

const outboundEdges = activeEdges.filter(([from, to]) => {
  const fromNode = input.baseline.nodes[from]
  const toNode = input.baseline.nodes[to]
  return fromNode !== undefined && containerDomain(fromNode.container) === input.domainId
    && toNode !== undefined && containerDomain(toNode.container) !== input.domainId
})
```

实现时继续遵守以下固定规则：

1. best 组织只用 `CgBest.domains`、`CgBest.containers`；best 缺席时 `organizationAvailable=false`，不能把 current 伪装成 best。current 组织只用 baseline 的 domains/containers。
2. 声明永远只读 `input.decls?.[input.domainId]`；组织切换不做 key 映射。覆盖统计以 best 词表为主，best 缺席才用 baseline domains 总数。
3. 实体只取 selected container 内 `modelKind === 'entity'` 的 model 节点；creator/writer 按 `lifecycle.kind` 和 `lifecycle.model` 关联，writer 原样保留 `field`。未知 modelKind/lifecycle kind 不崩溃、不进入实体表。
4. 包目录沿用现状 `containerFacts` 口径：文件最后一个 `/` 之前为 dir；只从 selected container 的节点涉及目录中读取 `CgGraph.packages[dir]`，原样产生 `{dir, summary}`，不生成职责文案；summary 缺失不补默认职责。
5. 入/出端口遍历 `baseline.edges` 原序，按来源/去向领域首次出现顺序聚合 edgeCount；同一目标节点被不同入边命中时每条边产生独立 lane，不静默合并。
6. 每条入边 lane 的 `key` 固定为 ``${fromDomainId}->${input.domainId}:${fromNodeId}->${focusNodeId}:${edgeIndex}``，其中 `edgeIndex` 是原始 `baseline.edges` 下标；focus 为 `to` 节点，depth 0 列只含该节点。
7. focus 先按原序取前 5；超额产生 `{total, shown, reason: 'focus-quota'}`。入缝为 0 时 `lanes=[]`、`noInboundSeams=true`，不造 fallback 主链。
8. 对每个待展开节点先统计其所有有效入边的调用方领域去重数；同一调用方领域重复 40 次只算 1，K=2 不收桩，K=3 时保留节点但标 `collapsed=true`、`collapseReason='shared-by-domains'`，且不生成其下游。
9. 非收桩节点只沿同一选定组织、同一 `domainId` 的出边扩展。每层先按原边序去重 node id，再先计算每个候选节点的 K 收桩状态，最后保留前 8；`droppedNodes` 为被裁掉数，大于 0 时 `truncated=true`。depth 0/1/2/3 均保留列，depth 3 列 `depthLimit=true` 且不继续展开。

```tsx
export function DomainCascadeDrawer({ project, baseline, lane, selectedNodeId, onSelectNode }: DomainCascadeDrawerProps) {
  const [source, setSource] = useState<CgSourceResp | null>(null)
  const [sourceError, setSourceError] = useState('')
  const selected = baseline.nodes[selectedNodeId]

  useEffect(() => {
    if (!selected) {
      setSource(null)
      setSourceError('')
      return
    }
    let current = true
    console.info('[codegraph] cascade source start', { project, id: selectedNodeId, file: selected.file, line: selected.line })
    setSource(null)
    setSourceError('')
    fetchCodegraphSource(project, selected.file, selected.line, 40).then((next) => {
      if (current) {
        console.info('[codegraph] cascade source success', { project, id: selectedNodeId, lines: next.lines.length })
        setSource(next)
      }
    }).catch((err: unknown) => {
      if (current) {
        const message = err instanceof Error ? err.message : String(err)
        console.warn('[codegraph] cascade source failed', { project, id: selectedNodeId, file: selected.file, line: selected.line, error: message })
        setSourceError(message)
      }
    })
    return () => { current = false }
  }, [project, selected, selectedNodeId])

  if (!lane) return null
  return (
    <aside data-cascade-drawer={lane.key}>
      {lane.columns.map((column) => (
        <section key={column.depth} data-cascade-column={column.depth}>
          {column.nodes.map((node) => (
            <button key={node.id} type="button" data-cascade-node={node.id} onClick={() => onSelectNode(node.id)}>
              {node.name}{node.collapsed ? ' · 共享工具，已收桩' : ''}
            </button>
          ))}
          {column.truncated ? <span data-cascade-truncated>本级已截断，丢弃 {column.droppedNodes} 个节点</span> : null}
          {column.depthLimit ? <p>再深是 CLI 的活：<code>codegraph chain --with-source</code></p> : null}
        </section>
      ))}
      {sourceError ? <p data-source-error>源码读取失败：{sourceError}</p> : null}
      {source ? <pre data-source-window>{source.lines.join('\n')}</pre> : null}
    </aside>
  )
}
```

上面代码块中的 `CgSourceResp`、`useEffect`、`useState`、`useMemo`、`fetchCodegraphSource` 均从已有包/文件导入；实现不得在 drawer 里直接调用 `fetch`。源码成功/失败/卸载过期响应分别有上下文日志和清理分支。
