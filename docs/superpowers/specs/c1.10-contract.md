## 2. 冻结清单

每条编号都是独立的 pass/fail 断言。

### 2.1 wire 端点与缺席语义

1. 端点保持 `GET /api/projects/{name}/codegraph`；路径参数、鉴权、成功状态码和既有错误状态码不变。宿主路由现状出处为 handoff `internal/agentd/server.go#registerRoutes`（当前外部 checkout 503 行）。
2. 响应在既有键之外新增可选顶层键 `decls`；不删除或改名 `baseline`、`views`、`stale`、`best`、`target`、`report`。
3. `decls` 的 wire 形状是 `Record<string, CgDomainDecl>`；key 是最优树领域 id，value 与 `codegraph/domains/<id>.json` 的 `DomainDecl` 逐字段等同。
4. 宿主对 `decls` 不做领域映射。
5. 宿主对 `decls` 不补默认值。
6. 宿主对 `decls` 不改写字符串、数组顺序或可选字段。
7. `codegraph/domains/` 目录缺席时，响应**不含** `decls` 键，不发送 `null`，其余响应照常返回。
8. 声明目录存在且成功加载时，响应包含 `decls`；没有声明文件时允许以空对象实现，但实现必须保持「无目录」与「有目录」的判断不阻塞整页。
9. 单个声明加载/解析失败时，宿主告警并省略 `decls`；不得因此把成功的整图响应改成 500。
10. `ValidateDecls` 的 issues 不进入 `decls`；校验结论只留在既有 `report`（若 provider 已提供该段）。
11. 旧 viewer 忽略未知 `decls` 键后仍可读取既有三键；新 viewer 在 `decls` 缺席时显示声明空态，不把缺席当成传输失败。
12. provider 的装配符号保持 `func (s *Server) handleProjectCodegraph(w http.ResponseWriter, r *http.Request)`；当前外部 checkout 现状出处为 handoff `internal/agentd/codegraph.go#handleProjectCodegraph`（27~78 行）。
13. viewer 的 wire 解析入口保持 `func fetchCodegraph(project: string): Promise<CodegraphResp>`；现状出处为 `graph/webui/src/api/client.ts#fetchCodegraph`（56~59 行）。

### 2.3 声明词表迁移与校验

23. `LoadDomainDecls` 仍要求文件名去 `.json` 后等于 `DomainDecl.Domain`；变化只在 Domain 的词表来源，不改变文件名强校验。
24. `ValidateDecls` 的冻结签名改为：

    ```go
    func ValidateDecls(v *View, best *Best, repoRoot string, decls map[string]DomainDecl) []string
    ```

### 2.4 领域页纯函数主缝

38. 新建纯函数模块 `graph/webui/src/app/codegraph/domainpage.ts`；模块不得请求网络、访问 DOM、读取 localStorage 或在组件中聚合。
39. 模块导出 `type DomainOrganization = 'best' | 'current'`。
40. 模块导出 `interface DomainPageInput`：

    ```ts
    interface DomainPageInput {
      baseline: CgGraph
      best?: CgBest
      decls?: CgDomainDecls
      organization: DomainOrganization
      domainId: string
    }
    ```

41. 模块导出 `interface EmptyStates`：`{ noDeclaration: boolean; noInvariants: boolean; noEntities: boolean; noInboundSeams: boolean }`。
42. 模块导出 `interface EntityReadout`：`{ id: string; node: CgNode; creators: string[]; writers: Array<{ id: string; field?: string }> }`。
43. 模块导出 `interface PackageReadout`：`{ dir: string; summary: string }`。
44. 模块导出 `interface SemanticViewModel`：`{ domainId: string; label: string; declaration?: CgDomainDecl; declaredDomainCount: number; totalDomainCount: number; entities: EntityReadout[]; packages: PackageReadout[]; empty: EmptyStates }`。
45. 模块导出 `interface DomainPort`：`{ domainId: string; label: string; edgeCount: number }`。
46. 模块导出 `interface FocusTruncation`：`{ total: number; shown: number; reason: 'focus-quota' }`。
47. 模块导出 `interface CascadeNode`：`{ id: string; depth: number; name: string; summary?: string; collapsed: boolean; collapseReason?: 'shared-by-domains' }`。
48. 模块导出 `interface CascadeColumn`：`{ depth: number; nodes: CascadeNode[]; droppedNodes: number; truncated: boolean; depthLimit: boolean }`。
49. 模块导出 `interface DomainLane`：`{ key: string; fromDomainId: string; focusNodeId: string; columns: CascadeColumn[] }`。
50. 模块导出 `interface StructureViewModel`：`{ domainId: string; inboundPorts: DomainPort[]; lanes: DomainLane[]; outboundPorts: DomainPort[]; inboundEdgeCount: number; focusTruncation?: FocusTruncation; noInboundSeams: boolean }`。
51. 模块导出 `interface DomainPageModel`：`{ organization: DomainOrganization; organizationAvailable: boolean; semantic: SemanticViewModel; structure: StructureViewModel }`。
52. 模块导出主缝 `function deriveDomainPage(input: DomainPageInput): DomainPageModel`；调用方必须是领域页组件层，组件只消费模型与维护选中态，不在 JSX 内重算。
53. `organization === 'best'` 时领域、容器和端口归属从 `CgBest` 解析；`organization === 'current'` 时从 `baseline.domains` 与 `baseline.containers[*].domain` 解析。
54. 语义声明数据始终从 `decls[domainId]` 读取；组织切换不得把声明映射回现状领域词表。
55. best 不存在时，best 组织按钮不可用；纯函数返回 `organizationAvailable: false`，不得把现状领域伪装成 best。
56. `SemanticViewModel.entities` 只列当前选定组织内 `modelKind === 'entity'` 的 model 节点。
57. 每个实体的 `creators` 来自 `CgGraph.lifecycle` 中 `kind === 'creator'` 且 `model` 等于实体 id 的记录。
58. 每个实体的 `writers` 来自 `CgGraph.lifecycle` 中 `kind === 'writer'` 且 `model` 等于实体 id 的记录，并保留 `field`。
59. `SemanticViewModel.packages` 只转录 `CgGraph.packages` 的目录与 summary，不概括、不生成职责文案。
60. `declaredDomainCount` 与 `totalDomainCount` 统计最优词表覆盖；best 缺席时才允许退回当前图 domains 的总数，不能改变声明 key 的语义。
61. 领域无声明时，空态必须表达「声明是人写的应然承诺、扫描器不生成」、全仓覆盖读数和 `codegraph/domains/<最优领域id>.json` 写入路径。
62. 领域无不变式时，空态必须明确「没有不变式声明」，不得只写「暂无数据」。
63. 领域无实体时，空态必须明确机械表只列 `modelKind=entity`，不把 dto/config 当实体。
64. 领域无跨域入边时，空态必须明确「本域没有跨域入边」并引导读包职责与实体表；不得编造主链。

### 2.5 结构模型、阈值和确定性

65. 结构模型的左端口是入边来源领域聚合；每个 `DomainPort.edgeCount` 是选定组织下活跃跨域入边条数。
66. 结构模型的右端口是出边去向领域聚合；每个 `DomainPort.edgeCount` 是选定组织下活跃跨域出边条数。
67. 一个 `DomainLane` 的 focus 是一条跨域入边，`key` 必须能稳定区分 `from → to`；同一目标节点被多个跨域边命中时按入边记录保留，不把不同来源静默合并。
68. 入边、出边和每级子节点都按原始 `baseline.edges` 的顺序处理；不得改用对象 key 遍历顺序或名称排序改变配额裁剪结果。
69. 收桩阈值固定为调用方**领域去重数 K≥3**，不是原始入边计数。
70. 收桩统计的领域集合由 `sharedCallerDomains(v)` 语义给出：统计调用方所属领域去重数；同一领域调用 40 次仍只算 1，不得因此收桩。
71. K≥3 命中时节点保留在 `CascadeNode`，但 `collapsed` 必须为 `true`、`collapseReason` 为 `shared-by-domains`，不得展开其下游。
72. 跨域 focus 配额固定为 5；超过 5 条时只保留按入边顺序的前 5 条。
73. 超过 focus 配额时必须写 `focusTruncation: {total, shown, reason: 'focus-quota'}`；不得静默丢掉尾部 focus。
74. 级联深度固定为 3；focus 节点为 depth 0，向域内下游扩展 3 条边，depth 3 列必须标 `depthLimit: true`。
75. 到达 depth 3 时模型与组件必须显式显示「再深是 CLI 的活」，并指向 `codegraph chain --with-source`；查看器不做无限下钻。
76. 每级节点上限固定为 8；同级按跨域入边/子边的既定顺序保留前 8 个。
77. 每级被丢弃的节点数必须写入该 `CascadeColumn.droppedNodes`；大于 0 时 `truncated` 必须为 `true`，组件必须可见地渲染截断标记。
78. 每级裁剪的节点不能改变 K≥3 收桩判定；先判断收桩，再对仍需展开的同级节点做 8 个上限裁剪。
79. viewer 侧四个平行副本常量只存在于 `domainpage.ts`：`DOMAIN_CASCADE_DEPTH = 3`、`DOMAIN_FOCUS_QUOTA = 5`、`DOMAIN_LEVEL_NODE_LIMIT = 8`、`DOMAIN_SHARED_CALLER_DOMAINS = 3`；前三个阈值的同源 Go 常量是上游 C1.5 `graph/codegraph/assemble.go` 的 `DefaultContextDepth = 3`、`DefaultContextFocusQuota = 5`、`DefaultUtilSharedByDomains = 3`，该出处当前工作树未验证。
80. 四个常量不进入 `CodegraphResp`、URL、localStorage、环境变量或任何用户配置。

### 2.6 组件与组织切换

81. 领域页新增「语义」与「结构」两个 tab；tab 切换不重新请求 API。
82. 语义 tab 依次显示应然层（职责、不变式/测试锚、状态机、生命周期）与机械层（实体、包职责）。
83. 结构 tab 显示左端口、入缝泳道、右端口；入缝为 0 时显示第 64 条空态而不是流程图。
84. 点泳道或步骤打开右侧级联抽屉；抽屉按列显示 focus、depth 1、depth 2、depth 3，点击列项目继续更新级联选中态。
85. 抽屉底部沿用既有 `fetchCodegraphSource(project, file, line, span = 40)` 源码窗口入口；该现状签名出处为 `graph/webui/src/api/client.ts#fetchCodegraphSource`（61~66 行）。
86. 组织开关只切换 `best`/`current` 画布；语义声明来源和覆盖读数不随开关映射。
87. 分支视图下声明仍来自主线 `decls`；不从 `CgDiff` 或 `codegraph/diffs` 生成分支声明。
88. 不新增路由库；tab、抽屉和组织开关使用组件局部状态与既有面包屑。

## 3. 依赖库既成行为查证

1. `LoadDomainDecls` 读取 `repoRoot/codegraph/domains`；目录不存在返回空 map、nil error：`graph/codegraph/decls.go#LoadDomainDecls`（18~23 行）。因此宿主不能把缺目录当 500。
2. `LoadDomainDecls` 对每个 JSON 使用 `json.Unmarshal`，并强校验文件名与 `decl.Domain` 相等、`responsibility` 非空：`graph/codegraph/decls.go#LoadDomainDecls`（32~48 行）。
3. 当前实现没有调用 `Decoder.DisallowUnknownFields`。Go 标准库 `encoding/json` 文档明确：结构体解码默认忽略未知键（`/usr/local/go/src/encoding/json/encode.go` 38~40 行）；因此 `decls` 的未知字段不应让旧 provider/消费方失败。
4. Go 标准库仅在显式 `Decoder.DisallowUnknownFields` 时才对未知键报错，现状实现未走该分支（`/usr/local/go/src/encoding/json/decode.go` 739~741 行）。
5. 当前 provider 的 `writeJSON` 使用 `json.NewEncoder(w).Encode(v)`，并设置 `Content-Type: application/json; charset=utf-8`：handoff `internal/agentd/server.go#writeJSON`（2142~2147 行）。本卡不改变这一响应编码路径。
6. viewer `request` 使用 `fetch(path, { credentials: 'same-origin' })`，当前代码不加 timeout、retry、polling 或 keepalive：`graph/webui/src/api/client.ts#request`（43~53 行）及文件头第 1~2 行。`decls` 增量不得顺手改变这些行为。
7. viewer `parseResponse` 成功后直接 `await resp.json() as T`，没有运行时 schema 校验：`graph/webui/src/api/client.ts#parseResponse`（26~40 行）。未知 JSON 键由既有消费路径忽略，缺席由可选类型表达。
8. `CgGraph` 既有 `lifecycle`/`packages` 使用可选字段镜像 Go 的 `omitempty`：`graph/webui/src/api/types.ts#CgGraph`（13~18 行）；`decls` 沿同一 additive-only 形态落地。
