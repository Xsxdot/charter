## 方案

1. **生成**：install/check 仍用 `regen_discipline.regen(tmp)` 在临时目录得到七份正文。组成映射不变。无参 `python3 scripts/regen_discipline.py` 仍可写 `OUT`（调试用），但 **不再是安装成功或 check 一致的判据**。文件头那句「现读盘即生效」改成：权威副本在账本，装入走 provision / `discipline put`。
2. **get 分诊（唯一）**：stderr 含子串「记录不存在」= **缺块**；其余 get 非 0 = **账本不可用**。禁止「get 非 0 一律退出 2」（那会让空账本永远装不上纪律块）。
   - check：缺块 = 漂移、退出 1；不可用 = 退出 2。
   - install：缺块 = 对该块 put；不可用 = 退出 2 且该块不 put。
3. **正文切法（唯一）**：跳过版本行之前的任何日志行；命中 `{请求的块名} v{数字}` 之后的**全部字节**与 regen(tmp) 文件逐字比。版本行不算正文。不新 flag。不要复用 `load_ledger_def` 的「最后一行 JSON」。测试夹具给 get 的 stdout 必须是 `"{name} v{N}\n" + 与 regen 相同的正文`，禁止复用 `_ledger_stdout` 的 `Def` JSON。
4. **install 第三步**：对 `compose_map()` 每个块名 `charter-{name}`：get 成功且正文 == 生成结果 → skip、不 put；缺块或正文不同 → `handoff discipline put <name> <tmpfile>`（位置参数，**无 `--file`**）。put 失败硬失败（含库层 64KiB/空正文/非法名），前两步保留，重跑安全。regen 产物不得在 charter 侧截断后静默 put。
5. **check 第三段**：regen 到 tmp，对每个块 get 与 tmp 正文比。不一致或缺块 → 漂移、退出 1。**禁止**再读 `OUT`。负向：get 成功但正文 ≠ tmp 时必须退出 1 且点名块名。
6. **override.discipline 存在性**：只按 get 成功（或复用第三段已解析的名字集合）。**删掉 list。** 账本无、本地 `~/.handoff/discipline` 有同名文件 → 仍报不存在。哨兵 `charter-must-override` 仍故意不查（F-8 只看 nodes 覆盖值）。
7. **回写冻结物**（本卡交付物）：
   - **C-9**：权威副本 = 账本；`<DataDir>/discipline` 三段式标「已退役」。
   - **比对面**：纪律段逐字比 get 正文与 regen(tmp)，不复用 C-11 的 nodes 规则。
   - **C-7** 第三步改为经 `discipline put` 入账本；顺序仍 template→workflow→纪律。
   - **R-4**：改从 B229 `ResolveDispatch` 推导——哨兵不入账本则拒发；本卡 OOS 已禁装 `charter-must-override`，这仍是哨兵成立条件。
   - **R-5**：追记纪律 get 使用同一「记录不存在」子串。
8. **check 仍只读**：不得发出任何 `put`（含 `discipline put`）。只读锁必须看见 `discipline get`，不能只断言 `kinds==["workflow","template"]`。

弃选：

- 继续写 `OUT` 并宣称「写盘即装好」：假绿的根。
- 改 `PutDiscipline` 库层按内容去重：handoff 仓，本卡不动；幂等放 provision。
- check 用 md5 只比长度：立卡时就是按字节发现漂移的，保持逐字。
- 装完真派一次 card dispatch：C7 原想要的安装冒烟，本卡不并（B286 也不代重装 agentd）。

- 只经 CLI：`handoff discipline get|put`（存在性不走 list）。不 import handoff 内部。check 与 install 共用同一处解析；禁止无调用方纯函数占缝。解析函数的名字是落点，归 plan。
- 块名 = `charter-{compose_map 键}`。
- 测试继续标准库 unittest + mock subprocess，不碰真账本。负向假绿必须在 mock 层打到第三段 get 正文。

## 测试决定（接缝清单）

1. **`check()` ← `python3 scripts/charter_provision.py check`**
   - `_run_check_with_ledger` 按 `cmd[1]` 分诊 workflow / template / **discipline**。discipline 成功路径回文本头+正文，不得回 `Def` JSON。
   - 账本正文 == regen(tmp) → 纪律段一致、退出 0。
   - get 成功但正文 ≠ regen(tmp) → 退出 1，报文含块名（**负向假绿锁**）。
   - 账本缺块（stderr 含「记录不存在」）→ 退出 1。
   - 只读锁：calls 里必须有 `discipline get`，必须没有任何 `put`（含 `discipline put`）。
   - 退役 `test_discipline_block_mismatch_is_reported` 的 `patch(rd.OUT)`。

2. **`install()` ← `python3 scripts/charter_provision.py install`**
   - 账本已是最新 → 该块不 `discipline put`。不得再把 `regen` mock 成空映射来跳过第三段。
   - 账本旧或缺块 → `["handoff","discipline","put",name,path]`，无 `--file`。
   - 顺序 template → workflow → discipline。

3. **节点 `override.discipline` 存在性** ← check 的 F-8 循环（复用 get，不 list）
   - 账本有该 name → 不报。
   - 账本无、本地目录有同名文件 → **仍报不存在**。

假缝：不要为了解析 get stdout 抽一个无生产调用方的纯函数当接缝；解析可以是 `load_discipline_body` 这类与 `load_ledger_def` 并列的模块函数，check/install 都调用它，这算缝上符号。

合 main 门：`python3 -m unittest discover -s scripts -p 'test_*.py'` 全绿，且负向假绿那支单独跑失败形态可演示（实现时先红后绿）。不依赖本机 `~/.handoff/discipline` 状态。
