### 3. Viewer 消费面：graph/webui（边界型）

## 三、子卡清单与依赖 DAG

    ┌──────────────┐
    │ A 结果装配器  │（logic）
    └──────┬───────┘
           │
    ┌──────▼───────┐
    │ B context    │（logic）
    └──────┬───────┘
           │
    ┌──────▼───────┐
    │ C CLI 接线    │（boundary）
    └──────────────┘

    D webui wire 收缩（boundary） ───┐
    E skills 文档同步（support） ────┴─→ 协调者整体验收/真机清单

- A 是 B 的唯一代码前置；A 与 D/E 可并行。
- B 完成后 C 才能接 context；C 的真实 stdout JSON 回归是 A/B 与外部 CLI wire 的接缝证据。
- D 不依赖 Go 编译产物，只依赖冻结 wire 语义；E 不依赖运行时代码。若协调者采纳待拍板 1 的合并方案，D 可并入 C，但其 webui 专属验收与缺陷审查不能删除。
- 每张卡的文件集如下均为有界集合；没有命中架构法第三条（前缀家族 ≥5、无子包单包 ≥40、上下文 >2~3 万行）的竖切信号，故不插竖切还债卡。

### A｜结果投影、折叠、源码窗口与预算（graph/codegraph，逻辑型）

#### ①契约引用

契约 §2 Neighborhood/ReAnchor/CheckStale；§3 的常量、QueryOptions、SourceWindow、TokenEstimate、Truncation、AssembledNode、AssembledItem、AssembledResult、ExtractSourceWindow、AssembleResult；§3.1～§3.3 的字段、折叠、预算与 deleted-edge 语义；§6 Go TestRef.Snippet 删除。

#### ②意图与为什么

让 raw BFS 真相与面向 agent 的 compact wire 分层：查询算法继续可还原，结果装配统一负责投影、折叠、源码窗口和 token 预算；同一套装配语义供 chain 与 context 复用。源码仍是本地实时读取，不把代码内容写回 baseline，也不把新 source 字段塞入 TestRef。

#### ③验收

有界文件集内新增/修改的测试必须能由下列命令独立判定；命令退出 0 不是唯一判据，括号内行为断言必须逐条存在：

1. cd graph && go test ./codegraph -run 'Test(AssembleResult|ExtractSourceWindow|NeighborhoodSkipsDeletedOutputEdges|TestRefSnippetWireRemoval)' -count=1 返回 ok；默认普通节点 JSON 只含契约十字段，--full 对旧字段逐字段恢复且不含 snippet，source 不被 --full 关闭。
2. 同一命令的装配测试构造至少两个领域、共享调用点、deleted 节点/边、同距节点和超预算结果：外部领域按 id 排序且 count 为 raw 全量、representatives 最多 3；共享节点按不同 caller 领域数命中 3 且只出现一个 item；输出边两端均为 live 普通节点。
3. ExtractSourceWindow 测试用 fixture 真实文件断言 span=1、span=40、span=200、文件首尾收缩；span=0、201、负 MaxTokens 返回参数错误而非静默钳制；文件缺失/未扫描/空文件不伪造 source，保留节点状态。
4. 预算测试断言 compact JSON UTF-8 bytes/3、approximate:true、method:"utf8-json-bytes/3"；发生截断时同时有 atDepth、raw droppedNodes、reason:"max-tokens"，未截断时没有 truncated；不会只依赖节点数量等中途副产物。
5. 变异复验必须能让以下任一改动使相应测试失败后再恢复：删除 deleted-edge 输出过滤、把 shared-util 阈值改为 2、让 Full 关闭 source、把 droppedNodes 改为已输出节点数。否则不得把内部 helper 绿灯当作行为证据。

### B｜领域上下文组合器（graph/codegraph，逻辑型）

#### ①契约引用

契约 §2 DomainTree、DomainTreeWithBest（context 禁用 best 路径）、LoadDomainDecls、EntityLookup；§4 的 ContextPackage、ContextInterface、ContextDomain、FocusTruncation、ContextResult、AssembleContext 及八步组装顺序；§3 的 QueryOptions/AssembleResult；§5.2 context 不暴露 depth override。

#### ②意图与为什么

把现状视图中的一个领域所需的职责声明、包摘要、对外接口、真实实体和主调用链装成一个结果，让调用方只需一次 context 查询；父领域按整棵子树边界理解，未声明领域仍有机械降级包，不把 best-only id 静默当作现状不存在。

#### ③验收

1. cd graph && go test ./codegraph -run 'TestAssembleContext' -count=1 返回 ok；视图词表中的叶子领域、父领域和 best-only/未知 id 分别走到契约规定路径，未知错误文案明确“现状视图词表”并带近似候选，不能引用 best 词表。
2. 有声明 fixture 断言 responsibility、每条 invariant 的 testRef、lifecycle、stateMachine 完整透传；无声明 fixture 返回 warning/机械包而非 error；父领域接口按子树外 caller 判定，不要求用户下钻。
3. Graph.Packages 含有摘要、空摘要和未覆盖目录时，输出每个覆盖目录一行、按 path 字典序、空摘要保持空串；包摘要不进入 chain。
4. 对外接口测试断言 live 跨域边、deleted 节点/边过滤、目标去重、按 id 排序且全量保留；实体表只收 Kind=model && ModelKind=entity，ModelKind 空不计入；全项目未分种时实体表为空并出现“该项目未分种，实体数不可用”的 warning。
5. 焦点测试构造 entry 与接口目标并集、重复 id、deleted entry、父领域外部 caller；按 live 跨域入边数降序、entry 优先、id 字典序取 5，超过 5 只产生 fociTruncated，不得把它混入 chain.truncated；主链固定深度 3、默认 source/fold/collapse/40/30000。
6. B 的测试必须用 AssembleContext 的返回行为作断言，不复制实现中的排序/过滤 helper；焦点配额、未声明降级、modelKind 空值各做一支变异复验，改坏对应规则时测试必须转红。
