## 1. 边界与允许依赖

现状架构形态是两层：`graph/codegraph` 是只读本地数据与查询核心，`graph/cli` 是 Cobra 命令适配层。新增装配器落在 `graph/codegraph`；CLI 只负责解析参数、调用装配器、把结果写到 stdout。禁止 `codegraph` 反向依赖 `cli`、web UI、handoff 内部包或网络客户端。

`graph/codegraph` 继续只用 Go 标准库；`graph/cli` 的直接依赖继续只有 `github.com/spf13/cobra v1.10.2`。依赖现状由 `graph/cli/deps_test.go#TestModuleDependencyAllowlist` 执法，Cobra 的位置参数校验行为由 v1.10.2 `args.go#MinimumNArgs` / `#ExactArgs` 实现。

CLI 的 JSON 边界继续是 `graph/cli/cli.go#graphPrintJSON`：缩进 JSON、关闭 HTML 转义、写入 `cmd.OutOrStdout()`。成功结果只写 stdout；错误沿现有 Cobra/main 路径走 stderr 和非零退出。

本刀不新增加载路径：

- 视图仍由 `graph/cli/cli.go#graphLoadView` 得到，基线与 `--view` diff 的合并仍由 `graph/codegraph/merge.go#Merge` 完成。
- 领域声明仍由 `graph/codegraph/decls.go#LoadDomainDecls` 读取。
- `Graph.Packages` 是基线中的包摘要源；`merge.go#View` 当前不携带 `Packages`，context 必须从 CLI 已加载的 `*Graph` 取它，不得再次读另一份文件。

## 2. 现状签名（实现必须复用）

以下是本轮对现状代码的签名核对，不是新设计：

| 现状符号 | 精确签名 | 契约用途 |
|---|---|---|
| `graph/codegraph/query.go#Neighborhood` | `func Neighborhood(v *View, foci []string, down, up int) (*Result, error)` | 保持多源 BFS；`down/up` 中 `0` 表示不查、`-1` 表示不限；deleted 节点/边不参与遍历 |
| `graph/codegraph/query.go#Resolve` | `func Resolve(v *View, arg string) (string, error)` | chain/who-calls 的 id/name 决议不变 |
| `graph/codegraph/sym.go#ReAnchor` | `func ReAnchor(repoRoot string, n Node) (int, string)` | 源码窗口使用同一再锚定结果；状态值沿现状为 `ok`、`moved`、`vanished`、`file_missing`、`unscanned` |
| `graph/codegraph/stale.go#CheckStale` | `func CheckStale(repoRoot string, g *Graph) []StaleNode` | validate 继续检查整图；chain 的 `--stale` 改为给它一个结果子集 Graph |
| `graph/codegraph/domains.go#DomainTree` | `func DomainTree(v *View) []DomainStat` | 读取视图领域树与直属统计；不读取 best 词表 |
| `graph/codegraph/domains.go#DomainTreeWithBest` | `func DomainTreeWithBest(v *View, best *Best) []DomainStat` | 只供既有 domains 命令的最优图对照；context 禁用这条路径 |
| `graph/codegraph/decls.go#LoadDomainDecls` | `func LoadDomainDecls(repoRoot string) (map[string]DomainDecl, error)` | 声明存在时提供职责、不变式、生命周期、状态机；目录不存在返回空 map |
| `graph/codegraph/entity.go#EntityLookup` | `func EntityLookup(v *View, repoRoot, arg string) (*EntityResult, error)` | context 对本域 `modelKind == "entity"` 的每个真实体复用现有投影查询 |

`Neighborhood` 的 BFS 与排序不能为折叠而改变。装配发生在它返回 `*Result` 之后；唯一允许在现有查询阶段修正的是 `Result.Edges` 输出循环必须跳过 `Status == "deleted"`，与遍历阶段现有过滤保持一致。

现有 CLI 接线事实：`graph/cli/cli.go#graphQueryRunE` 当前是“加载视图 → `Resolve` → `Neighborhood` → `graphQueryOutput`”；`graphQueryOutput` 当前把 `Result` 平铺并附 `Depth`、可选 `Stale`。`graph/cli/cli.go#graphResetState` 负责进程内复用命令树时清除 flag 状态；新增 flag 必须进入同一清理路径。当前 `chain` 与 `who-calls` 都是 `cobra.MinimumNArgs(1)`，`sym`/`entity` 是 `cobra.ExactArgs(1)`。

## 3. 新增 codegraph 类型与签名

以下符号是本卡冻结的新增契约；它们当前不存在，故没有现状出处。现状调用点与输入来源见 §2，签名不可在 implement 节点改名或改参。

```go
const (
	DefaultUtilSharedByDomains     = 3
	DefaultExternalRepresentatives = 3
	DefaultContextDepth            = 3
	DefaultContextFocusQuota       = 5
	DefaultSourceSpan              = 40
	MaxSourceSpan                  = 200
	DefaultMaxTokens               = 30000
)

type QueryOptions struct {
	Full         bool
	FoldExternal bool
	CollapseUtil bool
	WithSource   bool
	SourceSpan   int // 1..MaxSourceSpan
	MaxTokens    int // 0 = unlimited; negative is invalid
}

type SourceWindow struct {
	From  int      `json:"from"`
	Lines []string `json:"lines"`
}

type TokenEstimate struct {
	Value       int    `json:"value"`
	Approximate bool   `json:"approximate"`
	Method      string `json:"method"`
}

type Truncation struct {
	AtDepth      int    `json:"atDepth"`
	DroppedNodes int    `json:"droppedNodes"`
	Reason       string `json:"reason"`
}

type AssembledNode struct {
	ID           string        `json:"id"`
	Dist         int           `json:"dist"`
	Kind         string        `json:"kind"`
	Name         string        `json:"name"`
	File         string        `json:"file"`
	Line         int           `json:"line"`
	Signature    string        `json:"signature,omitempty"`
	Summary      string        `json:"summary,omitempty"`
	Status       string        `json:"status,omitempty"`
	Domain       string        `json:"domain"`
	Container    string        `json:"container,omitempty"`
	Order        int           `json:"order,omitempty"`
	SignatureOld string        `json:"signatureOld,omitempty"`
	Params       [][]string    `json:"params,omitempty"`
	Returns      string        `json:"returns,omitempty"`
	Tests        []TestRef     `json:"tests,omitempty"`
	Fields       [][]string    `json:"fields,omitempty"`
	Unscanned    bool          `json:"unscanned,omitempty"`
	ProjScanned  bool          `json:"projScanned,omitempty"`
	ModelKind    string        `json:"modelKind,omitempty"`
	Source       *SourceWindow `json:"source,omitempty"`
	SharedBy     int           `json:"sharedBy,omitempty"`
}

type ExternalDomain struct {
	Domain          string          `json:"domain"`
	Count           int             `json:"count"`
	Representatives []AssembledNode `json:"representatives"`
}

type AssembledItem struct {
	Node     *AssembledNode
	External *ExternalDomain
}

type AssembledResult struct {
	View             string        `json:"view"`
	Foci             []string      `json:"foci"`
	Nodes            []AssembledItem `json:"nodes"`
	Edges            []ViewEdge     `json:"edges"`
	UnscannedEntries int           `json:"unscannedEntries"`
	Warning          string        `json:"warning,omitempty"`
	TokenEstimate    TokenEstimate `json:"tokenEstimate"`
	Truncated        *Truncation   `json:"truncated,omitempty"`
}

func (i AssembledItem) MarshalJSON() ([]byte, error)

func ExtractSourceWindow(repoRoot string, n Node, anchoredLine, span int) (*SourceWindow, error)

func AssembleResult(v *View, raw *Result, repoRoot string, opts QueryOptions) (*AssembledResult, error)
```

这四个行为常量必须各自保留一行代码注释：shared-util 的 `3` 注释 K≥3/28、K≥2/145、K≥4/7 的基线取舍；external representatives 的 `3` 注释“辨认职责而不复刻清单”；context depth 的 `3` 注释与 C1.10 级联深度对齐；focus quota 的 `5` 注释焦点体积乘数与跨域入边排序依据。注释必须与常量同处包内，不能只留在文档。

`AssembledItem.MarshalJSON` 是有意的 union wire：普通节点直接编码为节点对象；外部领域折叠项直接编码为 `{domain,count,representatives}`；一个 item 必须且只能有一个非空指针。普通节点的 `kind` 沿图的 `entry|func|model`；折叠项不伪装成图节点，直接走 `ExternalDomain` 形状。

`AssembleResult` 的输入 `raw` 必须来自同一次 `Neighborhood`，不得自己重新加载 baseline 或重跑 BFS。它输出的 `domain` 从 `v.Containers[n.Container].Domain` 派生；容器缺失、未归域、旧图没有 domains 段时输出空字符串，不按包名猜领域。

### 3.1 投影、`--full` 与源码窗口

每个普通节点的默认投影只保留：`id`、`dist`、`kind`、`name`、`file`、`line`、`signature`、`summary`、`status`、`domain`。`params`、`returns`、`tests`、`fields`、`order`、`signatureOld`、`unscanned`、`projScanned`、`modelKind` 在默认投影中不得出现。

`Full=true` 时恢复当前 `ViewNode`/`Node` 的全部字段形态，唯一例外是 §6 删除的 `TestRef.Snippet`；JSON `omitempty` 行为与现状保持一致。`Full` 只控制字段投影和折叠，不关闭 `WithSource`，也不关闭 token 预算。

`WithSource=true` 时，每个未折叠的普通节点附 `source:{from,lines}`；折叠项及其 representatives 不附源码。`ExtractSourceWindow` 使用 `ReAnchor` 返回的锚定行号，窗口最多 `span` 行，默认 40、上限 200，窗口在文件边界处收缩但不补造行；同一装配调用按文件复用行缓存。未扫描节点或空文件节点没有源码窗口，保留现有节点位置/状态；文件存在但符号 vanished 时仍读取并返回以原始行号为中心的可用窗口。

`SourceSpan` 必须在 `1..MaxSourceSpan`；`MaxTokens < 0` 返回参数错误；`MaxTokens == 0` 表示不限。超出上限不得静默钳制。

### 3.2 折叠规则

1. `FoldExternal=true` 时，以所有 focus 节点的非空领域集合为焦点领域；焦点领域之外的普通节点按领域合成一个 `ExternalDomain`。无 domains 段或节点没有领域时不折叠。`count` 是该领域本次 raw 结果中的全部节点数；representatives 按该节点被本次结果内其他节点调用的 live 入边数降序，随后按节点 id 字典序取前 `DefaultExternalRepresentatives` 个。折叠项按 domain id 字典序输出，折叠项下游不再单独展开；输出 edges 只保留仍以普通节点为两端的 live 边。
2. `CollapseUtil=true` 时，节点只要被当前视图中来自至少 `DefaultUtilSharedByDomains` 个**不同非空领域**的 live caller 调用，就标 `sharedBy` 为不同 caller 领域数，并作为一个普通节点只输出一次。判定按领域数，不按 caller 节点数；`model` 也可命中，不限于 `func`。共享节点的下游不单独展开，除非该下游仍能从另一个未收桩路径到达；一个节点最多出现在一个输出 item 中。
3. 两条规则同时打开时，先保留 shared utility item，再将其余焦点领域之外的节点归入 `ExternalDomain`，以保证共享内核不会被外部领域行吞掉。
4. `Full=true` 关闭两条折叠；这不改变 raw BFS，也不恢复 deleted edge。

阈值全部是包内常量，不进配置、不新增阈值 flag：`3` 的 shared-util 阈值来自协调者提供的 handoff 真基线跨域扇入分布（K≥5 为 3、K≥4 为 7、K≥3 为 28、K≥2 为 145）；取 2 会把 117 个普通双域调用点收桩，取 4 只剩 7 个。代表数 `3` 的取舍是辨认外部职责与避免重新输出清单之间的边界。任何阈值变更必须连同这组依据重新走契约审核。

### 3.3 token 预算

`AssembleResult` 按 raw 节点 `dist` 升序、同距按 id 字典序填充普通节点；折叠项使用其最小 dist 参与该序。新增一个 item 会使估算超过 `MaxTokens` 时立即停止，并丢弃该 item 及其后所有未填充节点。`TokenEstimate` 的 `method` 固定为 `utf8-json-bytes/3`，`approximate` 固定为 `true`；估算值是当前 compact JSON 负载按 UTF-8 字节数除以 3 的整数估算。

发生预算截断时必须出现：

```json
"truncated": {"atDepth": 2, "droppedNodes": 41, "reason": "max-tokens"}
```

`atDepth` 是第一个未填充 raw 节点的 dist，`droppedNodes` 是因此未进入输出的 raw 节点数，`reason` 固定为 `max-tokens`。未截断时省略 `truncated`；不得只删节点而不报文。

## 4. context 组合器

新增以下类型与函数：

```go
type ContextPackage struct {
	Path    string `json:"path"`
	Summary string `json:"summary"`
}

type ContextInterface struct {
	ID        string `json:"id"`
	Name      string `json:"name"`
	Signature string `json:"signature,omitempty"`
}

type ContextDomain struct {
	ID       string   `json:"id"`
	Label    string   `json:"label"`
	Kind     string   `json:"kind"`
	Summary  string   `json:"summary,omitempty"`
	Desc     string   `json:"desc,omitempty"`
	Parent   string   `json:"parent,omitempty"`
	Children []string `json:"children"`
}

type FocusTruncation struct {
	Total  int    `json:"total"`
	Shown  int    `json:"shown"`
	Reason string `json:"reason"`
}

type ContextResult struct {
	View          string             `json:"view"`
	Domain        ContextDomain     `json:"domain"`
	Declaration   *DomainDecl        `json:"declaration,omitempty"`
	Packages      []ContextPackage   `json:"packages"`
	Interfaces    []ContextInterface `json:"interfaces"`
	Chain         *AssembledResult   `json:"chain"`
	Entities      []EntityResult     `json:"entities"`
	FociTruncated *FocusTruncation   `json:"fociTruncated,omitempty"`
	Stale         []StaleNode        `json:"stale,omitempty"`
	Warning       string             `json:"warning,omitempty"`
}

func AssembleContext(v *View, g *Graph, repoRoot, domainID string, opts QueryOptions) (*ContextResult, error)
```

`AssembleContext` 必须按以下顺序组装：

1. **词表与范围**：`domainID` 只在 `v.Domains` 现状词表中决议，绝不取 `best.json` 的领域 id。未知 id 返回非零错误；错误文案必须明确 context 使用现状词表，并列出现状词表的近似候选，避免把 best-only id 报成图损坏。领域节点的子树范围是自身加所有递归 descendants；直属统计为零的父领域不能因此降级。
2. **声明**：若 `LoadDomainDecls` 有该 id，完整透传 `DomainDecl`（包含 `responsibility`、每条 invariant 及其 `testRef`、`lifecycle`、`stateMachine`）；无声明不报错，省略 `declaration`，仍继续机械组装。
3. **包摘要**：从范围内容器所覆盖的节点文件目录收集包路径，去 `g.Packages` 查 `Package.Summary`；每个目录都输出一行，缺摘要时 `summary` 留空，不自行概括；按 `path` 字典序输出。该段只进 context，不进 chain。
4. **对外接口清单**：叶子领域按 live 跨域边 `from` 域外、`to` 域内重算；父领域按整棵子树边界重算。清单列出全部 live 目标节点，去重后按 id 字典序输出，每行只含 id/name/signature。删除节点和 `status=="deleted"` 的边都过滤。
5. **实体表**：范围内只收集 live 且 `Kind == "model" && ModelKind == ModelKindEntity` 的节点，按 id 字典序逐个调用 `EntityLookup`，完整输出 `EntityResult`。`ModelKind` 为空时不得把节点计入实体表；若全项目没有分种，实体表为空并给出“该项目未分种，实体数不可用”的 warning。
6. **主链焦点**：焦点全集是范围内 live `kind=="entry"` 节点与第 4 步接口目标节点的并集，按 id 去重。父领域接口按子树外部 caller 判定，不能要求用户下钻。
7. **焦点配额**：主链不直接使用全集，而是按每个焦点的 live 跨边界入边数降序、同数时 `entry` 优先、再同按 id 字典序排序，取前 `DefaultContextFocusQuota` 个。全集大于 5 时输出 `fociTruncated:{"total":全集大小,"shown":5,"reason":"focus-quota"}`；配额截断不得混入 `truncated`，两者都必须可见。接口清单不受该配额影响，仍全量输出。
8. **主链查询**：调用 `Neighborhood(v, selectedFoci, DefaultContextDepth, 0)`，深度固定为 3；再调用 `AssembleResult`。context 默认 `WithSource=true`、`FoldExternal=true`、`CollapseUtil=true`、`SourceSpan=40`、`MaxTokens=30000`；其它字段遵循传入 `QueryOptions`。context 不提供深度 override；需要更深查询必须使用 `chain --depth`。

context 的 token 预算作用于 `chain` 子段，故 `chain.truncated` 必须原样保留；固定声明、包摘要、全量接口清单和实体表不能因预算而静默删减。源码只附在 chain 中未折叠的节点上。

未声明领域的降级路径是主路径，不是异常路径：只要领域存在于视图词表，就必须返回包摘要、接口清单、主链和实体表，并可在 `warning` 指向 `codegraph/domains/<id>.json` 与 roadmap 1a；不得把未声明当作 error。

## 5. CLI 端点与参数

### 5.1 `chain` / `who-calls`

现有端点保持位置参数和 BFS 方向：

```text
codegraph chain <节点 id 或名字>...       # cobra.MinimumNArgs(1)，down=depth
codegraph who-calls <节点 id 或名字>...   # cobra.MinimumNArgs(1)，up=depth
```

两条查询都使用以下新选项：

| flag | 类型 | 默认值 | 语义 |
|---|---|---:|---|
| `--full` | bool | false | 关闭字段瘦身与两条折叠，保留旧字段形态（除 Snippet） |
| `--fold-external` | bool | true | 开启外部领域折叠；可显式传 false |
| `--collapse-util` | bool | true | 开启共享内核收桩；可显式传 false；阈值不由 flag 传入 |
| `--with-source` | bool | false | 给未折叠节点附源码窗口 |
| `--source-span` | int | 40 | 源码窗口行数，合法范围 1..200 |
| `--max-tokens` | int | 30000 | UTF-8 JSON 字节/3 的近似预算，0 不限 |

现有 `--repo`、`--view`、`--stale`、`--depth` 语义不改。`--stale` 只对本次 `Neighborhood` 结果节点构造子集 `Graph` 后调用 `CheckStale`，不得再把全基线 `g` 传入；输出字段仍是 `stale`，并与现有 `graphQueryOutput` 平铺兼容。`--stale` 的 deleted 节点同样不进入检查子集。

### 5.2 `context`

```text
codegraph context <领域>                  # cobra.ExactArgs(1)
```

它调用 `AssembleContext(v, g, graphRepo, args[0], opts)`，输出 `ContextResult` 的 JSON。context 默认带源码，固定主链深度 3；`--full`、`--fold-external`、`--collapse-util`、`--source-span`、`--max-tokens` 适用同一套优先级和边界。context 不暴露深度 flag；调用方要改变深度必须改用 `chain`。

context 的 `--stale` 若传入，只检查其主链 raw 结果子集，并将结果写入 `ContextResult.Stale`；不得对整张基线图执行 stale。

新增命令后业务子命令数从当前 `graph/cli/cli.go#init` 的 14 增至 15；`graph/cli/cli_test.go#TestGraphCommandCountIncludesMigrate` 的硬编码断言同步更新。新增 command var、注册、reset state、包注释和计数测试属于 CLI 接线，不得另造命令树或第二个 JSON 输出器。

## 6. `TestRef.Snippet` wire 收缩

`graph/codegraph/types.go#TestRef` 删除 `Snippet string \`json:"snippet,omitempty"\``；`tests` 保留 `name` 与 `file`。该删除是跨 provider/consumer 的 wire 变更，必须同步：

- `graph/webui/src/api/types.ts#CgTestRef` 删除 `snippet?`；
- `graph/webui/src/app/codegraph/DetailPanel.tsx` 删除 `t.snippet` 的渲染分支；
- `graph/webui/src/app/codegraph/DetailPanel.test.tsx` 删除 fixture 中的 `snippet` 与只验证该字段的断言；
- 相关 Go/JSON fixture 不得再把 `snippet` 作为新输出生成。

旧输入含 `snippet` 时由标准 JSON 反序列化忽略，不能复活字段，也不能将源码窗口写回 `TestRef`。源码窗口只能走 §3 的 `source`。

## 7. 文档同步与显式不做

**记录四：删掉虽有 web UI 渲染方但数据全空的 `TestRef.Snippet`。** 这是跨 Go wire、TypeScript 镜像、渲染器与测试 fixture 的难逆收缩；后人看到渲染代码会想恢复它，且“保留死字段”与“收缩 wire、源码走 source”是实际取舍。选择删除并同步三处 web UI；明确不把新源码窗口塞进旧字段。
