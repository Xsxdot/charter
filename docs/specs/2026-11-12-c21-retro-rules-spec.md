# C21 复盘补条：变异不留残、替代环境与代点不算真机、全量冻结被测树与基线复用

状态：r2 已批（2026-11-12，用户：「1、3 是有意义的，2 是过拟合」——删去替代环境/代点一条及其红旗行，只留变异与全量两条）
级别：L1（规则正文卡，spec 即 plan：同一份文件挂 `spec:` 与 `plan:`）

## 问题陈述

2026-11-12 pejam PJ2（凭据管理器）与 ERP 智能客服两件事复盘，取证到三处 charter 规则执行不到位造成的大额损失：

1. **变异留残引发连环 OOM**：ERP 一个子 agent 做变异复验时用 `cp` 备份、事后还原；变异后的测试跑到一半节点 OOM，还原那一步没执行，错误实现留在树里，之后三次测试都撞同一失败断言把内存吃爆，合计约 4.6 小时停摆。
2. **替代环境被当成真机**：PJ2 的 S1 在 Chromium 亮色主题验，代替指定的 Electron；S4「人批」由执行者经 API 代点。review 第 3 步已写「指定环境的证据不可自判等价」，但没有点名这两种最常见的替代，结果暗色主题不可读、无会话 CLI 审批卡在桌面没有入口，两个缺陷都拖到父卡整体走查才暴露。
3. **全量作废与重复跑**：批级全量单次约 43 分钟；一次跑到 18 分钟因被测工作树被新提交改动而作废；main 基线与父卡串行各跑一遍。

## 方案

只在 `skills/review/SKILL.md` 三处补句与一行红旗，不新增节、不改顺序铁律。弃选：

- 给测试命令加内存上限写进 charter——属环境配置（pejam 已在节点 systemd 层限内存，PJ84），不进通用流程。
- review 比例口径——2026-11-11 已入 75bf2e4，不重复。

## 必交故事

- S1 下一张走 review 的卡，审查者读 `charter:review` 时能看到：变异必须在可丢弃的副本上做；全量期间被测树冻结、基线按 main 提交复用。验证：`grep` 两句原文在 `skills/review/SKILL.md`。
