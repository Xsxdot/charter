## 问题陈述

2026-08-25 三路文档对齐审计（charter 仓 14 份 spec、10 份契约 + 8 份拆解稿、handoff 仓 21 份重点样本；过程与原始结论见台账 `docs/ledgers/2026-08-25-c9-carrier-law-ledger.md`）的顶层诊断：**节点内核与节点衔接健康且在自我加严，四处系统性漂移同出一个根因——某类流程信息没有唯一法定载体时，它挤进最近的容器。**

四处漂移与其「挤进的容器」：

1. **拍板裁决留在会话**（breakdown 侧）：两份拆解稿裁决零回写、三份状态行失真——「状态承载于文件而非会话记忆」的原则散落为各节点各自的条款，breakdown 只立了「拍板即提交」半条，没管回写。
2. **契约吃进实现规格**（contract 侧）：08-23 批次冻结清单膨至 86 条峰值，大量单包实现选择混入接缝断言——查证期确立的实现级决定无处安放。
3. **spec 吃进 plan 落点**：实现决定段持续出现未来类型名/文件落点——禁令没有边界判据，正当的产品命名与越界的内部落点无从区分。
4. **spec 吃进 ledger 读数**：盲测数据、对照组读数整段落进 spec 备注——台账条款覆盖 contract/breakdown/plan/implement 四节点、review 有豁免，唯独 spec 没立。

正反两面验证根因：**唯一被立了专属载体的信息类型（残余→`docs/roadmap.md`，条款铺满 spec/acceptance/integrate/finish 四节点）恰是执行最扎实的纪律；spec 批准回写在立「头部状态行」载体后从全线失守转为近满分。**

元问题：现行修法方式是「每个节点出一次事故，就给该节点补一条记录类条款」——各节点的状态条款各自生长、形态不一，这是「拒绝补丁式修复」（核心原则第一条）在立法层的再现。

## 方案（四岔口裁决，用户 2026-08-25 逐条拍板）

| 岔口 | 裁决 | 弃选与理由 |
|---|---|---|
| 载体法总纲落点 | **README 设计原则第七条**（一句原则 + 判例表） | 新横切 skill：五类信息撑不起一个 skill，挂 compose_map 附录会给多个纪律块加重量，执行者多数时刻用不到总纲全文。网关加节：每会话注入付全时上下文成本，而载体法只在节点收尾时刻起作用。总纲读者是修法的人，README 恰是修法必读文件，零分发成本。 |
| contract 冻结物边界 | **判据句 + 移交区** | 纯判据句（越界即删归 plan 重写）：查证成果无合法出口，出稿者舍不得丢会塞回冻结清单——正是今日膨胀成因，违反「凡红线必留正当出口」。条目数上限：治标，条目被压缩成复合句反弹，与原子化直接冲突。 |
| spec 未来落点判据 | **可见性分界** | 临时命名标注（「命名待 contract 核定」）：标注泛滥成白名单，禁令被架空。放开合法化（交 contract 复核）：spec 与 plan 制度化双写同一信息，与「很快过时」的立法理由正面冲突。 |
| spec 读数归置 | **补台账条款 + 裁决/过程分界** | 仅收尾自检瘦身项：盲测读数这类真证据没有合法去处，删了丢审计链、不删回倾倒场——禁令无出口。附录合法化（只要求分节）：台账制度在 spec 侧被架空，长度榜前二的形态成为合法模板。 |

**追加三项（用户 2026-08-25 指令，非岔口）**：③L1 立法并入（实现决定 I，用户授权原话「OK」）——背景：L1 只活在 product-backlog 手册的路由约定里（而该手册自称「本 skill 不定级」），charter 正文无 L1，定级判据无法定居所，正是本刀要修的病的又一实例。裁决要点：**复用 implement 节点，不加「直接实现」节点**（新节点=纪律更松的 implement 副本，复制即漂移，且成为绕 TDD 的通道）；L1 判据落成可判伪形式（见 I）。另：①每次 skill 更新必须配检查方案（事后核奏效与负优化）——立为 README 修法自检条款（实现决定 G），本 spec 自带一份（「生效判据与负优化信号」节）；②对 393d2d7a / f2b101eb 两笔未经批准落地的台账条款作追认审查（实现决定 H）——内容合格、落点正确（源文件而非同步脚本：skills 正文是唯一真源，两个消费端都从它出发；条款进脚本则本地流程失明，且违反脚本自身「只拼接不装正文」的职责边界）。

## 用户故事

1. 修法者读 README 即知每类流程信息的法定居所；再给节点新增记录类条款时必须指认既有载体，不新造段落。
2. breakdown 拍板者收尾时把裁决与状态行回写进稿并同批提交；下游读稿即得全部裁决，不依赖任何会话记忆。
3. contract 出稿者在查证期顺手确立的实现级决定有合法出口（移交区），冻结清单保持窄接缝、逐条可判。
4. spec 出稿者有判据可依：用户可见的名字可写，内部落点禁写；实验读数进台账，spec 正文只留结论与指针。

## 实现决定（决策级）

**A. README 设计原则第七条「信息归唯一载体」**：一句原则——每类流程信息有唯一法定居所，节点新增记录类条款必须指认既有载体、不新造段落。附判例表：

| 信息类型 | 法定居所 |
|---|---|
| 判决与状态（批准/冻结/拍板） | 产物文件头部状态行，随产物提交 |
| 残余（本期不做、后续要做） | `docs/roadmap.md` |
| 读数与实验过程 | 台账；产物正文只留结论 + 台账指针 |
| 欠账 | 交棒声明，由下游显式认账 |
| 实现级决定（plan 之前顺手确立的） | contract 移交区 → plan 吸收后销区 |

**B. breakdown 节点（拍板回写）**：「拍板即提交」条款扩为——拍板结果逐岔口回写进稿首待拍板清单（裁决 + 理由），头部状态行更新为「已拍板（日期）」，与裁决同批提交；**状态行与裁决记录不一致视同未拍板**。

**C. contract 节点（三条）**：①冻结物边界判据句——冻结清单只收接缝断言与三重闸门决定；②「移交 plan」附区——查证期确立的实现级决定落文档末尾附区，不占冻结条目名额、不参与逐条打勾对账，plan 出稿时吸收并在区头标注「已由 plan〈文档〉吸收（日期）」销区；③原子化补双向——一条一断言（复合句必拆），也不许一条打包整个 wire 形状，粒度以「单独可判 pass/fail 且失败可定位」为准。

**D. spec 节点（两条）**：①落点可见性分界——实现决定段可写决策级落点（哪层收口、谁依赖谁）与用户可见的名字（命令名、配置键、错误文案——它们是产品决策）；禁写内部符号名与文件路径（判据：这个名字改掉，用户能察觉吗？不能察觉的都是落点，归 contract/plan）；②补与四产出节点同款的「边干边落台账」条款，收尾自检加分界句——裁决变更与结论回写 spec 正文，实验过程与原始读数进台账、正文留一行指针。

**E. 纪律块同步**：条款落盘后重跑 `scripts/regen_discipline.py`（机械动作；compose_map 不改——spec 无纪律块、README 不分发，contract/breakdown 正文变更随既有映射进块）。

**F. 个案销账（charter 仓内四处，均已一手核实）**：

1. `docs/specs/2026-08-24-codegraph-viewer-semantics-spec.md:126`「推荐 A 若获批」残句——按已回写的裁决 A（2026-08-24）改为定稿措辞。

**G. README 修法自检条款**（与第七条同处「设计原则」，立法层纪律，不做节点投影——修法者读 README 即受约束）：每笔 `skills/` 正文变更须三件套——①**授权留痕**：有卡/spec，或用户显式指令原话入提交说明；②**检查方案**：生效判据 + 负优化信号 + 检查时点，随修法产出落 `docs/roadmap.md` 观察条目（载体=roadmap，防止检查方案死在会话里）；③**同步**：重跑 `scripts/regen_discipline.py`。三件缺一即修法未完成。

**I. L1 立法（定级三级制入法）**：spec 节点定级表补 L1 行，using-charter 节点地图补 L1 路由。**L1 两判据，两个都命中才是 L1，缺一按 L2**：①**plan 增量为零**——把 plan 写出来只会复述 spec（spec 末尾三行「改哪个文件、怎么验收」即全部实现决定，三行写不完就不是 L1），此时同一份 spec 文件挂 `spec:`/`plan:` 双 kind 过 implement 门，不另写 plan 文档；②**验收一眼可核**——review + 真机一眼收口，acceptance 可跳（快道）。路由：L1 → implement → review → finish；implement 的 TDD 纪律照常适用——**L1 省的是文档，不是实现纪律**。只命中判据①的按 L2 定级，可由用户在 spec 状态行裁决跳过 plan 直接实现（先例：seam-budget、C9），review/acceptance 照走。

**负优化信号**（任一出现即回炉本条款，不硬扛）：

1. 移交区膨胀成第二冻结清单（条目数接近或超过冻结清单本体）或 plan 从不吸收——出口变倾倒场；
