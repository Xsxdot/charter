# Spec：接缝预算执法 + 运行时直通竖切

**状态**：已批准（2026-08-24，用户裁决：跳过 plan 节点直接实现——纪律文本改动，实现决定即任务清单）（v2.1，吸收外部审查三轮：B219 实例 + 旧卷复跑 + 对偶覆盖审查）
**级别**：L2（charter 仓 skills 文本，单子系统，不动契约层）→ plan → implement → review → acceptance → finish

## 问题陈述

外部评论（卡颂文）照出本套件两处「规矩写了、没人执法」的缺口，例证已对本仓与 handoff 仓产物核实：

1. **接缝清单是死预算**。spec「测试接缝对齐」段写明接缝清单「决定后续所有节点的测试预算落点」（skills/spec/SKILL.md:35-37），但 plan 的自审只查「故事指到 task」不查「测试指回缝」，implement 的 TDD 铁律无范围限定（skills/implement/SKILL.md:10）。实证：刀 3+4 的 spec 定「主缝一个：Check() 返回的 Report」（docs/specs/2026-08-23-codegraph-reconcile-fitness-spec.md:96），同卡 plan 的 T0 却给包内未导出的 `sortFindings` 写红绿（docs/plans/2026-08-23-codegraph-reconcile-fitness-plan.md:42）——而该 plan 又自发补了缝级真仓复验（冻结 21），说明直觉在、法条不在。
2. **结构竖切了，行为还是横切**。Ticket 0 只保编译期走骨架（skills/contract/SKILL.md:25），无任何节点要求在并行长肉前先有一条可跑的行为路径；第一次竖着跑在 integrate——integrate 自己承认契约错配的正确暴露点应更早（skills/integrate/SKILL.md:14）。
3. **接缝清单可在源头就被写歪**（handoff 仓 B219 实证）：spec 阶段作者会把「最好单测的无 IO 纯函数」填进接缝清单——B219 的调用面是导出的 `DenyWrite`/`DenyRead`，spec 却把「唯一接缝」写成包内未导出的 `decideProbe`，落地后对外 API 零直接覆盖、红绿全打在肚子里的文案子串上。只在 plan 加「指回清单」的闸，闸会替被写歪的清单背书。

## 方案

**选定：增量修法，不加节点、不引新词、不新增卡种。**弃选两案：

- 弃「引进 Seam / Tracer Bullet 术语重写相关段」——与既有「契约面 / 测试接缝 / 测试缝」撞车，纯改名无执法增量。
- 弃「新增独立的 tracer 节点」——流程固定成本已实测约 70 分钟/子系统，加节点抬成本；两个既有节点（contract、plan）各有自然挂点。

**修法总原则（v2 新增，v2.1 修订口径）**：**能钉符号的钉符号**——闸门判据优先钉在可机械核验的事实上（入口调用的符号、grep 得到的调用方、变异转红的测试身份），不钉在作者的自我标注上；唯一钉不了符号的一闸是内部锁的理由，它钉**理由形状**（「从声明缝构造不出」），由审核者对照声明缝复核。例外一律**默认非法、声明合法、且不能顶替主义务**。

## 用户故事

1. 作为 plan 的审核者，我能机械地问「这支测试的**入口符号**在声明缝上吗、调用链穿过缝吗」——指不回且无合法内部锁声明即 plan failure；作者标注与入口不符也是 plan failure，不得降格为内部锁。
2. 作为执行者，我在 plan 模板里看见的红绿步骤**只套在锁缝断言上**；每个实现类 task 至少一条缝级断言，我不再为日志、注释、纯映射、内部帮手各配一盏红灯。
3. 作为协调者，L3 重档在 Ticket 0 之后、扇出之前有一发运行时直通：一次真实调用穿过所有空壳返回写死结果，测试钉在声明主缝上；且这发写死结果**不会**成为子卡免除最薄路径的理由。
4. 作为审查者与验收者，「测试有牙」的主证据必须来自**声明缝上的**变异或红绿——内部锁的红不能单独过这一维。
5. 作为 spec 的审核者，我能核验接缝清单每条的合法性：存量符号 grep 它的调用方；新建符号查它的「将被谁调用、导出到哪一层」声明——把「decideProbe 式假缝」挡在清单成形时。

## 实现决定（逐文件改动清单）

0. **skills/spec/SKILL.md**——「测试接缝对齐」段加**接缝合法性条件**，三款：
   - **a) 每条缝写成「符号 + 调用方」**。存量符号：调用方可 grep 核验，spec 里带出处。新建符号：不写死签名（签名归 contract），但必须写清**将被谁调用、导出到哪一层**（语义声明）；contract 落地时核验导出面与此声明一致——核不上按契约分歧退回 spec，不许落地时顺手改缝。
   - **b) 假缝禁令**：未导出、无生产调用方、只为在本机走满分支而抽出的纯函数，**不得占据接缝清单名额**。它可以是正当的可测性启用点（架构法第四条第 2 档测试缝），记入 plan 的内部锁候选——它是手段，不是缝。
   - **c) 边界型例外入法条**：缝的对面是外部现实的格式/协议时（wire 格式、外部工具输出如 git porcelain、对端载荷 JSON），其**解析/编码入口即缝上符号**，即便未导出；此类表驱动测试视为穿过该缝，不占内部锁名额。
   - **d) 收尾自检对应加严**：spec 收尾自检第 2 项由「测试接缝清单不许空」扩为「每条缝有符号 + 调用方，假缝禁令（b 款）逐条核过」。
1. **skills/plan/SKILL.md**——四项检查扩为五项，新增「**接缝覆盖**」，判据三句全部钉死：
   - **指回看入口，不看标注**：测试**入口调用的符号**是缝上符号、或调用链穿过该缝，才算指回；作者标注「属于某缝」而入口不符 = plan failure，不得降格为内部锁。
   - **内部锁默认非法、只能附加、不能顶替**：每个实现类 task **至少一条缝级断言**；内部锁合法理由的唯一形状是「**从声明缝构造不出这条断言** + 为什么构造不出」——「更短 / 更纯 / 无 IO / 好写表驱动」不构成理由。
   - **内部锁逐条在占位符扫描节自我声明**（与既有 harness 例外同款）；无声明的内部测试即 plan failure。
   - **对偶覆盖（缝 → 测试）**：清单里**每一条声明缝至少被一支缝级断言锁住**；锁不住的缝要么提请从清单删掉（缝清单修订走 review 的冻结物触碰行留痕），要么说明 task 缺了。此句与「每个 task 至少一条缝级断言」是两个方向，不互相代替——前者防预算条目合法空置（只测 Check 不测 CLI、只测 DenyWrite 不测 DenyRead），后者防 task 全靠内部锁。
2. **skills/plan/SKILL.md**——**格式铁律本句修订**（改模板本身，不靠事后自审对冲）：步骤粒度 2~5 分钟保留；「写失败测试 → 跑红 → 最小实现 → 跑绿 → 提交」的红绿模板**只套在锁缝断言的步骤上**——内部实现、日志、注释、纯映射步骤不配独立红绿周期。
3. **skills/plan/SKILL.md**——「每个实现类 task 必含的步骤」区加**最薄路径条**，「可跑」定义收严：「已有活路径」的判据 = **本卡要锁的那条行为，今天从声明缝调用已能得到该断言的预期结果（测试写下去会绿）**；会红或调不到都不算——缝上存在旧响应/旧功能不构成免除，直通竖切的写死结果也**不构成**后续子卡的「已有活路径」。判为「无」→ task DAG 第一条必须是点亮该行为的最薄可跑路径。
4. **skills/implement/SKILL.md**——TDD 铁律加范围段：「铁律的对象是**已声明接缝上的行为断言**。日志、注释、直通镜像、纯映射不构成独立红绿周期——但纯映射必须被缝上断言或 roundtrip 断言覆盖（缺陷族·序列化边界条），豁免红绿仪式不豁免被覆盖。内部复杂逻辑从已声明缝够不着时，接 debug 的无缝条款：立架构债，不造假缝、不硬塞内部测试」。
5. **skills/contract/SKILL.md**——Ticket 0 条后追加「**直通竖切**（重档法定步骤）」，含两句消歧：
   - 骨架提交后、扇出前，落一发运行时直通——一次真实调用穿过所有空壳、返回写死但接线真实的结果，测试钉在 spec 声明的主缝上。此测试即现行「越过空壳的可观测行为须有能变红的测试」条款的正当出口，不是新例外。**归属协调者或 contract 执行者，不进任何并行子卡**。
   - **与既有「直通镜像」分工**：镜像 = 编译期透传接线（Ticket 0 空壳范畴）；竖切 = 运行时一次真实调用。两者可同卡并存，不互相替代。
   - **「一次调用」按主缝形态取义**：库缝 = 测试夹具直调（如 `Check()`）；CLI 缝 = 一次命令调用；HTTP 缝 = httptest 一发请求。**禁止为直通新造对外面**。
   - 轻档与 L2 无此步骤，由 plan 的最薄路径条（实现决定 3）承接。
6. **skills/defect-families/SKILL.md**——「假红/假绿测试」族追加设问：「这支测试锁的是**调用方依赖的行为**，还是内部帮手？换实现、不改需求，它会不会无意义地红？」（检测用；裁决权见 7、8——内部锁合法≠内部锁有牙。）
7. **skills/review/SKILL.md**——「测试有牙」维度判据改写：已验的**主证据必须来自声明缝上的**变异或红绿；内部锁的红**不能单独**充当此维证据——只有内部证据的写「未验 + 缝级证据缺失」。
8. **skills/acceptance/SKILL.md**——变异复验补一句（接既有「只红一边说明另一边的覆盖是假的」句式）：变异转红的测试**必须包含声明缝上的那支**；只有内部锁转红、缝级测试不红 = 缝级覆盖是假的，不得过此维。
9. **同步**：改完跑 `scripts/regen_discipline.py`，纪律块重生成无残留 diff。

## 旧卷复跑（出稿自验：两张歪卷在 v2 闸下必须不及格）

- **刀 3+4 T0**：`TestSortFindingsIsTotalOrder` 入口调 `sortFindings`，不在 Check 缝上 → 指回失败（决定 1 第一句）。想立内部锁须证明「从 Check 构造不出撞键排列断言」——构造得出（用既有 `mkView` 造两条同 Kind/Detail 的 finding、两个排列各跑 Check、断言 Report 逐字段相等），理由不成立；即便成立也不能顶替——T0 必须至少一条 Check 缝断言（决定 1 第二句），且 plan 模板不再引导给内部函数配红灯（决定 2）。**T0 原样不再合法。**
- **B219**：`decideProbe` 未导出、生产调用方仅 helper 自身、抽出动机是本机走满两支 → 第 0 条 b 拒占缝名额，缝只能写 `DenyWrite`/`DenyRead`；`TestDecideProbe` 若保留须走内部锁且不能顶替——`permission_test.go` 必须有 DenyWrite/DenyRead 的缝级断言（决定 1）；review 的有牙维度只认缝上变异（决定 7）；acceptance 变异只有它红、缝上不红即判假（决定 8）。**四道闸每道独立能挡。**
- **L3 重档直通后的子卡**：直通的写死结果不构成「已有活路径」（决定 3）→ 子卡第一 task 仍须点亮本卡行为的最薄路径，直通不会作废竖切自己。
- **对偶卷（预算条目合法空置）**：清单写主缝 Check() + 次缝 CLI，所有 task 只打 Check、CLI 零断言——每支测试都指得回去，「测试 → 缝」全过；但「缝 → 测试」（决定 1 对偶覆盖句）查出 CLI 缝零锁 → 要么提请删缝（review 冻结物触碰留痕），要么 task 缺了。B219 变体（清单写 DenyWrite+DenyRead、只测其一）同理被挡。

## 测试决定（接缝清单）

本卡是纪律文本改动，主缝一个：**各 SKILL.md 正文本身 + `scripts/regen_discipline.py` 重跑结果**。验收 = 逐条对读改动与本 spec 的实现决定 + 上节「旧卷复跑」按改后文本重演一遍（两张歪卷仍能过任何一闸即验收不通过）；regen 后 `git status` 无未预期 diff。无可执行测试缝——文本仓的行为事实由下一张过流程的真卡踩出来（回旋镖对账）。

## Out of Scope

- **永不做**：引进 Seam / Tracer Bullet 作为术语；替换 debug「无缝即发现」的措辞；卸掉 2~5 分钟步骤粒度（粒度保留，改的是红绿模板的适用对象）；采用单会话工作流（mattpocock 式）替换节点；新增流程节点或卡种。
- **本期不做**：内部锁的**数量**上限（质条件——不能顶替、理由形状——已入本期，见实现决定 1）——先跑两张真卡攒内部锁的真实分布，再定要不要设数量阈值，已落 roadmap 第 14 条。
