## 问题陈述

C12 把「人看流程图、只留入口」做成了：**一条 CLI/HTTP/WS 程序访问面一张图**。用户原意是：**入口 = 对外契约 = 被外部调用的方法**。CLI/HTTP 只是到达这些方法的通道。

真机后果（2026-08-27）：

- 点「任务编排」右栏「没有程序入口」——入口容器挂在 `d_cli` / `d_gateway`，契约方法没有泳道。
- 点 `GET /console` 得到的图是 handler 里每一句 `if err { return }` 摊上主干再蛇形翻转，看不出这个方法对外在办什么事。
- 「对外面」tab 列的才是契约面，却点不进流程图。

同一天继续走查，露出主语改完之后仍缺的几件事：

- 紫框 ▸ 进下一张图之后，要有「上一层」，不能把人扔在一张没有来路的图上。iframe 里的浏览器后退不可靠，必须是页内栈。
- 双线框的实现清单不只是注释：每一个实现方法自己就是一张流程图的主语，点进去、能回来。C12 契约 §2.4-35 写「每个实现的入口即其流程图起点」，实现里却要先点中接口步骤才看得到按钮，而且把「入口」理解成实现容器里的 CLI/HTTP。
- 右栏没有「被谁调用」。人要看的是这个方法被哪些符号调进来，不是只有到达通道、也不是下游机械序列。
- C12 交付时 CLI 没有 `flow`。`chain` 是调用图按跳数切开的下游子图（节点出现一次、菱形汇合、无源码次序），不是执行树。近 12 小时实测：`codegraph flow` / `flows` 两次都是 unknown command。本分支批准前已挂 `flow`/`tree`（流程债，见备注），JSON 形状仍待 contract 冻结。
- 也没有调用树：沿哪条路径下去、从哪条命令上来，都被摊成同一张邻域。Hub 的 `who-calls` 是粥，卡不住「只看 Dispatch 这条走廊」。

C12 契约把这次误解写进了 §2.4-30/32/35/36 和 §2.1-5。本卡废止并替换这些主语与承重集合，补导航栈 / 实现即主语 / 被谁调用 / CLI `flow`+`tree`，不推倒结构轴、不推倒 `flows` 的 JSON 形状。

## 级别与档位

**L3 · 轻档。** 改 C12 已冻结的行为轴语义，并新增 agent/人可见的 CLI 子命令（动契约层 → L3）。实现落在查看器 + CLI + 扫描配方承重范围，不新造分层，不扇出子卡。charter 仓无项目 `codegraph/best.json`（本仓是图工具本身）：contract 对照 C12 契约 + 本 spec，不降档装有图。调用树只读现有调用边，不新增扫描数据面。

## 方案

### 一张图 = 一个方法怎么走

**默认落地集合**（从结构轴点进去）= 结构轴「对外面」tab 同一批未折叠入缝：跨域被调方法，噪声折叠同一判据（兜底桶 ∧ 复用度 ≥ 10 的不占默认泳道）。折叠块展开后，其中未折叠的入缝同样可点进图。

**可打开的泳道主语**比默认集合大，三类同一套页面、同一套返回：

1. 对外入缝（默认落地）
2. 紫框目标：见下方机械判据，不是「紫框指向的下层主语」这种循环定义
3. 右栏列出的接口**实现方法**（方法自己是主语，不是实现容器里的 CLI 入口）

**紫框机械判据（唯一）**：流程图上一步 `kind=call` 的 `to`，若属于承重主语集合，则标紫框 ▸、可压栈换图。承重主语集合 = 默认入缝 ∪ 右栏实现方法 ∪ 已有 `flows[id]` 的符号。`to` 为到达通道（`kind=entry`）**不得**标紫、**不得**换图。

CLI / HTTP / WS 是**到达通道**：挂在当前主语上，标明「谁能从程序访问面调到它」，**不是泳道主语**。Cobra 分组命令没有行为，继续不是泳道。点通道 = 高亮右栏该通道条目，以及图上从该通道到达当前主语的第一步（若有）；没有对应步则只高亮右栏。不新开一张以通道为主语的图。

**结构轴旧路卸掉**：基本信息里的 CLI/HTTP/WS 列表改为只读到达通道，点击**不**打开流程图。「对外面」未折叠入缝（及展开后的入缝）才是进图按钮。对外面 tab 里不得再写「点程序入口进流程图」。

形态仍对照原型 `behav-flow.html`，不另起标准：

- 主干 = 快乐路径（改变结果的调用）
- 菱形 = 分支（要看得出是菱形，不能只是橙色圆角矩形）
- `if err != nil { return }` = 菱形右侧返回终点，**不占主干行**
- 分支体缩进成子干，左侧「否」旁路绕回
- 装不下蛇形折列，接续段走边缘带
- 紫框 = 上条机械判据命中的 call 步
- 双线框 = 接口；图上展示接口，右栏列实现，点实现换到该实现方法的图

扫描侧：`flows` 的键覆盖三类主语（见契约语义对 §2.1-5 的替换）。`if err { return }` 必须写成 `branch.then = [return 步]`，return **不得**再作为未引用的 sequential root。嵌套 `body` 树与 SSA 级 CFG 仍归 roadmap 27/32。不要求全函数覆盖：CLI 对没有 `flows[id]` 的符号显式降级，不拿 `chain` 冒充。

### 导航：每一张图都能回上一层

页内维护下钻栈，不依赖浏览器后退。

- 从结构轴「对外面」点入缝 → 栈底 = 这张契约方法图。
- 点紫框 ▸、点右栏某个实现、点「被谁调用」里**允许换图**的项 → 压栈。主语已在栈中则再压一层（允许 A→B→A），不跳回旧层。
- 流程图页只留一颗 **← 上一层**：弹出栈顶。栈底那一次由装配层切回结构轴，并保住原 scope（不得重挂后回到根）。默认不做第二颗「跳过整栈回结构轴」；要并列必须显式加，本期不加。
- 面包屑可点：`结构轴 ▸ 主语1 ▸ 主语2 ▸ 当前`，点祖先直接跳到那一层（截断其后）。
- 栈语义只有一条：**上一层 = 我从哪张图来的**。从「被谁调用」往上走和从紫框往下走是同一条栈。

### 右栏（行为轴 · 基本信息）

常驻三段，缺则显式空态，不渲染看起来完整的假读数：

| 段 | 内容 | 点它 |
|---|---|---|
| 到达通道 | 能到达当前主语的 CLI / HTTP / WS（`kind=entry`） | 高亮，不换图、不压栈 |
| 实现 | 当前主语是接口方法，或选中步骤是接口调用时：全部实现方法 | 换到该实现方法的流程图（无 `flows` 则降级空态） |
| 被谁调用 | 当前主语的**直接**调用方（与 `who-calls --depth 1` 同一批边） | `kind=entry` 的项按到达通道处理（高亮、不压栈）；其余有 `flows` 的压栈换图；没有的只显示名字，标「无流程图」 |

C12 的入口归属 / 注册散度 / 入口族（§2.4-32 的旧「程序入口」读法、§2.4-33/34）**不再是行为轴页的必有段**。若保留，只挂在「到达通道」当注释，不得用契约方法名去套 CLI/HTTP 族规则。

「调用链（给 agent）」tab 保留（C12 已冻结的机械下游），不冒充流程图，本期不删。agent 看「怎么走」走 CLI `flow`。

### CLI：`codegraph flow <节点 id 或名字>`

与 `sym` / `chain` / `who-calls` 同树、同一套符号决议（id 精确 > Name 精确 > 方法尾段）。`handoff graph` 别名自动具备。

一次调用给人/agent 三样东西（字段名归 contract）：

1. **定位**：id、名字、file、line、再锚定状态（与 `sym` 同套）
2. **流程图**：`flows[id]` 的步骤树，**不是** `chain` 的调用图切片
3. **邻域摘要**：直接调用方、实现清单、到达通道

缺 `flows[id]`：输出显式 `degraded`，steps 保持空；**禁止**把机械可达序列填进 steps。符号不在图中：与 `sym` 相同的未覆盖错误。默认只给定位，不挂 `--with-source`（要源码窗口用 `sym` / `chain --with-source`）。

`codegraph summary` 的开局菜单补上 `flow` 与 `tree`。

### CLI：`codegraph tree`（两种用法，不是 chain 换皮）

向下如果只把 `chain` 的节点列表 nested 打印，菱形仍去重，做完和 `chain` 差不多，**不做这种**。值得做的是字面树 + 向上走廊。

| | `chain` / `who-calls` | `tree` |
|---|---|---|
| 形状 | 调用图切片：汇合点出现一次 | 真树：菱形在两条路径上各出现一次 |
| 问的是 | 碰过谁 | 沿哪条路径下去 / 从哪条走廊上来 |
| 同一函数里两个调用的先后 | 没有 | **没有**（与 chain 一样不保证源码序）；子节点按名字、同名再按 id 稳定排序。禁止为排序去读 `flows` |
| 过滤 | 深度 / 折叠工具节点 | 向上可再卡「上面那层 + 调用那层」；tree **不**做 chain 那套折叠，截断只走 `truncated` / `--once` |

`chain` 保留。不给 `chain` 加 `--pretty`。

**用法一 · 向下（缺省）**

```
codegraph tree <节点 id 或名字> [--depth N]
```

根 = 焦点。子节点 = 这个方法调过的方法，再递归。`--depth` 与 `chain` 同语义（缺省 2，`0` = 不限）。自环作为子节点出现一次并停止展开。共享被调方在每个父下各挂一份——测试锁死：菱形 A→B, A→C, B→D, C→D，`chain` 里 D 出现 1 次，`tree` 里 D 出现 2 次。

**用法二 · 向上（被谁调到，带走廊）**

```
codegraph tree <焦点> --up [--depth N] [--through <上面那层>] [--from <调用上面那层的方法>]
```

根仍是焦点，子节点是调用它的方法。depth **从焦点计**，与 chain 相同。`kind=entry` 不当成隐式刹车。

- `--through U`：只保留经过 U 到达焦点的反向路径。U 是上面那层（焦点的某个祖先）。**只给 `--through` 时仍保留 U 之上的反向祖先，直到 depth 用尽**；要切掉 Hub 必须再给 `--from`。
- `--from F`：必须同时给 `--through`。只保留正向边 `F → U` 且 U 到达焦点的路径。
- 只给 `--from` 不给 `--through`：命令失败。
- `--through` / `--from` 出现在向下模式：命令失败。
- U 不是焦点在该 depth 内的祖先、或 F 并不调用 U：命令失败，不返回被截断的空走廊装成功。

```
codegraph tree Store.GetTask --up --through Manager.Dispatch --from handleFlowPost
```

展开过大显式 `truncated`。`--once` 可选，缺省关。

决议、`--repo` / `--view` 与 `chain` 同套。输出嵌套 JSON（根 + `children`）。

### Agent 怎么用图（近 12 小时实测）

第一跳经常是 `context <领域>`，不是行号。行号已由 `sym` 给出。缺的是「这个方法怎么走」和「沿哪条路径」。钉死：

```
领域从哪下手       → context <领域>
已经有名字         → sym（定位+行号）
这个方法怎么走     → flow（没有就 degraded，禁止拿 chain 冒充）
沿哪条路径下去/上来 → tree / tree --up --through --from
碰过谁（切片）     → chain / who-calls
```

C16 已钉「调用链 ≠ 流程图」。skill 正文「点程序入口进流程图」随本卡改术语。

## 用户故事

1. 作为看图的人，我点子系统「对外面」里的一个契约方法，看到的是这个方法怎么走，而不是某个 HTTP 路径怎么注册。结构轴「程序入口」列表点不进图。
2. 作为看图的人，我在那张图上能看出快乐路径；提前失败甩在旁边，不会和主干缠成朝上的「返回」列。
3. 作为看图的人，我能看到这个契约方法是被哪些 CLI/HTTP/WS 通道调到的，但不需要为每个通道再看一张重复的图。
4. 作为看图的人，点「任务编排」时，「对外面」能进 `Store.GetTask` / `Manager.Dispatch` 这类方法的图；不再出现「这张卡没有程序入口因此没有流程图」。
5. 作为看图的人，我从紫框走进下一张图之后，用「上一层」回到来处；从结构轴进来的第一张图，上一层是结构轴。
6. 作为看图的人，右栏列出的每个实现都是一张流程图的主语；点进去看这个实现怎么走，再回到接口那一层。
7. 作为看图的人，右栏能看到谁在调用当前这个方法。其中 `kind=entry` 的项只高亮不换图；其他有流程图的可以点进去；没有的不会假装有。
8. 作为 agent，我可以对一个方法名跑 `codegraph flow`，一次拿到它在哪、怎么走、被谁调；没有流程图时命令明确告诉我缺数据。
9. 作为 agent，我可以对一个方法跑 `codegraph tree` 看到它内部调用递归展开成树；向上查时用 `--through` / `--from` 卡住走廊。

## 契约语义与接缝（相对 C12 的增量）

废止并替换：

- §2.4-30「一条程序入口一张流程图」→ **一条泳道主语一张流程图**。默认落地主语 = 对外入缝；下钻主语 = 紫框目标或右栏实现方法。`deriveFlowPage` 的缝地址不变；输入里那个节点 id 的语义从 `kind=entry` 改为「当前泳道主语」。字段名若仍叫 `entryNodeId` 必须在契约注释里写明「历史名，不是 CLI/HTTP」。
- §2.4-32 入口归属：主语改为当前泳道主语所属子系统；CLI/HTTP 的「第一次跨域」归属降为通道的注释，不再决定泳道在哪张卡上。行为轴页不再必画归属段。
- §2.4-33/34 注册散度与入口族：不再是行为轴页的必有段。仍只对到达通道有意义；若保留则挂在「到达通道」当注释，不得用契约方法名套 CLI/HTTP 族规则。
- §2.4-35 中「每个实现的入口即其流程图起点」→ **每个实现方法自己即其流程图主语**；禁止再到实现容器里找 CLI/HTTP。形态断言（菱形、卫语句甩侧、蛇形、紫框、双线框）仍执法。紫框改用本 spec 的机械判据，不再等于 `kind=entry`。
- §2.4-36 术语：**对外入缝 = 默认落地的入口 = 结构轴点进去的泳道主语**。CLI/HTTP/WS 改称**到达通道**。实现方法与紫框目标是**下钻主语**。禁止再写「点程序入口进流程图」。结构轴程序入口列表只读。
- §2.1-5 承重函数集合改为 **对外入缝 ∪ 紫框下钻目标 ∪ 右栏列出的实现方法**。入口 handler 不再因「它是程序入口」进入承重集合。通道上残留的 flows 只作注释数据，不是默认主语。

保持并执法：

- §2.4-31 禁止用机械可达序列冒充流程图。CLI `flow` 与查看器同一条禁令。
- §2.4-35 其余形态断言（菱形、卫语句甩侧、蛇形、双线框）。

本卡新增语义（精确签名归 contract）：

- 行为轴页内下钻栈：一颗上一层 / 可点面包屑 / 栈底回结构轴并保住 scope。
- 右栏常驻「被谁调用」；`kind=entry` 不压栈。
- graph CLI 增加 `flow` 与 `tree`；`summary` 菜单包含它们。`tree` 与 `chain` 的菱形计数差有测试锁。已落 CLI 是现状读数，**不可当冻结物**——contract 按本 spec 冻结 JSON。

## 实现决定

- 结构轴进图：只从「对外面」未折叠（及展开后的）入缝进入行为轴。基本信息里的 CLI/HTTP/WS 列表只读，点击不打开流程图。
- 行为轴页打开任意有 `flows[id]` 的主语（入缝、实现方法、紫框目标）。
- 通道：右栏列出能到达该符号的 `kind=entry`，只读高亮。
- 实现：右栏每一项以该实现方法为下一张图的主语压栈。
- 被谁调用：直接调用方；`kind=entry` 不压栈；其余有 `flows` 的压栈。
- 导航：流程图页只留一颗 ← 上一层；栈底切回结构轴并保住原 scope；面包屑祖先可点。不依赖 iframe 的浏览器历史。
- 布局：卫语句臂必须甩侧且不进蛇形 `linear`；真菱形，不能只靠琥珀色边框冒充。
- CLI：`flow` 与 `tree` 已在本分支挂命令（流程债）。contract 冻结 JSON 后，实现轮把查看器接上，并按冻结物核对 CLI 字段；缺的补、多的删。`handoff graph` 同树。`tree` 只读现有调用边，不改扫描配方，不为排序读 `flows`。
- 扫描配方（handoff，本卡交棒）：承重 `flows` 键 = 对外入缝 ∪ 紫框下钻目标 ∪ 右栏实现方法；禁止把卫语句 return 做成未引用 root。
