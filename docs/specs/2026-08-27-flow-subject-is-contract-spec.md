# C17：行为轴泳道主语改为对外契约方法

**卡**：C17 · **级别**：L3 · **档位**：轻档
**状态**：**待用户批准**
**上游**：C12 `docs/specs/2026-08-25-codegraph-viewer-two-axis-spec.md`（已批准）+ `docs/superpowers/specs/c12-contract.md` §2.4-30/32–36
**形态基准**：`prototypes/codegraph-two-axis/pages/behav-flow.html`（C12 走查确认的那张；不入库，C14 携带提交 `d267310b` 可还原）

## 问题陈述

C12 把「人看流程图、只留入口」做成了：**一条 CLI/HTTP/WS 程序访问面一张图**。用户原意是：**入口 = 对外契约 = 被外部调用的方法**。CLI/HTTP 只是到达这些方法的通道。

真机后果（2026-08-27）：

- 点「任务编排」右栏「没有程序入口」——入口容器挂在 `d_cli` / `d_gateway`，契约方法没有泳道。
- 点 `GET /console` 得到的图是 handler 里每一句 `if err { return }` 摊上主干再蛇形翻转，看不出这个方法对外在办什么事。
- 「对外面」tab 列的才是契约面，却点不进流程图。

C12 契约 §2.4-30「一条程序入口一张流程图」和 §2.4-36 术语三分（程序入口点进图、对外入缝只在「对外面」）把这次误解写死了。本卡废止这两条的主语，不推倒结构轴、不推倒 `flows` 的 JSON 形状。

## 级别与档位

**L3 · 轻档。** 改的是 C12 已冻结的行为轴语义（泳道主语、点哪里进图），扫描配方的承重范围跟着改；实现仍落在查看器 + 配方，不新造分层，不扇出子卡。

## 方案

**一张流程图 = 一个对外被调方法**（与结构轴「对外面」tab 同一批符号：跨域入缝，噪声折叠同一判据——兜底桶 ∧ 复用度 ≥ 10 的不占泳道）。

CLI / HTTP / WS 是**到达通道**：挂在该契约方法上，标明「谁能调到它」（哪些程序访问面可达），**不是泳道主语**。Cobra 分组命令没有行为，继续不是泳道。

人从结构轴右栏「对外面」点一个未折叠的入缝，进入它的流程图。右栏「程序入口」仍列出通道，点通道 = 高亮「从这里进来」，不新开一张以通道为主语的图。

形态仍对照原型 `behav-flow.html`，不另起标准：

- 主干 = 快乐路径（改变结果的调用）
- 菱形 = 分支（要看得出是菱形，不能只是橙色圆角矩形）
- `if err != nil { return }` = 菱形右侧返回终点，**不占主干行**
- 分支体缩进成子干，左侧「否」旁路绕回
- 装不下蛇形折列，接续段走边缘带
- 紫框 = 该步本身是下层契约方法，点进去换一张图
- 双线框 = 接口；图上展示接口，右栏列实现

扫描侧：`flows` 的键是这些契约方法的节点 id，不再以 `kind=entry` 为人类泳道主语。`if err { return }` 必须写成 `branch.then = [return 步]`，return **不得**再作为未引用的 sequential root——否则布局无法甩侧，必然再现 `GET /console` 那种「返回墙」。嵌套 `body` 树与 SSA 级 CFG 仍归 roadmap 27/32；本卡只要求现有四值 `kind` + then/else/body 引用能表达卫语句与子干。

## 用户故事

1. 作为看图的人，我点子系统「对外面」里的一个契约方法，看到的是这个方法怎么走，而不是某个 HTTP 路径怎么注册。
2. 作为看图的人，我在那张图上能看出快乐路径；提前失败甩在旁边，不会和主干缠成朝上的「返回」列。
3. 作为看图的人，我能看到这个契约方法是被哪些 CLI/HTTP/WS 通道调到的，但不需要为每个通道再看一张重复的图。
4. 作为看图的人，点「任务编排」时，「对外面」能进 `Store.GetTask` / `Manager.Dispatch` 这类方法的图；不再出现「这张卡没有程序入口因此没有流程图」。

## 契约语义与接缝（相对 C12 的增量）

废止并替换：

- §2.4-30「一条程序入口一张流程图」→ **一条对外契约方法（入缝符号）一张流程图**。`deriveFlowPage` 的缝地址不变；输入里那个节点 id 的语义从 `kind=entry` 改为「当前泳道主语」（入缝符号）。字段名若仍叫 `entryNodeId` 必须在契约注释里写明「历史名，不是 CLI/HTTP」。
- §2.4-32 入口归属：主语改为入缝符号所属子系统（它本来就在该域）；CLI/HTTP 的「第一次跨域」归属降为通道的注释，不再决定泳道在哪张卡上。
- §2.4-36 术语：**对外入缝 = 人看的入口 = 泳道主语**。CLI/HTTP/WS 改称**到达通道**，列在契约方法的基本信息里。禁止再写「点程序入口进流程图」。

保持：§2.4-31 禁止用机械可达序列冒充流程图；§2.4-35 形态断言（菱形、卫语句甩侧、蛇形、紫框、双线框）。

## 实现决定

- 查看器：`onOpenEntry` 的调用点从「程序入口」列表改到「对外面」未折叠入缝；FlowPage 打开任意有 `flows[id]` 的入缝符号。
- 通道：入缝页右栏列出能到达该符号的 `kind=entry` 节点（按 channel 分桶），只读。
- 布局：卫语句臂（then/else 成员全是 return）必须 `guardReturn` 且不进蛇形 `linear`；真菱形（clip 或旋转），不能只靠琥珀色边框冒充。
- 扫描配方（handoff，本卡交棒或同批）：承重 `flows` 键 = 对外入缝（与噪声折叠同一批）；禁止把卫语句 return 做成未引用 root；CLI/HTTP 的 flow 可留作通道下钻，但不是查看器默认主语。
- C16 skill 正文里「程序入口点进流程图」随本卡改术语，避免两套说法并存。

## 测试决定

缝：`deriveFlowPage`（主语改入缝、通道列表、缺 flows 仍 degraded）。布局缝：卫语句不进 `linear`、菱形 `data-shape=diamond` 且几何不是圆角矩形。页面：点「对外面」某入缝出现流程图；点「任务编排」能打开至少一张契约方法图。
