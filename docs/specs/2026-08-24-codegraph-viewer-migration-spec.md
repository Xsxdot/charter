# Spec：查看器二期——下钻 + 迁移视角对照 + 欠账读数（C1.9）

> **状态：已批准（2026-08-24，用户「OK，开工吧」；形态基准 prototypes/codegraph-phase2 同日确认——嵌套同构下钻裁决已并入）**
> 级别/档位：**L2 单子系统**（仅动 charter `graph/webui`；消费 C1.3 一期已冻结的响应字段，宿主零改动、不触 wire 契约）
> 来源：roadmap 第 10 条二期残余的取舍重排——主轴改为用户实际痛点（2026-08-24 拍板），A 组愿景顺延三期。

## 问题陈述

一期把理想树与执法读数上了墙，但三个痛点留在原地：①点子系统卡进不了子领域（无下钻）；②「和现状差在哪」只有数字读数，没有可行动的形态；③距离感缺失——预算棘轮钉在现状值，36 条边全显示 N/N「顶格绿」，602 笔直调债在视觉上等于零欠账。B233（架构物理化刀系）确立了终态：按理想图分目录、client 包收口、绞杀式逐边迁移——查看器二期就是这场战役的作战地图。

## 现状读数（事实核查，2026-08-24）

- 数据面：一期响应已含 `best / target / report` 全量（`graph/webui/src/api/types.ts#CodegraphResp`），二期全部读数均可由现有字段客户端派生，无需宿主改动：
  - 放错位明细：`report` warns（container-misplaced，BestDetail 对照段已在消费）；
  - 直调实测/预算：一期边标签已算（`besttree.ts` 方向聚合）；
  - 窄缝覆盖：`target.contracts[].entries`（实测 3 个入口 / 36 条方向）；
  - 双向环：`target.contracts` 对偶检测（实测 3 对：gateway↔orchestration 319/2、orchestration↔workspace 19/2、policy↔transport 2/4）。
- handoff 实测量级：放错位 50（全在 Web 控制台，应归 6 个子领域）、直调余额 602、fails 0、未归属 0。

## 方案（含已拍板裁决与弃选）

**对照形态 = 迁移视角（用户 2026-08-24 拍板，方案 1）**：理想树仍是唯一画布，差异画成「待迁移件」——放错位容器标红、下钻页画迁移边（现在在 X → 应归 Y）、全局迁移清单侧栏。理由：diff 是稀疏的（结构差异集中在一家子系统），且最优图的存在意义就是迁移目标，对照应是行动清单而非观察任务。**弃选**：双画布理想/现状切换（稀疏 diff 下人眼来回记忆，多数切换无效）；域页内并排（11/12 子系统 diff 为零，只有一页有内容）。

**主轴取舍（用户 2026-08-24 拍板）**：二期只做下钻 + 迁移对照 + 欠账读数；A 组（语义 tab、泳道、级联、组织切换）顺延三期，理由是它们消费职责/生命周期数据——B231 扫描补职责面完成前做是空壳。

**形态基准**：`prototypes/codegraph-phase2/`（fork 自 base，2026-08-24 走查确认为准）。

## 用户故事

1. **欠账横幅**：全景顶部读数从「执法读数」升级为欠账四件套——直调余额（Σ实测直调）、窄缝覆盖（有入口方向数/总方向数）、放错位数、双向环对数；fails>0 时红字仍最高优先。
2. **边按债务着色**：跨子系统连线不再以 N/N 顶格显示为中性——按直调量级梯度着色（0 淡 → 重债深），标签「欠 N」；点边看方向明细（实测/预算、窄缝清单、双向对端警示）。
3. **迁移清单侧栏**：按「应归领域」分组列出全部放错位容器（容器 · 现在在 X → 应归 Y），组头计数，总数与横幅一致；点条目跳转到对应子系统下钻页并高亮该容器；无放错位时显示「无待迁移件」。
4. **下钻 = 嵌套同构（用户 2026-08-24 拍板）**：每进一层都是与首层同一套全景逻辑——本层子领域卡 + 层内聚合调用边 + 圈外虚线占位卡（横跳），面包屑逐级返回；递归到**叶子领域**切换为领域图（容器视角，按包分组、带节点数，沿一期形态）。迁移与欠账是叠加在每一层上的覆盖层：有未归位容器的层显示「未归位」托盘 + 迁移箭头指向应归子领域卡；应归而未迁入的叶子领域以幽灵容器（虚线 + 待迁入标）呈现未来态。弃选：迁移专用特设页（打破层级同构，一次性布局无法递归）。
5. **回退不变**：无 best 项目照旧回落现状域全景；切分支视图行为与一期一致（对照恒面向主线）。

## 实现决定

- 纯查看器改动：迁移清单、债务聚合、环检测都在纯函数层派生（沿 `besttree.ts` 纯函数 + 组件薄壳的既有分层），不在组件里就地聚合。
- 下钻页为新组件（子系统页），容器分组树复用一期 BestDetail 已验的分组逻辑（提公共件，不复制粘贴）。
- 不动宿主、不动 `codegraph/diffs` 视图叠加、不加路由库——下钻状态沿用组件内状态 + 面包屑（与原型一致）。

## 测试决定（接缝清单）

- **纯函数缝（主）**：迁移清单派生（分组/计数/排序）、债务聚合（余额、窄缝覆盖）、双向环检测——vitest 直测，含变异验证（如环检测漏对偶必须能红）。
- **组件缝**：横幅读数、侧栏分组渲染、下钻进出与高亮——testing-library 既有模式。
- 一期用例不红即回退语义未破。

## Out of Scope

- 三期 A 组：领域页语义 tab（职责/不变式/状态机/生命周期锚）、订单样例泳道、级联调用链面板、组织切换（本期不做、后续要做，已在 roadmap 第 10 条排队）。
- 组/容器职责文案展示——数据依赖 B231（roadmap 10a），本期不做。
- legacyHits 逐边明细、窄缝清单编辑——永不做进查看器（一期 OOS 延续）。
- 迁移的操作性功能（在图上点一下真改 best.json/target.json）——查看器只读，编辑归 CLI 与 contract 节点。
- per-view 对照重算——延续一期裁决，等真需求。
