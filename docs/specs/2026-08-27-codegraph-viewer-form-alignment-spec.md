> 上游：C12（已完成）的形态偏差复核；偏差清单与取证在 `docs/roadmap.md` 第 49 条，同族项第 48 条。

## 问题陈述

C12 实现的两轴查看器骨架（一页按 scope 变、容器原子、右栏三 tab、显式降级）与确认原型一致，
但**布局层与卡面读数层**与原型差距显著（2026-08-27 用户真机复核发现，协调者 DOM 取证核实）：

1. 根层拓扑分层未实现（spec 布局判据第 3 条冻结的 SCC 缩点/环红标/孤立节点单列全部缺席，
   `graph/webui/src/app/codegraph/scopelayout.ts` 无对应代码）；
2. 摆放判据未达「一屏见全部、交叉最少」（根层 12 卡有 2 张被裁出视口，连线穿卡打结）；
3. 容器卡面 doc 职责缺席（类型方法容器应显示同名 model 节点 doc 摘要，原型有、实现无；
   推导代码在 `scopepage.ts:503` 但真数据上未出文本）；
4. 子系统卡面入口数徽标缺席（原型有「43 入口·集中」橙标；实现的入口散度只在右栏）。

漏网原因（流程侧）：C12 验收对照的是 `prototypes/base/README.md` 的形态要点摘要，
而非其指定的最终基准——fork 页面本身。本卡的验收因此必须上重判据（见测试决定）。

## 方案

**选定：以 fork 原型代码为唯一形态基准，逐项直对（用户裁决 2026-08-27）。**

不经 spec/plan 的文字转述中间层——形态基准即代码。执行者直接读
`prototypes/codegraph-two-axis/` 的 `shared/graph.js`（293 行：Tarjan SCC → 最长路分层 →
货架装箱；孤立节点例外；环/双向边红标；边色按预算）、`index.html`（卡面结构与徽标）、
`shared/style.css`，把行为移植进 webui 的派生层与组件，而不是照本段文字重新发明。

弃选与理由：

- **弃选「文字描述对齐」（C12 老路）**：已证伪——摘要是要点不是基准，形态细节（分层标注、
  徽标、职责文本、连线语义）在转述中全部丢失。
- **弃选「重写查看器」**：骨架已是对的，塌的是布局层与卡面读数层；重写违反 YAGNI。

## 实现决定

1. **基准载体与派发前提**：fork 原型 gitignore 不入主线库；本卡的卡分支携带
   `prototypes/codegraph-two-axis/` 全量作为参照物（force-add 入卡分支），
   finish 合并前移除该携带提交——base/README 的单一基准地位不变。
2. **对齐清单 = roadmap 第 49 条①–④ + 第 48 条**，逐条以原型代码为准对齐；
   原型与 C12 冻结契约冲突处（若有）以契约为准并在卡上记分歧，不静默取舍。
3. **不动 wire 数据与 API**：`/api/projects/{name}/codegraph` 响应零变更；
   只动 `graph/webui` 的派生层（scopepage/scopelayout）与组件薄壳（ScopeCanvas 等）。
4. **布局算法以移植代重写**：原型 `graph.js` 的分层/装箱/孤立例外逻辑移植为 TS 纯函数，
   保持纯函数派生层 + React 薄壳的既有两层架构（C12 contract §0）。

## 测试决定（接缝清单）

唯一新缝不开——全部落在既有最高缝上：

- **缝 1：`scopelayout` 纯函数**（现状：`graph/webui/src/app/codegraph/scopelayout.ts`，
  调用方 ScopeCanvas.tsx 可 grep）——分层正确性：topo 序、SCC 同层、环/双向边标记、
  孤立节点例外行、一屏可见性（装箱输出无负坐标、无出视口）。
- **缝 2：`scopepage` 纯函数**（现状：`scopepage.ts`，调用方同上）——卡面读数：
  类型方法容器 doc 职责文本在场（真数据夹具）、入口数徽标与集中注册债务色。
- **组件薄壳**行为断言照旧（渲染接线，禁 snapshot）。
- **验收重判据（roadmap 29 首次启用）**：同视口逐屏对拍——原型页（自带 mock 真数据）vs
  真实页（隔离实例 c12data），根层/领域层/容器层三 scope 截图并排 + 关键 DOM 在场断言；
  不再接受「核摘要」式验收。
