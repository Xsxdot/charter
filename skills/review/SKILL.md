# Review：审查与验收

审查者拿精确构造上下文（spec 故事与原型/流程版本、plan、冻结物、diff），不继承实现会话；读不到已批准基准不得声称已对照。裁决表头标阶段（子卡 / 单卡最终 / 父卡最终）、故事与 plan 版本，首节也是「偏离与自主决定」（审查者自行拍板处）。

## 第一步：核偏离

先读被审交回物首节：①逐条对照 plan「决策权限」看是否越权；②对照 diff 抽查，plan 未写或与 plan/spec 不一致的改动是否都在该节。**缺失、漏报或越权未披露直接 fail，不进两轴**；越权已披露交协调者裁决；「无」且 diff 无偏离记「已核」。

## 双轴

两轴分别报告，**不合并、不互相重排**：

- **目标轴**：对照本轮故事/步骤、批准的原型/流程分支、plan 边界与验收方式；双向查 **scope drift**（承诺未做？未授权新增？），核实际截图/输出/运行证据与基准差异；不以过时内部步骤逐字一致为标准。
- **架构与证据轴**：对照权威状态归属、真实生产组装/消费链、既有或新冻结契约与测试证据（拿不准查 `architecture-law`）；演示绿而新增路径越界仍裁失败。

## 裁决表

每格 **verdict + 证据指针**（文件:行或命令输出）：

| 维度 | verdict |
|---|---|
| 偏离与自主决定 | 已核 / **缺失、漏报或越权未披露（fail）** |
| 故事与验收覆盖 | 通过 / 缺项（列出）/ 不适用+理由 |
| 原型/流程基准差异 | 已按版本对照（证据）/ 差异待裁决 / 无约束 |
| scope drift | 无 / 有（双向各列）|
| 越界 | 无 / 有——新增跨子系统穿透、改写他方权威状态、新增对外承诺未冻结（各给证据）|
| 缺陷族三问 | 静默失败或误导报错 / 假绿或假红 / 门禁绕过——各给证据或「无」+理由 |
| 测试有牙 | 已验（红绿证据 + 变异复验）/ 未验+理由；内部单测不能独自证明用户故事 |
| 日志与注释 | 通过 / 缺（列位置）|
| 序列化边界 | 有穿透断言 / 缺 / 无新字段 |
| 适用契约 | 符合（给版本）/ 触碰已回写（给修订号）/ **触碰未回写（阻塞）** / 无新增 |

契约触碰：本轮发现**推翻、增补或澄清了已冻结内容**，须回 plan 冻结节回写留修订号；仅内部可逆调整记理由与验证。**禁止无检查过程的「no issues」**：每格有证据或有理由，空格即未完成；跑过的命令与输出、看过未成 finding 的地方写进裁决表。

## Findings

Critical（立修）/ Important（本节点内修完）/ Minor（记账不阻塞）。触及故事结果、权威状态、外部兼容或共同边界的交协调者裁决；局部可逆调整按 plan 授权判断。**落卡，不留对话**：Critical/Important 写进卡验收栏或独立缺陷卡，按卡核销。

## 验收

**顺序铁律：复跑 → 承重变异 → 真机 → 裁决；通过后才可归档。**

**阶段**：子卡只裁其工作单元技术结果与真实消费者接入条件，不替父卡核销故事；单卡即最终验收；父卡在全部子卡合入后逐项核销全部必交故事、原型/流程状态、关键反例与回归；子卡技术绿、首故事旧绿或「已开修复卡」不抵账。

1. **复跑**：没有本轮跑出的证据不许声明通过，「早些时候绿过」不算；执行者自报的绿用 diff 与复跑独立核验。
2. **变异复验**：把实现改坏一处，对应测试必须转红、还原回绿；全流程唯一一次变异。变异点选**本次交付的承重行为**；多路径共用的实现变异一处应使每条声称覆盖它的路径都红，至少一支穿真实消费入口或生产接缝。**变异必须编译得过**（删行常连带编译错、0 失败假象；优先取反、改边界值、改比较符）。**变异必须打中唯一**（变异前确认命中唯一，变异后先跑最相关用例确认行为真变）。「一切如常」先怀疑变异没生效。
3. **真机验收**：API 事实可 grep，行为事实（通路、字段写入者）**只有跑起来才知道**。plan 每条「未验证，需真机」在指定环境逐条执行（implement 已跑的首跑项核其证据）；指定浏览器、机器、账号、数据集或隐私状态的证据不可自判等价，环境不可用标未验并请批替代判据；受原型/流程约束的故事拿实际截图/输出/轨迹对照指定版本；落卡的 Critical/Important 逐条核销。
4. **契约对照**：有新冻结物核版本及消费方证据，无则查既有契约和实际架构调用；既有证据失效时补跑，留旧记录。

**父卡最终验收另做四件事**：在合入全部子卡的父卡分支跑**全量**，红的先定归属，跨卡接缝缺陷归父卡；逐条核对跨子系统可观察行为在生产代码中有真实触发者、载体、消费者与结果，只有接口/空壳/替身按未完成，不靠全量绿放行；集成新发现缺陷逐个记录（现象、根因、归类）；**回旋镖对账**——plan 预测（判据、影响面、耗时、「无风险」）与实测逐条对账，预测错不是过失，不对账才是。

判定「退回/留待下一期」的缺口逐条落 `docs/roadmap.md`；**原承诺欠交、脱敏/隐私/安全红线不能只转 roadmap 或新修复卡就判通过**，须修复重验或请用户显式变更承诺与风险接受范围。

## L1 单审一轮

L1 由主会话亲审，不派独立审查 subagent：复跑 + 一次变异 + 真机一眼，一轮出裁决。裁决表可压成偏离 / 变异 / 真机三行，每行仍给证据；顺序铁律与落卡不变。

## 红线

- **审查是只读回合**：不 commit、不改文件，合法产出只有裁决表与 findings；可顺手修的也只记 finding。
- **待审 diff 找不到时提问，不重做**：不按 plan 重做再审自己写的。

## 收到反馈

- **先核验后实现**：反馈对照代码现实，错了用技术理由推回。
- **禁表演性认同**：不写「You're absolutely right」类，行动代替感谢。
- **一条不懂，全部暂停**：部分理解 = 错误实现。
- 建议「正规实现」某能力先查有人用否，没人用提议删。
