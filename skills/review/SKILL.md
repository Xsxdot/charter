# Review：审查与验收

**角色**：审查者拿到精确构造的上下文（spec 故事与原型/流程版本、适用 plan、冻结物若有、BASE..HEAD diff），不继承实现会话史。读不到已批准的基准，不得声称已对照通过。裁决表头标明本轮阶段（子卡阶段 / 单卡最终 / 父卡最终）、故事/步骤与所审 plan 版本。

**交回物第一节固定为「偏离与自主决定」**：本节点的交回物（裁决表 / 报告 / 交棒声明）第一节标题固定为「偏离与自主决定」，逐条列出：①与已批准 plan 或 spec 不一致之处；②本节点执行者自行拍板的内容与理由；③每条是否落在 plan「决策权限」节的授权范围内。没有偏离时必须写「无」，不得省略该节。

## 第一步：核对「偏离与自主决定」

开审先读被审交回物的第一节「偏离与自主决定」，做两件事：①逐条对照 plan「决策权限」节——每条自行拍板是否落在授权范围内；②对照 BASE..HEAD diff 抽查——diff 里与 plan/spec 不一致、或 plan 未写而执行者自定的改动，是否都在该节里。**该节缺失、漏报、或越权未披露，直接判 fail，不进入两轴裁决**；越权但已披露的，交协调者裁决，照常进两轴。该节写「无」而 diff 无偏离，记「已核」后进两轴。

## 双轴，互不遮蔽

两轴分别报告，**不合并、不互相重排**——合格代码实现了错东西，与实现对了但破坏规范，是两种病，一轴的干净不许掩另一轴：

- **目标轴**：对照本轮故事/步骤、批准的原型页面状态或流程分支、适用 plan 的边界与验收方式。双向查 **scope drift**（承诺未做？未经授权新增？），核验实际截图/输出或运行证据与基准的差异；不以计划中已过时的内部步骤逐字一致为完成标准。
- **架构与证据轴**：对照 `architecture-law`、权威状态归属、真实生产组装/消费链、适用的既有或新冻结契约，以及测试证据。故事演示绿而新增路径越界，仍裁失败。

## 维度化裁决表

每个维度必须给 **verdict + 证据指针**（文件:行 或命令输出），不打分数：

| 维度 | verdict 取值 |
|---|---|
| 偏离与自主决定（第一步） | 已核（与决策权限一致、抽查无漏报）/ **缺失或漏报或越权未披露（fail，不进两轴）** |
| 故事与验收覆盖 | 通过 / 缺项（列故事或步骤）/ 本轮不适用+理由 |
| 原型/流程基准差异 | 已按版本对照（证据）/ 差异待裁决 / 本轮无形态或流程约束 |
| scope drift | 无 / 有（双向各列）|
| 架构法与触及路径 | 通过（实际边界/生产调用证据）/ 违条（引条号）/ 未验证（列缺口）|
| 测试有牙 | 已验（承重行为的红绿证据 + 下文变异复验）/ 未验+理由；内部单测不能独自证明用户故事 |
| 日志与注释覆盖 | 通过 / 缺（列位置）|
| 序列化边界 | 有穿透断言 / 缺 / 本次无新字段 |
| 适用契约 | 既有/冻结物符合（给版本）/ 触碰已回写（给修订号）/ **触碰未回写（阻塞）** / 无新增冻结对象 |

冻结物触碰行的判据：本轮的发现或裁决**推翻、增补或澄清了已冻结内容**吗？有就须回 plan「需冻结的外部承诺」节回写并留修订号；只有工作单元内部可逆调整时，记简短理由和验证结果即可。原型/流程基准冲突由协调者核对批准意图，改变用户结果才交用户取舍。

**禁止无检查过程的「no issues」**——每格要么有证据要么有理由，空格即审查未完成。

## Findings 分级

Critical（立修，修完才前进）/ Important（本节点内修完）/ Minor（记账不阻塞）。发现触及故事结果、权威状态、外部兼容或其他卡依赖的共同边界时交协调者裁决；局部可逆实现调整按 plan 授权判断，不因不同于预写步骤而自动打回。**Findings 落卡，不留对话**：Critical/Important 必须写进持久载体（卡的验收栏或独立缺陷卡），验收按卡逐条核销——聊天里转达的 finding 会修两条蒸发一条。

## 验收：行为事实只能跑出来

**顺序铁律：复跑 → 承重变异 → 真机 → 裁决；通过后才可归档。**任务挂在待审状态零成本；提前归档等于赌测试没有盲区。

**三种阶段，同一证据纪律**：子卡 review 只裁其工作单元的技术结果与真实消费者接入条件，不替父卡核销故事；单卡（L1/L2/L3 未扇出）review 即最终验收；父卡在全部子卡合入父卡分支之后做**最终验收**，逐项核销本轮全部必交故事、原型/流程状态、关键反例与已有故事回归。子卡技术绿、首故事旧绿或「已开修复卡」都不能抵账。

1. **复跑：新鲜证据**。没有本轮跑出的证据不许声明通过——「早些时候绿过」不算，执行者自报的绿要用 diff 与复跑独立核验。任何暗示成功的措辞（「应该行了」）都触发本条。
2. **变异复验：测试有没有牙**。把实现改坏一处，对应测试必须转红，还原必须回绿；这是全流程唯一一次变异。变异点选**本次交付的承重行为**，多路径共用的实现变异一处应使每条声称覆盖它的路径都红，转红者至少有一支穿过真实消费入口或生产接缝。**变异必须编译得过**（删一行常连带「未使用」编译错，此时测试一支没跑、失败计数为 0，与「测试是摆设」长得一样；优先取反、改边界值、改比较符）。**变异必须打中唯一**（同名文本命中别处时编译过、测试跑、报 0 红，输出上看不出异常；变异前断言命中唯一，变异后先跑一条最相关用例确认行为真的变了）。「变异后一切如常」永远先怀疑变异没生效。
3. **真机验收**。API 事实（签名存在、方法名对）可以 grep；行为事实（事件走不走那条通路、字段实际谁写入）**只有把系统跑起来才知道**——夹具编码了错误的现实时，单测全绿、变异也红，它们忠实验证了一个不存在的世界。plan 里每条「未验证，需真机」在指定环境逐条执行；指定浏览器、机器、账号、数据集或隐私状态的证据不可自行判为等价，环境不可用就标未验并请求批准替代判据。受原型/流程约束的故事拿实际截图、输出或运行轨迹对照指定版本。落卡的 Critical/Important findings 逐条核销。
4. **契约对照**。有新冻结物时核其版本及消费方证据；无新冻结物时查适用的既有契约和实际架构调用。代码或环境变化使既有故事证据失效时补跑，并保留旧记录。

**父卡最终验收另做四件事**：在合入全部子卡的父卡分支上跑**全量**（三段律里全量的法定位置之一），红的先定位归属，跨卡接缝缺陷由父卡负责；逐行核对 plan 行为闭环「触发者 → 载体 → 消费者 → 可观察结果 → 实现责任」在生产代码中成立，只有接口/空壳/测试替身而无生产调用方按未完成处理，不得靠全量绿放行；集成阶段新发现缺陷逐个记录（现象、根因、属于原承诺遗漏/假设错误/边界变化/新需求哪类）；**回旋镖对账**——把 plan 的预测（判据、影响面、耗时、「无风险」结论）与实测逐条对账，预测错误不是过失是校准数据，不对账才是。

验收中判定「退回某节点/留待下一期」的缺口逐条落 `docs/roadmap.md`；**原承诺的欠交、脱敏/隐私/安全红线不能只转 roadmap 或新修复卡就判通过**，须修复并重验，或请用户显式变更原承诺与风险接受范围。

| 念头 | 事实 |
|---|---|
| 「测试全绿，直接归档」 | 全绿只证明「写下的假设被满足」，不证明假设对。行为假设逐条真机。 |
| 「变异后行为一模一样，测试也不红」 | 先怀疑变异没打中，而不是先判「没人看着」。变异真生效则行为必变。 |
| 「真机麻烦，下次补」 | 事后补验 = 永不验。真机清单清空是归档的前置条件。 |

## 红线

- **审查是只读回合**：不 commit、不改文件、不建分支内容；合法产出只有裁决表与 findings。发现可顺手修的问题也只记 finding，修复归实现侧。
- **本节点不留台账文件**：只读回合没有写通道。跑过的命令与原始输出、看过但未成为 finding 的地方，一并写进裁决表随裁决回传。
- **禁止把「台账记录的 hash ≠ 当前 HEAD」写成 finding**：那是「同批提交 + amend」的必然结果；缺的是提交命令或原始输出才构成台账缺项。
- **待审的 diff/代码在工作树里找不到时，提问，不重做**：绝不按 plan 重新实现一遍再审自己写的。

## 收到审查反馈的一侧

- **先核验后实现**：反馈对照代码库现实检查——错了就用技术理由推回。
- **禁表演性认同**：「You're absolutely right」「说得好」不许出现，行动代替感谢。
- **一条不懂，全部暂停**：部分理解 = 错误实现；先澄清再动手。
- 审查建议「正规实现」某能力时先查有没有人用——没人用就提议删，不镀金。
