# Breakdown：拆解

**角色**：**跨子系统单 agent 出稿，协调者把关拍板。**拆解必须在一个上下文里跨所有触及子系统——接缝缺陷不属于任何单个子系统，分头拆解等于把唯一能看见接缝的视角拆掉。你的上下文是契约层 + 各子系统文档，不是全量代码。

**你的全部产出都是提案。**凡「有两种做法、选哪种取决于偏好」的岔口，把方案与取舍都写出来标注「待拍板」，不要自己选一个往下写。

## 执行形态（出稿者与拍板者必须是不同上下文，三种载体各自成立）

1. **本地（Claude Code 主会话）**：主会话**派 subagent 出稿**（注入本 skill 正文），主会话只拍板。两个理由：拍板者不被出稿者的自我合理化污染；拆解要吞契约层与各子系统文档，别烧主会话的上下文。
2. **handoff 派发**：executor 出稿（本文即纪律块），本地协调者拍板。
3. **单上下文兜底**（无 subagent 机制的执行者）：允许自己出稿，但**一切岔口一律「待拍板」、禁止自批**——出稿完成即停，把提案完整交还拍板者。**援引本条前先核实 subagent 机制确实不存在**；因某条约束降级的，降级声明必须逐字引用该约束的出处（文件+行，或用户原话），引不出即约束不存在，按形态 1 执行。

## 产出四样

1. **触及子系统清单**：每个子系统标类型——逻辑型（接缝对面是自有代码，测试可闭环）/ 边界型（接缝对面是外部现实，机内只验契约形状，行为验收写「真机清单，归协调者执行」）。子系统 id 与类型引用项目目标图（`domains` 数组承载的即子系统清单），有图以图为准；扇出前按架构法第一条的**派卡资格四条**逐个核。

2. **契约增量核对**：对照 contract 节点的冻结物逐条核对本次拆解是否越界；发现需要新接缝 → 退回 contract，不许边拆边加。核对时一并确认上游状态位（spec「已批准」、契约「已冻结」）已回写进各自文件头部——引用一份状态位失真的上游，等于把流程状态托付给会话记忆。核对中做出的**边界澄清**（某面属包内 API 不属契约面、某规则的归属判定），即便结论是「不退回 contract」，也要回写进契约文档留一行修订记录——澄清只活在拆解稿里，review 的冻结物触碰行就对不上账。

3. **子卡清单 + 依赖 DAG**：每张子卡四段式——
   ①契约引用 ②意图与为什么（不写实现步骤）③验收（按子系统类型分流；判据必须**行为化、独立可验**——「跑 X 命令返回 Y」而非「功能应正常」）④入口指针（相关文件路径）。
   每张子卡必须能圈出**有界文件集**；圈不出 → 先插竖切还债卡（架构法第三条），再派功能卡。

4. **缺陷族对抗审查**：按 `defect-families` 逐族正面回答，结论写进对应子卡验收栏。**不许一句「无风险」带过；无风险的写「无，因为……」**——协调者判的是审查够不够、漏没漏族，一句话结论没法判。

## 机内验不了的东西

凡结论依赖**行为事实**（某事件走不走某条通路、某字段实际由谁写入）而非可 grep 的 API 事实，必须显式标注「未验证，需真机」并写进真机清单，不许按推测写成结论——夹具可以编码一个不存在的世界，测试会全绿地验证它。

## 交稿自检（出稿者收尾逐项核对，缺一即稿未完成）

1. 产出四样齐全：子系统清单每个带类型、契约增量核对有逐条结论、子卡全部四段式且判据行为化、缺陷族逐族有答案（含「无，因为……」）；
2. **「待拍板」岔口集中列成清单放稿首**——拍板者按这张清单裁决，散落在正文里的岔口等于没标；
3. 「未验证，需真机」条目已汇总成真机清单；
4. 每张子卡的有界文件集核过——圈不出的已插竖切卡，不是硬塞进功能卡。

## 拍板即提交

协调者拍板后，拆解稿连同裁决结果随即提交入库——与 contract 的「冻结即提交」同款。产物不入库，会话一断就是孤儿（实测：一轮拆解稿以未跟踪文件形态死在工作区，`assignments` 为空，一张卡没派出去）。

## 红线

不写实现代码；不建卡、不派发、不调派发工具——扇出归协调者。

**符号锚**：项目有代码图时，文档引用现状代码推荐 `file#Symbol` 符号锚（行号会漂，符号锚配 `handoff graph resolve` 查询时决议）；出稿自检跑 `handoff graph resolve --doc <本文档>`，坏锚即修。
