# Triage：定级与路由

**角色**：协调者（或定性节点的执行者）。产出是一个定级结论 + 路由决定，不是任何实现。

## 定级两问

1. **触及几个域？**（按项目目标图/实例化清单的域划分数；没有的项目按顶层模块数）
2. **动不动契约层？**（域的导出面 / 接口 / 共享数据结构 / wire 格式）

| 答案 | 级 | 路由 |
|---|---|---|
| 1 个域，不动契约，根因明确 | **L1** | plan → implement → review → acceptance → finish |
| 1 个域，需要设计或动本域契约 | **L2** | spec → plan → … |
| ≥2 个域，或动跨域契约 | **L3** | spec → contract → breakdown → （选档） |

回答两问需要读码或读图——那是本节点内的工作，做完才许定级。**拿不准时定低一级**：升级的纠错通道（跨流迁移）是设计好的，降级浪费的是已付出的流程成本。

## L3 选档：扇不扇出

**判据一条：单域工作量是否超过流程固定成本（实测约 70 分钟）。**

- 超过 → **重档**：各域并行子卡 + 集成。
- 不超过 → **轻档**：拆解与契约冻结照做，实现归**一轮**。

「规模适中」是轻档的信号，不是重档的——多域但每域改动浅的需求，扇出的并行收益救不回固定成本（实测：可并行部分 20 分钟，固定成本 70 分钟）。**轻档不许跳契约冻结**：试点数据表明价值在契约那半段，不在扇出。

## 判错了怎么办

定级允许错。纠错动作是**跨流迁移**（显式指定目标流与落点列，事件留痕），不是重建卡——重建丢事件流与关系边，审计链断裂。发现判错的时刻通常在 spec 或 breakdown：跨域性藏不过拆解。

## 红旗

| 念头 | 事实 |
|---|---|
| 「先干起来，级别边做边看」 | 边做边看 = 用 L1 的流程干 L3 的活，接缝缺陷没有任何节点负责。 |
| 「这个需求不大，直接重档扇出练练」 | 扇出是成本不是姿态。判据只有工作量一条。 |
