# Implement：实现

## 测试纪律

测试只有两层，**先红后绿**：

1. **故事级检查**：每条必交故事一条检查，从真实入口到可观察结果，在项目的测试环境里跑（后端经接口、前端经自动化脚本）。它是验收的主证据：写在 plan 验收方式里、implement 跑、review 复跑。环境的起/跑/收命令须存在且可由 agent 跑；没有环境时检查项逐条进 plan 真机清单。
2. **不变式单测**：只为承重规则与不变式写（状态机、金额/时间计算、权限判定、序列化边界）。**不为文件、不为层、不为映射写测试**；与实现 1:1 的测试是删除对象。断言现状读数的测试（固定个数、固定清单、文案或样式原样）同属删除对象：要守登记完整，就断言「源头的每一项都登记了」，不断言个数。期望值出自 spec 的故事或规则，不出自实现当前的行为。

**只测当前组件。**邻居靠既有测试与 review 真机兜底。没有可测的真实路径先说明障碍并设计验证，不造假缝。日志、注释、纯映射不开红绿周期。

- **看到红才算测试存在**：确认失败是功能缺失而非 typo。新建缝符号首红可为编译红，空壳落地后必须再见断言红；既有缝的红必须直接是断言红。
- 绿灯只写最小代码（YAGNI），重构不加行为。
- 测试有牙否由 review 变异复验，实现侧不自验。
- **集成分支的全量判定只有全绿与红**：不与已知红名单对照；现存的红修好，或显式删除并落 roadmap，不得作「已知抖动」跳过。抖动或既有红给一个排查轮：定出根因就修；定不出就删掉该用例并落 roadmap，写明它守的行为。不加等待、不放宽超时、不靠重跑让它过。
- **清单以骨架为准**（有骨架的卡）：只填骨架测试清单内的测试；**清单外须披露**——新增测试文件进「偏离与自主决定」，写明拦的是哪个实现中发现的真实缺陷，由 review 裁决；bug 流的复现测试不受此限。对应故事检查转绿后**按删除清单删**旧测试（认搬迁提交里的待删标记，删完标记为零），没有故事覆盖的保留。

**骨架边界（有骨架的卡，含全部 L2）**：只在骨架留的位置填业务，沿 spec 声明的职责、权威状态与允许依赖做到用户可观察结果；不得新增跨泳道穿透、临时协调对象、硬编码成功或测试专用入口；**不得使超线容器净增**（`architecture-law` 第十四条），骨架没给落点时停下回 plan；发现骨架错了停下回 plan 改骨架，不就地绕；探索证伪目标边界时停下修订 spec。L2 没有计划文档：本文「plan 的决策权限、真机清单」指 spec 末尾「实施备注」，「plan 验收方式」指骨架测试清单。

## 真机前移

首条故事级检查绿即按 plan 真机清单的**首跑项**真机一次，不等 review；环境、操作、观察、时间戳写进交回物。

## 测试三段律

**编译全量、测试局部、全量归集成分支。**task 内只跑**触及包**测试；每个 task 收尾全量**编译/类型检查** + 触及子系统测试；全量测试**只在集成分支上按提交跑**，卡与父卡都不跑，跨包破坏由编译与契约闸兜底。

**契约闸**：项目把跨包的登记与方向检查（接口登记与分类、能力表、迁移清单、依赖方向）归成一条秒级命令，每张卡收尾必跑，与全量编译、结构检查同权重。没有这条命令时，改到契约面的卡把这些检查所在的包列进触及包。

## 日志与注释

- 关键节点必打：入口带输入、外部调用前后、**每条错误分支带上下文与原因**、成功路径不静默。
- 结构化 logger，禁 print / fmt.Printf / console.log。
- 新文件头写职责 + 边界；导出函数写参数/返回/注意事项；非显然逻辑写「为什么」，与代码重复的注释删。

## 修复熔断

**同一问题 3 次修复失败 = 架构问题，禁止第 4 次**——停下，写清三次各改了什么、怎么失败，上报协调者。

## 排查

**无根因调查不许提修复。**排查可派快执行者跑轮次；根因后**分流归协调者**。

- **第 0 步：钉死被验对象身份**——哪个二进制、分支、提交、进程；版本戳、构建缓存、worktree 会说谎，没钉死前观察不可归因。
- **第 1 步：建红色反馈回路**（排查的全部，其余是机械）：一条命令同时满足①对这个 bug 变红②确定性（偶发红先二分成必现）③快（秒到分钟级）④agent 可跑不依赖人眼，才算有回路；没有它不许进假设阶段。
- **第 2 步：边界取证**（多组件系统）：每个组件边界加统一前缀诊断日志（如 `[DEBUG-xxxx]`），完整跑一遍先定位断在哪层再进那层查；没取证的层不凭感觉翻代码。
- **第 3 步：假设纪律**：列 3~5 个可证伪假设并排序（只有一个 = 锚定第一直觉）；一次实验只改一个变量；归属看失败原文，「不是我干的」≠「没有 bug」。
- **常见形状**：偶发红多是判据取了中途副产物；环境假红有固定形状（root 下负向权限断言、路径长度上限、HOME 不可写），认不出就在环境内外对跑同一命令；测试全绿但功能不生效 = 夹具编码错误假设，转真机。
- **出口**：修复必须先有复现该 bug 的失败测试；没有能写回归测试的接缝即是发现，按架构债立卡。根因后分流：小修顺手修；改职责、权威状态或依赖方向回 spec；命中新共同依赖接缝或对外承诺进 plan 冻结节；不在排查现场动架构。收尾清净诊断日志，根因、证据、分流落卡。

## 结论纪律

- **交回物纪律**（网关有同文）：第一节固定为「偏离与自主决定」：①与已批准 plan/spec 不一致处；②自行拍板内容与理由；③是否在 plan「决策权限」授权内。无偏离写「无」，不得省略；未进该节的偏离视同未披露。读数与证据**随卡走**，无随卡存储才进仓（只留指针与一行读数）。
- **完工触发一次独立运行**（项目有按提交号可查、非执行者自述的运行记录时）：对交付提交跑触及包 + 契约闸 + 本卡故事检查（不是全量）；交回物只引记录指针（在哪、哪个提交），不抄输出；修复轮改了代码就重新触发，旧记录作废。
- **没跑到结果不许写结论**：没跑写「预计通过」、失败绕过去都算谎报；跑不了如实记「未验证」与原因；宁可交一个诚实的未验证，不交一个编造的绿。

## 收尾自审
