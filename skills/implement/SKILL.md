# Implement：实现

## 测试纪律

测试只为两类对象写，**先红后绿**：

- **竖切**：承诺的故事从真实入口到可观察结果的一条路径，优先经生产接缝或真实消费入口断言；
- **核心方法**：承重规则与不变式（状态机、金额/时间计算、权限判定、序列化边界）。

**只测当前组件。**邻居靠既有测试与 review 真机兜底。没有可测的真实路径先说明障碍并设计验证，不造假缝。日志、注释、纯映射不开红绿周期，纯映射须被行为或 roundtrip 断言覆盖。

- **看到红才算测试存在**：确认失败是功能缺失而非 typo。新建缝符号首红可为编译红，空壳落地后必须再见断言红；既有缝的红必须直接是断言红。
- 绿灯只写最小代码（YAGNI），重构不加行为。
- 测试有牙否由 review 变异复验，实现侧不自验。

**首故事（L3）边界**：沿 spec 声明的职责、权威状态、允许依赖和组装点，从真实产品入口做到用户可观察结果；只建所选故事的路径，不得新增跨子系统穿透、临时万能协调对象、硬编码成功或测试专用入口；探索证伪目标边界时停下修订 spec；过审代码才作后续子卡基线。

## 真机前移

首条竖切跑通即按 plan 真机清单的**首跑项**真机一次，不等 review；环境、操作、观察、时间戳写进交回物。

## 测试三段律

**编译全量、测试局部、集成全量。**task 内只跑**触及包**测试；每个 task 收尾全量**编译/类型检查** + 触及子系统测试；全量测试**只在 review（父卡最终验收）与 finish**，跨包破坏由编译与契约闸兜底。

## 日志与注释

- 关键节点必打：入口带输入、外部调用前后、**每条错误分支带上下文与原因**、成功路径不静默。
- 结构化 logger，禁 print / fmt.Printf / console.log。
- 新文件头写职责 + 边界；导出函数写参数/返回/注意事项；非显然逻辑写「为什么」，与代码重复的注释删。

## 修复熔断

**同一问题 3 次修复失败 = 架构问题，禁止第 4 次**——停下，写清三次各改了什么、怎么失败，上报协调者。

## 排查

**无根因调查不许提修复。**排查可派快执行者跑轮次；根因后**分流归协调者**。

- **第 0 步：钉死被验对象身份**——哪个二进制、分支、提交、进程；版本戳、构建缓存、worktree 会说谎，没钉死前观察不可归因。
- **第 1 步：建红色反馈回路**（排查的全部，其余是机械）：一条命令同时满足①对这个 bug 变红②确定性（偶发红先二分成必现）③快（秒到分钟级）④agent 可跑不依赖人眼，才算有回路；没有它不许进假设阶段。
- **第 2 步：边界取证**（多组件系统）：每个组件边界加统一前缀诊断日志（如 `[DEBUG-xxxx]`），完整跑一遍先定位断在哪层再进那层查；没取证的层不凭感觉翻代码。
- **第 3 步：假设纪律**：列 3~5 个可证伪假设并排序（只有一个 = 锚定第一直觉）；一次实验只改一个变量；归属看失败原文，「不是我干的」≠「没有 bug」。
- **常见形状**：偶发红多是判据取了中途副产物；环境假红有固定形状（root 下负向权限断言、路径长度上限、HOME 不可写），认不出就在环境内外对跑同一命令；测试全绿但功能不生效 = 夹具编码错误假设，转真机。
- **出口**：修复必须先有复现该 bug 的失败测试；没有能写回归测试的接缝即是发现，按架构债立卡。根因后分流：小修顺手修；改职责、权威状态或依赖方向回 spec；命中新共同依赖接缝或对外承诺进 plan 冻结节；不在排查现场动架构。收尾清净诊断日志，根因、证据、分流落卡。

## 结论纪律

- **交回物纪律见网关**；第一节固定为「偏离与自主决定」：①与已批准 plan/spec 不一致处；②自行拍板内容与理由；③是否在 plan「决策权限」授权内。无偏离写「无」，不得省略；未进该节的偏离视同未披露。末节「读数与证据」。
- **没跑到结果不许写结论**：没跑写「预计通过」、失败绕过去都算谎报；跑不了如实记「未验证」与原因；宁可交一个诚实的未验证，不交一个编造的绿。

## 收尾自审

日志注释齐（错误分支带上下文、成功路径有出口、文件头与导出函数注释）？触及包测试绿、全量编译过？首跑项真机已跑？故事、契约、架构边界一致，未冻结调整有理由与验证？交回物首节对照了决策权限，无偏离写「无」？
