# Implement：实现

## TDD 铁律

- **无失败测试不写生产代码。**先写了代码？删掉重来，不许「留作参考」「边改边测」。
- **看到测试红才算测试存在。**必须确认失败原因是「功能缺失」而非 typo；立即通过的测试证明不了任何事。**新建缝符号的首红允许是编译红**（`undefined`，先核实不是拼写错），但空壳落地后必须再见一次断言红才进入实现——编译红证明符号缺席，不证明断言有牙；既有缝上的红必须直接是断言失败红。
- 绿灯只写最小代码（YAGNI）；重构不加行为。
- **铁律的对象是已声明接缝上的行为断言**（spec 接缝清单 / plan 接缝覆盖闸）。日志、注释、直通镜像、纯映射不构成独立红绿周期——但纯映射必须被缝上断言或 roundtrip 断言覆盖（缺陷族·序列化边界条）：豁免红绿仪式，不豁免被覆盖。内部复杂逻辑从已声明缝够不着时，接 debug 的无缝条款——立架构债，不造假缝、不硬塞内部测试。

## 测试三段律

**编译全量、测试局部、集成全量。**

- task 内循环：只跑**触及包**的测试（plan 里已声明范围）。
- 每个 task 收尾：全量**编译/类型检查**（最便宜的全仓检查）+ 触及子系统的测试。
- 全量测试**只出现在集成与收尾节点**——它不是被省略，是被移位到唯一有意义的位置。跨包破坏由编译与契约闸兜底，漏网的由集成全量抓。

## 变异自验：确认测试真的有牙

改完之后做变异，是为了回答「测试拦不拦得住我」。这件事有两种失败方式，两次都会让你
得到一个长得像结论的假读数——**两次都必须先排除，再解释读数**。

**① 变异必须编译得过。**删掉一行代码常常连带让 import 或局部变量变成「未使用」，
在 Go / Rust / TS(noUnusedLocals) 这类语言里直接是编译错误。此时测试一支都没跑，
`grep -c "^--- FAIL"` 得到的是 **0**——它和「变异存活 = 测试是摆设」长得一模一样。
所以变异脚本必须**两段判定**：先确认编译通过（`go build ./...`，或检查输出里没有
`build failed` / `cannot` / `undefined`），再数失败数。编译不过的那一发**不算数**，
必须整块替换成可编译的等价变异后重做。

配套手法：**变异要改语义，不要改「有没有用到」**。优先取反、改边界值、改比较符，
而不是整行删除——删除天然容易牵连 import 与变量声明。

**② 变异必须打中唯一。**同一段文本在文件里出现两次时，`replace(old, new, 1)` 打中的
是第一处，而你要测的守卫可能在第二处。这一种比 ① 隐蔽得多：**编译通过、测试真的跑了、
报 0 红**，从任何输出上都看不出异常。所以变异前必须**断言命中唯一**（`count(old) == 1`），
命中多处就要求更长的上下文锚。

变异后**先做一次行为断言**（哪怕只跑一条最相关的用例，确认它变红或变绿），确认这一发
真的改变了行为，再去数全量失败数。

**「变异后一切如常」永远先怀疑变异没生效，而不是先下「测试是摆设」的结论。**
如果变异真的生效，行为必须变；行为没变说明没打中，不说明没人看着。

## 日志与注释（交付的一部分）

- 关键节点必打：入口带输入、外部调用前后、**每条错误分支带上下文与原因**、成功路径不静默（静默成功是「靠猜排障」的头号成因）。
- 结构化 logger，禁 print / fmt.Printf / console.log。
- 新文件头：职责 + 边界；导出函数：参数/返回/注意事项；非显然逻辑：写「为什么」不写「做了什么」——与代码重复的注释删掉。

## 修复熔断

**同一问题 3 次修复失败 = 架构问题。禁止第 4 次尝试**——停下，写清三次各改了什么、各怎么失败的，上报协调者。继续硬试烧的是轮次，掩的是结构性根因。

## 结论纪律

- **边干边落台账**：每确立一个事实就往台账文件追加一行——提交、跑过的命令与原始输出、放弃的尝试、做出的判断。不要攒到回合结束再写：回合可能不会有结束。台账是仓内文件，与本节点产出物同批提交；落点随项目约定，无约定时与产出物同目录。

**没跑到结果不许写结论。**测试没跑就写「预计通过」、命令失败就绕过去——都算谎报。跑不了就如实记「未验证」与原因。宁可交一个诚实的未验证，不交一个编造的绿。

## 收尾自审

- 每条错误分支有带上下文的日志？成功路径有出口日志？
- 新文件有头注释、导出函数有文档注释？
- 触及包测试绿、全量编译过？
- 与 plan 的 Interfaces 签名一致？
