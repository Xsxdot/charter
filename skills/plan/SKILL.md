# Plan：实现计划

**读者假设**：执行者对本任务零上下文。计划要让他找到输入、知道下一步和完成标准，保留边界内的实现判断。

**归属**：Wave 0、L3 轻档、L2 与 bug 流由协调者写交接；L3 重档子卡由有界工作单元执行者依 spec、breakdown 与适用的既有/新冻结契约自写，协调者审目标、边界和验收责任。没有命中 contract 时，不得要求一份不存在的冻结物。

## 事实定位

**有图先查图**：项目有 `codegraph/` 时先查图，未命中再 grep，未命中符号记「图覆盖债」。
  - 领域从哪下手 → `codegraph context <领域>`（`<领域>` 必须是 best 领域 id；现状 id 会被拒并报它在最优树里的分布——分布非单值，不代为改写。无 best 时降级为现状词表并在错误里注明。声明缺失不是错误，仍返回机械字段并以 warning 指向声明路径。响应 `actual` 披露实然归属与 `misplaced`/`misplacedSkipped`，应然≠实然。截断看 `truncated` / `fociTruncated`。）
  - 已经有名字 → `codegraph sym`
  - 这个方法怎么走 → `codegraph flow`（有序控制流：`call`/`branch`/`loop`/`return`。无数据则 `degraded` 且 `steps` 空，然后读源码。**禁止拿 `chain` 冒充。** 参数是方法名或节点 id，不带 `--with-source`；源码窗口用 `sym` / `chain --with-source`。）
  - 沿哪条路径下去 / 上来 → `codegraph tree` / `tree --up --through --from`（真树；菱形按路径重复。`--from` 必须搭配 `--through`。）
  - 碰过谁（切片）→ `codegraph chain` / `who-calls`（无次序、无分支。默认瘦身、外部领域折叠、共享内核收桩；旧形态显式 `--full`，`--full` 不关闭源码窗口或预算。）

**调用链 ≠ 流程图。** `chain` / `context` 的主链是无序可达邻域。`flow` 的主语是对外契约方法（入缝 / 紫框目标 / 右栏实现），不是 CLI/HTTP/WS 通道。通道只说明怎么到达该主语；不要对 `GET /console` 这类通道跑 `flow`，先 `sym` / `who-calls` 找到它调进去的方法。

## 交接只需回答五件事

| 内容 | 必须明确 |
|---|---|
| 交付目标 | 本轮对应哪些已批准故事/步骤，做到哪里，哪些留待后续批次 |
| 改动边界 | 有界模块或文件集、真实代码入口、须遵守的架构方向与已有/冻结契约版本 |
| 工作顺序 | 先验证哪个承重假设，再产生什么可检查结果；只细化下一段可验证工作 |
| 验收方式 | 成功与关键反例的断言、测试/运行入口、真机环境及需保存的证据；有原型时给具体版本与状态 |
| 决策权限 | 执行者可自行调整什么，何种用户结果、权威状态、外部兼容面或共享接缝变化须升级 |

重档父卡的 Wave 0 plan 头部标明阶段、选定故事与 spec 修订号；review/acceptance 引用执行时的计划版本。Wave 0 验收后，协调者在**同一 plan 的交棒区追加**已验故事及提交/证据、下一去向、下一批工作单元的责任草案、共同依赖的接缝与仍待验证项。草案不是子卡 DAG；是否进 contract 由新增冻结对象判据决定。追加记录不覆盖原计划和已引用版本；最终验收由 integrate 交棒标明阶段、故事全集与下一去向。

不要求预写完整代码块、逐 task 复制精确签名或统一拆成 2～5 分钟动作。已冻结的面引用源码符号与提交/协议版本，由编译和契约断言核对；无冻结对象的内部实现可在本工作单元内演化。详细代码仅在已明确的协议、不可逆迁移或关键算法确有预定价值时写，并说明理由。

**无占位符指向交付承诺。**「适当处理错误」「之后再验」不合格；「此行为待实验，先运行 X，失败阻塞 Y 并回到 Z」是合法交接。局部私有函数、算法和实现顺序的可逆选择不必请用户逐项拍板。

## 事实、风险与测试

1. **判据先核事实**：计划引用的现状、依赖版本、既有公开契约、命令和可运行环境，能在基线查的先查；未能查证的标为假设并给验证动作，不写成已证实。绿地项目的外部库行为带源码出处或最小验证。项目有图时先查图，未命中再读真代码。

   **判据要钉住行为，不钉住计数。**写下一条计数型判据（「文件数 41→50」「覆盖率 ≥80%」
   「新增 ≥N 行」）之前先自问：**满足它的最省力方式是什么，那个方式达成目标了吗。**
   实测反例：判据写「cmd/ 图内文件数 41→50」，执行者补了 40 个**零边**节点，文件数精确
   达标，而 who-calls / chain 查这些命令依然一无所获——判据要代理的是「命令进图可查」，
   它钉住的却是「文件名出现过」。计数是可数的、可满足的，且与目标往往只有相关性没有因果性。

   **跨仓判据落笔前，先确认目标仓钉的依赖版本里真有这个能力。**尤其是自己刚在上游加、
   尚未发版的东西，最容易想当然。实测反例：判据写「anchor-off-\* warn = 14」，而目标仓
   钉的依赖版本里根本没有这个类型，执行者查证后如实标「未验证」——处置正确，错在判据。
2. **风险对应断言**：对本轮故事写成功与关键反例；按 `defect-families` 识别真正相关的风险，写入对应验收责任，不机械遍历全产品。边界型子系统的实际行为写真机清单，局部 mock 不能顶替。
3. **序列化边界**：新增字段经过手写投影、编码或跨语言转换时，至少有一条断言穿过真实转换链，区分字段缺失与零值；两端各自单测不能代替链路证据。
4. **测试范围**：task 内测试聚焦触及范围，编译与集成全量位置沿用 implement/integrate 的三段律。允许复杂内部规则补充单测；内部测试不能顶替用户故事或生产接缝的验收。日志与注释沿用 implement 的通用纪律，plan 只写本任务特有观测点。

Wave 0 整个阶段的完成条件是从真实产品入口走到用户可见结果，沿 spec 声明的子系统职责、权威状态和依赖方向实现；计划说明如何核对触及路径的物理边界。第一段可先验证承重假设，但后续仍须闭合选定故事；探索失败可以重做，演示用的越界捷径不能作为已验共同基线。

## 跨卡审计（L3 重档，扇出前法定步骤）

各子卡 plan 齐稿后、派发前，plan 集合过一次**独立上下文**的跨卡审计——本地可派 subagent，单上下文兜底时结论标「待拍板」交协调者；出稿者不得自批。审三样，都是单看任何一份 plan 看不见的：

1. **共同边界**：每份 plan 引用的适用契约符号/版本与真实生产者、消费者一致；没有新增冻结对象时查 spec 架构边界与既有契约，不发明空清单。编译与契约断言核对类型兼容，不在各 plan 里复制签名逐字符比对。
2. **依赖与验收**：跨卡共享接缝在派发前已按 contract 判据处理，依赖顺序可执行，故事步骤有集成与演示负责人。
3. **全部承诺归属**：待实现故事映射到工程卡和最终父卡验收；Wave 0 已交付故事指向已验父卡基线与最终回归责任，不造重复子卡。共享基础设施卡说明服务于哪条承诺，不因子卡技术通过就宣布故事完成。

## 派发前自审

计划里凡有需要**驱动派发系统自身**的验收步骤，标注「本 task 由协调者执行，不派发」——它与执行者纪律的「不派发、不调派发 CLI」直接冲突，派出去等于没验。

## 红线

- **边干边落台账**：每确立一个事实就往台账文件追加一行——提交、跑过的命令与原始输出、放弃的尝试、做出的判断。不要攒到回合结束再写：回合可能不会有结束。台账是仓内文件，与本节点产出物同批提交；落点随项目约定，无约定时与产出物同目录。**提交事实的记法**：把提交当时的命令与原始输出追加进台账（历史读数），随后只 amend 一次收进同批提交。amend 会换 hash——这是 git 的事实，不是漏记。禁止把 amend 后的 HEAD 写回台账再 chase；收口判据是工作树干净，不是文件里的 hash 等于 HEAD。

- **本节点的产出物是计划文档，不是实现代码**：不写实现、不建脚手架、不「顺手把活干了」。同场 prompt 里出现实现级验收判据（真机清单、「没跑到结果不许写 pass」）时，那是 implement 节点的完成标准——plan 节点的完成标准只有一条：计划落盘且自检通过。两者冲突时以本条为准，不以判据为由越节点。
- **依赖的输入（spec、契约文档等）缺失或读不到时，提问，不自造**：远程执行发工单问协调者，本地执行问用户；绝不自写一份替代、不凭记忆补设内容——自写的输入会让后续所有节点建立在虚构之上。

## 自审三查

故事/步骤覆盖；待验证假设有动作与阻塞范围；共同边界和最终验收责任一致。
