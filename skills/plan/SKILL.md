# Plan：实现计划

执行者零上下文：计划让他找到输入、知道下一步与完成标准，保留边界内判断。L2 与 bug 流协调者写；L3 子卡 plan 由子卡执行者自写，协调者审目标、边界、验收责任。

## 五件事

| 内容 | 必须明确 |
|---|---|
| 交付目标 | 对应哪些已批准故事/步骤，做到哪里 |
| 改动边界 | 有界模块或文件集、真实代码入口、架构方向与已有/冻结契约版本 |
| 工作顺序 | 先验证哪个承重假设、再产生什么可检查结果；只细化下一段可验证工作 |
| 验收方式 | 成功与关键反例的断言、测试/运行入口、真机环境与须存证据、原型版本；**每条必交故事一条故事级检查**（真实入口 → 可观察结果，在项目测试环境跑；无环境时逐条进真机清单）；真机清单标一条**首跑项** |
| 决策权限 | 执行者可自行调整什么，何种用户结果、权威状态、外部兼容面或共享接缝变化须升级。这一节是交回物「偏离与自主决定」的对照基准：执行者的每条自行拍板都要对着它说明是否越权，review 第一步按它核对 |

不预写完整代码、不复制签名、不拆分钟级动作；冻结的面引用源码符号与版本，由编译和契约断言核对；详细代码仅在协议、不可逆迁移或关键算法有预定价值时写。**无占位符**：「适当处理错误」「之后再验」不合格，「先跑 X，失败阻塞 Y 回 Z」合法。局部私有函数、算法与实现顺序的可逆选择不必请用户逐项拍板。

## 事实与风险

1. **判据先核事实，钉行为不钉计数**：能查的先查，查不到的标假设给验证动作。计数型判据先问最省力的满足方式是否达成目标；跨仓判据先确认目标仓钉的依赖版本真有该能力。
2. **风险对应断言**：写成功与关键反例，只写真正相关的风险。边界型子系统的行为写**真机清单**，mock 不能顶替；清单标一条**首跑项**，implement 首条故事级检查绿即跑。新增字段经手写投影/编码/跨语言转换时至少一条断言穿过真实转换链、区分缺失与零值。

## L3：拆分与接缝

**出稿者与拍板者必须是不同上下文**：本地主会话派 subagent 出稿、主会话只拍板；派发执行器出稿时协调者拍板；单上下文兜底可自己出稿，但岔口一律标「待拍板」、禁止自批，援引前先核实 subagent 机制不存在。**一切产出都是提案**，待拍板岔口集中稿首。

拆解在一个上下文跨全部触及子系统：

1. **触及子系统清单**：逻辑型（对面是自有代码，可闭环测试）/ 边界型（对面是外部现实，机内只验契约形状，行为靠真机）。派子卡前核资格（有界文件集、契约面可枚举、依赖可排 DAG、有类型标注；`architecture-law` 第一条），不满足按文件改。
2. **工作单元与依赖**：单轮能交付的写一个有界工作单元及顺序，不强造子卡。依赖注明是**硬依赖**（前卡产物是后卡前提）还是**施工排序**（资源冲突），后者不得冒充架构依赖。批次按依赖图定：硬依赖串、无依赖并；无真实消费者的接口不单独派卡；圈不出有界文件集先插竖切还债卡。
3. **骨架先行**：骨架 `--no-ff` 合入集成分支的提交即全部子卡共同基线；子卡之间只按依赖图等待。

结论依赖**行为事实**而非可 grep 事实时，标「未验证，需真机」入真机清单，不按推测写结论。

**拍板即回写**：裁决逐岔口回写稿首，状态行改「已拍板（日期）」，同批提交；不一致视同未拍板。

## 层表、骨架与楼层图

L3 的 plan 必产出三件；L2 在 spec 头部点名「出骨架」时同样产出（单泳道）。拍板者只审楼层图：

1. **层表**：每个触及子系统列出层（泳道 = 子系统，楼层 = 层，边缘层是契约面所在层）、每层职责一句话、允许的依赖方向。
2. **可编译骨架**：类型、接口签名、接线（组装点）齐全，**不写业务逻辑**；每个 stub 方法只做两件事——打一行结构化 flow 日志（谁在哪层调了谁，可带「用户看到」）、返回零值或固定值；**每个 stub 方法头一行注释写「做什么」**。骨架必须编译过、能按故事跑通一遍产生日志。
3. **楼层图**：四要素——泳道、楼层、actor、调用。**结构从骨架 diff 的静态调用图抽取**，日志只提供调用顺序与「用户看到」标注；手画也合法。

五项自动判据，命中即标、裁决归人：空层（层表声明的层在该泳道无任何 actor）；上帝对象嫌疑（单 actor 承担该泳道 ≥ 60% 的步骤、步骤 ≥ 5、且跨 > 1 层）；跳层（一条调用跨过 ≥ 2 个非边缘层）；越过契约面（跨泳道调用不从本泳道边缘层出发或不落在对方边缘层）；过度设计嫌疑（≥ 4 个非边缘、非 ui 的 actor 各只承担 1 步）。

人审两件事：产品逻辑与流程对不对（按故事走图）；分层与架构对不对（对照 `architecture-law` 第十三条）。

## 契约面冻结 = 骨架

**入口判据**：只有本轮新增/变更的跨子系统契约面被独立工作单元共同依赖，或构成新的对外兼容承诺（跨仓、跨进程 wire），才有冻结对象；已有契约引用版本即可；工作单元内可逆的内部方法不入。无冻结对象写一行「无新增冻结对象 + 复用契约及版本」。

**冻结物是骨架里跨子系统契约面的类型与接口签名，由编译核对**，不另列文本条目。仍需文字的只有两类：对外 wire 承诺（跨仓/跨进程）与拍板记录。

- **查证**：依赖库既成行为也是契约，读源码钉死带出处；对侧每个常量查谁真发出、谁真消费，零使用标「疑似漂移」；能算金样本的写测试，跨仓 wire 消费方出用例、提供方回放。
- **拍板记录三重闸门**：难逆转、无上下文会惊讶、真取舍同时满足才记，含被否方案；尤其记「反着写也没测试变红」的决定。
- **冻结即提交**；变更已冻结契约面 = 改骨架 + 重走本节审核。骨架只建可编译接口/类型/接线，不写业务行为、不硬编码成功。

## 红线

- **读数与证据进本文件末节**，裁决与结论回写正文。
- **产出物是计划文档与骨架**：骨架是唯一允许的代码产出，不写业务逻辑、不顺手干活；完成标准只有计划与骨架落盘且自检通过。
- **输入（spec 等）缺失时提问，不自造**：远程发工单问协调者，本地问用户。

## 自审

故事/步骤覆盖；待验证假设有动作与阻塞范围；决策权限写清；真机清单有首跑项。L3 另核：待拍板在稿首、依赖分清硬依赖与施工排序、骨架编译过且楼层图五判据已标、冻结节有结论。
