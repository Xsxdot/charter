# Plan：实现计划

**读者假设**：执行者对本任务零上下文。计划要让他找到输入、知道下一步和完成标准，保留边界内的实现判断。L2 与 bug 流由协调者写；L3 扇出时子卡的 plan 由子卡执行者依父卡 plan 自写，协调者审目标、边界和验收责任。

## 交接只需回答五件事

| 内容 | 必须明确 |
|---|---|
| 交付目标 | 本轮对应哪些已批准故事/步骤，做到哪里，哪些留待后续 |
| 改动边界 | 有界模块或文件集、真实代码入口、须遵守的架构方向与已有/冻结契约版本 |
| 工作顺序 | 先验证哪个承重假设，再产生什么可检查结果；只细化下一段可验证工作 |
| 验收方式 | 成功与关键反例的断言、测试/运行入口、真机环境及需保存的证据；有原型时给具体版本与状态 |
| 决策权限 | 执行者可自行调整什么，何种用户结果、权威状态、外部兼容面或共享接缝变化须升级。这一节是交回物「偏离与自主决定」的对照基准：执行者的每条自行拍板都要对着它说明是否越权，review 第一步按它核对 |

不要求预写完整代码块、逐 task 复制精确签名或拆成 2～5 分钟动作。已冻结的面引用源码符号与提交/协议版本，由编译和契约断言核对；无冻结对象的内部实现可在本工作单元内演化。详细代码仅在已明确的协议、不可逆迁移或关键算法确有预定价值时写，并说明理由。

**无占位符指向交付承诺。**「适当处理错误」「之后再验」不合格；「此行为待实验，先运行 X，失败阻塞 Y 并回到 Z」是合法交接。局部私有函数、算法和实现顺序的可逆选择不必请用户逐项拍板。

## 事实、风险与测试

1. **判据先核事实**：计划引用的现状、依赖版本、既有公开契约、命令和可运行环境，能在基线查的先查；未能查证的标为假设并给验证动作，不写成已证实。**判据要钉住行为，不钉住计数**：写下计数型判据（「文件数 41→50」「覆盖率 ≥80%」）前先自问满足它的最省力方式是什么、那个方式达成目标了吗。**跨仓判据落笔前，先确认目标仓钉的依赖版本里真有这个能力**，尤其是自己刚在上游加、尚未发版的东西。
2. **风险对应断言**：对本轮故事写成功与关键反例；按 `defect-families` 识别真正相关的风险写入验收责任，不机械遍历全产品。边界型子系统的实际行为写真机清单，局部 mock 不能顶替。
3. **序列化边界**：新增字段经过手写投影、编码或跨语言转换时，至少有一条断言穿过真实转换链，区分字段缺失与零值；两端各自单测不能代替链路证据。
4. **测试范围**：task 内测试聚焦触及范围，全量位置沿用 implement 的三段律；日志与注释沿用 implement 通用纪律，plan 只写本任务特有观测点。

## L3 增段：拆分与接缝

**出稿者与拍板者必须是不同上下文**：本地主会话派 subagent 出稿（注入本 skill 正文），主会话只拍板——拍板者不被出稿者的自我合理化污染，拆解吞各子系统文档也不该烧主会话上下文；handoff 派发时 executor 出稿、本地协调者拍板；单上下文兜底允许自己出稿，但一切岔口标「待拍板」、禁止自批，援引本条前先核实 subagent 机制确实不存在。**一切产出都是提案**，「待拍板」岔口集中列在稿首。

拆解在一个上下文里跨全部触及子系统（接缝缺陷不属于任何单个子系统）。产出四样：

1. **触及子系统清单**：每个标类型——逻辑型（接缝对面是自有代码，测试可闭环）/ 边界型（对面是外部现实，机内只验契约形状，行为验收写真机清单）。按子系统派子卡前核架构法第一条的**派卡资格四条**（有界文件集、契约面可枚举、依赖可排 DAG、有类型标注）；不满足的只是一组文件，按文件改、不按子系统派。
2. **故事映射**：逐条「故事/承重步骤 → 实现责任 → 真实消费者 → 集成与回归负责人」。每条跨子系统可观察行为再写一行**行为闭环**「触发者 → 权威事实/载体 → 消费者 → 可观察结果 → 实现责任」；触发条件或结果说不清退回 spec；没有实现或回归责任不得推进。没有真实消费者的接口/基础设施不单独派卡；工程子卡可不单独产生用户可见结果，但不能因技术通过就宣布故事完成。
3. **工作单元与依赖**：单轮能交付的写一个有界工作单元及内部顺序，不强造子卡。要扇出的标出**首故事子卡**：单独先走完一轮，`--no-ff` 合入父卡分支的提交即其余子卡的共同基线；其余子卡每条依赖注明是**契约/数据硬依赖**（前卡的产物或事实是后卡开工前提）还是**施工排序**（共享文件、机器、checkout 等资源冲突），不得把后者伪装成架构依赖。一批不超过两张、只在既有边界上扇出。工作单元圈不出有界文件集时先插竖切还债卡（架构法第三条），不造空子卡掩盖范围。
4. **风险对抗审查**：用 `defect-families` 找与本故事和接缝真正相关的失败族，结论写进对应子卡或父卡的验收责任；「无风险」须说明依据。

凡结论依赖**行为事实**（某事件走不走某通路、某字段实际由谁写入）而非可 grep 的 API 事实，显式标「未验证，需真机」并汇总进真机清单，不按推测写成结论——夹具可以编码一个不存在的世界，测试会全绿地验证它。

**拍板即回写**：协调者拍板后，裁决逐岔口回写稿首清单，头部状态行更新为「已拍板（日期）」，与裁决同批提交；状态行与裁决记录不一致视同未拍板。产物不入库，会话一断就是孤儿。

## 需冻结的外部承诺（条件节）

**入口判据**：只有本轮新增/变更的接缝被独立工作单元共同依赖，或构成新的对外兼容承诺（跨仓、跨进程 wire），才写本节；已有稳定契约引用版本即可，不重述；同一工作单元内可逆的内部方法不入。无冻结对象就写一行「无新增冻结对象 + 复用契约及版本」，不造空清单。

- **查证三条**：依赖库的既成行为（读限、超时、保活、握手时序）也是契约，逐条读依赖源码钉死并带出处；契约对侧的每个常量查证谁真的发出、谁真的消费，零使用的标「疑似漂移」不照抄；能算出金样本的（哈希、密钥派生、编码格式）写成测试，跨仓 wire 契约可由消费方产出用例、提供方回放。
- **条目原子化**：一条 = 一支可独立判 pass/fail 的断言；复合句拆开，也不许一条打包整个 wire 形状。
- **只收接缝断言**：单包实现选择（私有函数处置、内部命名、遍历顺序）不入——实测一份契约膨至 86 条，大半是实现规格。
- **拍板记录三重闸门**：同时满足难逆转、无上下文会惊讶、真取舍才记一段，含被否方案；尤其记「反过来写不会有任何测试变红」的决定。
- **冻结即提交**；已冻结内容的变更 = 重走本节 + 审核。需要骨架供两侧独立编译时只建可编译接口/类型/接线，不写业务行为、不返回硬编码成功。

## 红线

- **边干边落台账**（纪律见网关「台账纪律」节；派发时作为附录随本块注入）。
- **本节点的产出物是计划文档，不是实现代码**：不写实现、不建脚手架、不「顺手把活干了」。同场 prompt 里出现实现级验收判据时，那是 implement 的完成标准；plan 的完成标准只有一条：计划落盘且自检通过。
- **依赖的输入（spec 等）缺失或读不到时，提问，不自造**：远程发工单问协调者，本地问用户；自写的输入会让后续所有节点建立在虚构之上。
- 凡有需要**驱动派发系统自身**的验收步骤，标注「本 task 由协调者执行，不派发」。

## 自审

故事/步骤覆盖；待验证假设有动作与阻塞范围；决策权限写清。L3 另核：待拍板清单在稿首、行为闭环每行五格完整、依赖分清硬依赖与施工排序、真机清单已汇总、冻结节有结论（含「无」）。
