# Finish：收尾

**角色**：协调者。收尾是裁决密集节点，机械步骤可派，每个裁决归人。

## 顺序

0. **核最终验收**：L2/L3 的全部必交故事、对应原型/流程图版本和关键反例已有实际证据；L3 重档须有**最后一批集成之后**的父卡最终验收记录，Wave 0 阶段通过、子卡技术绿或另开修复卡不能代替。指定浏览器/机器的证据不得擅自换成“等价”环境；原承诺欠交与脱敏/隐私/安全红线不得仅转 roadmap 后通过。L1 快道则核 review 与一眼可验的真机结果。缺项退回相应验收/实现，不进入合并与归档。

1. **当前树新鲜全量**——「早些时候绿过」不算数。**CI 的静态门禁在本地前置**：格式、lint 这类推送后才被 CI 看见的检查，合并前先在本地跑（Go 仓即 `gofmt -l $(git ls-files '*.go')` 须为空）。2026-09-28 实测：B409.5/6 的 11 个未格式化文件指望 CI 兜底，而 main 十二天没推送，脏提交攒到 559 个才暴露，格式门禁 7 连红。红了就地停住，不进入任何清理。

2. **集成方式是人的决定**：呈现三选项（本地合并 / PR / 保留分支）并等待，不自作主张，也不主动提议丢弃。丢弃工作需要用户显式确认。

3. **合并后**：结果树再跑全量（第 1 步的静态门禁同权重）；红了停在原地，不清理不收尾。

4. **原型基准回流**（项目有 `prototypes/base/` 时，先合并后回流）：本分支的前端形态改动回流基准站——基准靠流程副产物保鲜，不靠专项重扫。

5. **文档对齐**：受本分支影响的文档逐个过。**事实性修正自动做**（版本号、命令、路径）；**叙事改写、删除、涉安全的必问**——停/不停按这两类清单执法，不凭感觉。

6. **残余落账**：本分支凡标过「未验证」「退回裁决」「下一期」的条目，逐条核对已落 `docs/roadmap.md`（残余账本）；仍散在注释、验收清单或对话里的，此刻收进去——finish 是残余的最后一道收集网。

7. **归档收口**：远程任务先归档成功、再谈清理（顺序反了会留孤儿）。验收没过不归档。

## 红旗

| 念头 | 事实 |
|---|---|
| 「测试早上全绿过，直接合」 | 分支在动、基线在动。新鲜证据是收尾的入场券。 |
| 「格式是小事，CI 会兜底」 | CI 只在推送后才跑。main 十二天不推送，11 个脏文件攒出 7 连红（2026-09-28 实测）。静态门禁前置到合并前，别让 CI 当第一读者。 |
| 「先清理工作区再收口」 | 顺序反了。收口被拒时，已删的现场救不回来。 |
