# Finish：收尾

**角色**：协调者。收尾是裁决密集节点，机械步骤可派，每个裁决归人。

## 顺序

1. **当前树新鲜全量**——「早些时候绿过」不算数。红了就地停住，不进入任何清理。

2. **集成方式是人的决定**：呈现三选项（本地合并 / PR / 保留分支）并等待，不自作主张，也不主动提议丢弃。丢弃工作需要用户显式确认。

3. **合并后**：结果树再跑全量；红了停在原地，不清理不收尾。

4. **基准回灌**（先合并、后回灌，锚点才指向主线提交）：
   - 有目标图：本分支图 diff absorb 回基线；
   - 有原型基准：本分支的前端形态改动回流基准站；
   - 基准靠流程副产物保鲜，不靠专项重扫——跳过这步就是在给未来的自己埋一张腐烂的地图。

5. **文档对齐**：受本分支影响的文档逐个过。**事实性修正自动做**（版本号、命令、路径）；**叙事改写、删除、涉安全的必问**——停/不停按这两类清单执法，不凭感觉。

6. **归档收口**：远程任务先归档成功、再谈清理（顺序反了会留孤儿）。验收没过不归档。

## 红旗

| 念头 | 事实 |
|---|---|
| 「测试早上全绿过，直接合」 | 分支在动、基线在动。新鲜证据是收尾的入场券。 |
| 「先清理工作区再收口」 | 顺序反了。收口被拒时，已删的现场救不回来。 |
| 「基准回灌下次一起做」 | 下次的分支 diff 会叠在陈旧基线上，absorb 从此对不上。 |
