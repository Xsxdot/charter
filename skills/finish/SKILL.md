# Finish：收尾

协调者节点：机械步骤可派，每个裁决归人。

## 两级

- **卡级 finish**（每张卡）：触及包测试绿 + 全量编译过 + 故事级检查绿 + 首跑项真机证据 → `git merge --no-ff` 合入集成分支 → 卡上记「怎么验证」（命令与入口）。**不跑全量**。
- **批级 finish**（集成父卡）：集成分支上**跑一次全量** + 整体走查（review 批级验收）→ 回旋镖对账 → `git merge --ff-only` 进 main。无父卡的单卡自己就是一批，两级一次做完。

**集成分支**：一批卡共用一张集成父卡，分支 `cards/<父卡号>-charter` 从 main HEAD 拉出；**一个仓同一时间只有一个活跃集成分支**；**main 只从集成分支 ff-only 合入，合入后不再全量**；热修也经集成分支（拉新的集成父卡），不直推 main。

## 顺序

0. **核验收记录**：review 最终裁决存在且通过——单卡核全部必交故事、原型/流程版本与关键反例的实际证据；子卡核阶段裁决与真实消费者接入条件；父卡核**全部子卡合入之后**的最终验收；L1 核单审的复跑/变异/真机证据。指定浏览器/机器的证据不得换「等价」环境；原承诺欠交与脱敏/隐私/安全红线不得仅转 roadmap 后通过。缺项退回 review/implement，不进合并与归档。
1. **当前树新鲜全量**（限批级；卡级只跑触及包测试 + 全量编译 + 故事级检查），「早些时候绿过」不算。**CI 的静态门禁本地前置**：格式、lint 等 CI 才看见的检查合并前先本地跑（Go 仓 `gofmt -l $(git ls-files '*.go')` 须为空）。红了就地停住，不进入任何清理。
2. **集成方式是人的决定**：单卡与父卡呈现三选项（本地合并 / PR / 保留分支）并等待，不自作主张、不主动提议丢弃，丢弃需用户显式确认。**每张卡的目标是集成分支，不是 main**：`git merge --no-ff <卡分支>` 进集成分支，合并提交即后续卡基线（`git merge-base --is-ancestor` 核）；main 只由批级 finish 以 `git merge --ff-only` 从集成分支合入。
3. **合并后**：卡级在集成分支重跑触及包测试 + 全量编译 + 故事级检查；批级 ff-only 后树与集成分支一致，不再全量（ff 失败 = 集成分支落后 main，先把 main 合进集成分支重走第 1 步）。静态门禁同权重；红了停在原地不清理。
4. **原型基准回流**（有 `prototypes/base/` 时，合并后）：前端形态改动回流基准站。
5. **文档对齐**：受本分支影响的文档逐个过。**事实性修正自动做**（版本号、命令、路径）；**叙事改写、删除、涉安全的必问**。
6. **残余落账**：本分支标过「未验证」「退回裁决」「下一期」的条目逐条核对已落 `docs/roadmap.md`；仍散在注释、验收清单或对话里的此刻收进去。
7. **归档收口**：远程任务先归档成功、再谈清理（顺序反了留孤儿）。验收没过不归档。父卡只在全部子卡归档后归档。

## 红旗

| 念头 | 事实 |
|---|---|
| 「早上全绿过，直接合」 | 分支在动、基线在动，新鲜证据是入场券。 |
| 「格式是小事，CI 会兜底」 | CI 只在推送后才跑，门禁前置到合并前。 |
| 「先清理工作区再收口」 | 顺序反了，已删的现场救不回来。 |
