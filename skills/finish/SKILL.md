# Finish：收尾

协调者节点：机械步骤可派，每个裁决归人。

## 两级

- **卡级 finish**（每张卡）：触及包测试绿 + 全量编译过 + 故事级检查绿 + 首跑项真机证据 → `git merge --no-ff` 落入集成分支 → 卡上记「怎么验证」（命令与入口）。**不跑全量**；超线容器计数下降时收紧基线。
- **main 快进**：只能 `git merge --ff-only` 到集成分支上一个**全量全绿**的提交，**用户点头**后执行；热修同路，不直推 main。

**常设集成分支**：一个仓一条，从 main 拉出、长期存在；卡过了卡级验证就落入，不等别的卡。**全量只在它上面跑**：按提交触发、同一时间只跑一个、结果按提交号留档；卡与父卡都不跑。判定只有全绿与红。**红了定归属**：从上次全绿以来落入的卡里找，修复作为一张卡落入，main 停在原地。扇出 L3 的父卡分支只承载自己的子卡，父卡验收通过后整体落入。

## 顺序

0. **核验收记录**：review 最终裁决存在且通过——单卡核全部必交故事、原型/流程版本与关键反例的实际证据；子卡核阶段裁决与真实消费者接入条件；父卡核**全部子卡合入之后**的最终验收；L1 核单审的复跑/变异/真机证据。指定浏览器/机器的证据不得换「等价」环境；原承诺欠交与脱敏/隐私/安全红线不得仅转 roadmap 后通过。缺项退回 review/implement，不进合并与归档。
1. **当前树新鲜验证**：卡级跑触及包测试 + 全量编译 + 故事级检查；main 快进以集成分支上该提交的全量运行记录为准。「早些时候绿过」不算。**CI 的静态门禁本地前置**：格式、lint 等 CI 才看见的检查合并前先本地跑（Go 仓 `gofmt -l $(git ls-files '*.go')` 须为空）。红了就地停住，不进入任何清理。
2. **落集成分支归协调者，main 快进与丢弃分支归用户**：review 通过即 `git merge --no-ff <卡分支>` 进集成分支（扇出 L3 的子卡进父卡分支），不逐张等用户，合并提交即后续卡基线（`git merge-base --is-ancestor` 核）；main 快进与丢弃分支才呈现选项并等待，不主动提议丢弃，丢弃需用户显式确认。
3. **合并后**：卡级在集成分支重跑第 1 步三项；快进后树与该全绿提交一致，不再全量（ff 失败 = 集成分支落后 main，先把 main 合进集成分支，以新提交的运行记录为准）。静态门禁同权重；红了停在原地不清理。
4. **原型基准回流**（有 `prototypes/base/` 时，合并后）：前端形态改动回流基准站。
5. **文档对齐**：受本分支影响的文档逐个过。**事实性修正自动做**（版本号、命令、路径）；**叙事改写、删除、涉安全的必问**。
6. **残余落账**：本分支标过「未验证」「退回裁决」「下一期」的条目逐条核对已落 `docs/roadmap.md`；仍散在注释、验收清单或对话里的此刻收进去。
7. **归档收口**：远程任务先归档成功、再谈清理（顺序反了留孤儿）。验收没过不归档。父卡只在全部子卡归档后归档。

## 红旗

| 念头 | 事实 |
|---|---|
| 「早上全绿过，直接合」 | 分支在动、基线在动，新鲜证据是入场券。 |
| 「格式是小事，CI 会兜底」 | CI 只在推送后才跑，门禁前置到合并前。 |
| 「先清理工作区再收口」 | 顺序反了，已删的现场救不回来。 |
