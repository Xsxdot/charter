# Spec：需求成形

协调者与用户的对话回路。**硬门：设计未获用户批准前禁止写码、建脚手架、调实现类 skill。**设计可只几句话，但必须呈现并获批。

## 承重歧义

spec 只消除**承重歧义**。先用需求自己的词说清谁在什么条件下使什么事实变化、谁观察到什么。每条关键陈述做**二解测试**：两个零上下文下游能作两种合理但不兼容的解释，且差异改变可观察行为、事实归属、系统边界或不可逆成本，即承重歧义。

- 可从系统核实的是事实，自己查；用户意图或取舍才上桌。
- 局部可逆的实现选择不追问，写清决策者、边界与结果交下游。
- 拿不准是否承重，只比两种最小解释的后果。

**停止条件**：下游无需替用户作未授权的承重决定，而非问完所有问题。

## 承诺清单

列必交故事 S1…Sn：谁从什么真实入口触发、期望观察到什么、关键失败如何呈现、在哪个环境验证；未承诺的入 Out of Scope。受形态/流程约束的故事引已批准原型/流程版本。故事 ID 与 spec 修订号贯穿 plan、子卡和验收；范围变化留痕，欠交不改名为新需求。**不能压成第一条演示。**

验证入口要有**真实消费者**：存量符号给调用方与出处，新建符号写明消费者与进入边界，不写死签名；无生产调用方的纯函数不占名额。外部格式/协议的解析/编码入口即缝上符号，表驱动测试算穿过该缝。

## 对话纪律

- **一次只问一个问题**。
- **事实归你查，决策归用户**。
- **只在确认承重岔口时才给方案**：推荐与必要备选，不凑数量；不相容于已冻结契约或产品不变式的标「需改契约」或不上桌；YAGNI。
- 追问只由未消除的承重歧义驱动，只剩一种解释即停。
- 用户原方向是默认项；想改必须举证，且**永不自决**。

## L3：边界与接缝

跨子系统需求定目标边界三行：**子系统职责** / **权威状态归属** / **允许的依赖方向**。**定语义，不抢写新签名**：内部接缝的精确签名在首故事实现中形成，只有被独立工作单元共同依赖或构成对外兼容承诺时才由 plan 冻结。

**选首故事**：高价值、最早暴露承重未知的最薄故事，说明它验证什么、谁依赖它。沿已批准边界做真实生产竖切；穿透他方内部的不能作后续子卡基线。

## 定级（只判一次）

按**定稿范围**判，判决写进 spec 头部。两问：改动跨几个子系统的契约面？动不动契约层（实现或对接既有跨仓/跨进程 wire 契约，本侧零修改也算动）。

| 答案 | 级 | 路由 |
|---|---|---|
| 单子系统、不动契约、L1 两判据全中 | **L1** | implement → review → finish（spec 即 plan） |
| 单子系统，不动契约 | **L2** | plan → implement → review → finish |
| 跨子系统，或动（含对接）其契约 | **L3** | plan（拆分与接缝）→ 单卡或各子卡 implement → review → finish；扇出时父卡终 review → finish |

**L1 两判据**（全中才是 L1）：①**plan 增量为零**——spec 末尾三行（改哪文件、怎么验收）即全部实现决定，同一份 spec 挂 `spec:` 与 `plan:` 过 implement 门；②**验收一眼可核**。L1 省文档不省纪律：批准硬门与测试纪律照走。只命中①按 L2，用户可在状态行裁决跳 plan。

**文档/规则正文类卡不出 plan**：产出物是文档/规则正文、不改运行代码的卡，spec 内逐文件改法表即 plan，不论级别直接 implement（同一份文件挂 `spec:` 与 `plan:`）。

**L3 扇出否**：单子系统工作量超流程固定成本（实测约 70 分钟）才扇出，只在既有边界上、一批 ≤ 2，新缝先由首故事串行长出；否则单卡单轮交付。**判错走跨流迁移**：带产出显式迁移留痕，不重建卡。

## 骨架

```
问题陈述 / 级别 / 方案（含弃选）/ 必交故事 / L3 边界与接缝 / 首故事（L3 扇出）/
实现决定 / 测试决定 / Out of Scope（必写）/ 备注 / 读数与证据（末节）
```

**可见性**判落点：实现决定只写决策级落点与用户可见的名字（命令名、配置键、错误文案），内部符号名与文件路径归 plan。现状事实带 `文件:行` 出处、标现状读数，执行节点复核；绿地不虚构。代码只留承载决策的形态。读数与证据进末节（原始命令与输出，一行一条），裁决与结论回写正文。

## 收尾

**自检**：TBD 清零、每条关键陈述至多一种承重解释；骨架各段齐全、Out of Scope 不许空、验证入口有真实消费者；定级已按定稿范围复核入头部；L3 三行边界可供首故事实现。

**残余落账**：Out of Scope 分「永不做」与「本期不做、后续要做」，后者逐条落 `docs/roadmap.md`（一行一条、注明来源；下一期从此取条重走 spec 门），不许只留在 OOS。

用户审文件后**批准即回写**——判决与日期写回 spec 头部状态行，不许只活在对话。交棒：L1 与文档/规则正文类卡 → implement；L2/L3 → plan。**批准前禁止实现动作**。
