# Integrate：集成

**前置**：全部子系统子卡完结（聚合闸放行）。**角色**：可派执行者干活，并入主线的裁决留协调者。

## 做五件事

1. **合分支 + 全量**：各子系统分支合入集成分支；跑**全量**测试——这是三段律里全量的法定位置之一。此处红的按接缝缺陷处理，不退回单个子系统。

2. **契约对照**：有图项目跑全量与分支视图两次对照，fail 清单清零。**集成阶段暴露的契约错配应为 0**——契约错配的正确暴露点在 Ticket 0 编译期；这里出现一个就记一个协议缺陷，回溯 contract 节点哪里漏了。

3. **生产闭环对账**：逐行核对 breakdown 的行为闭环在生产代码中真实成立——触发者会写、权威事实有载体、消费者会读、结果可观察。只有接口/空壳/测试替身或测试调用而无生产调用方，按未完成处理；就地补齐，或显式退回 spec/contract/breakdown，不得靠全量测试绿放行。

4. **接缝缺陷记账**：「集成阶段新发现缺陷数」逐个记录（现象/根因/属于哪条接缝）。这是流程自身的测量点——它衡量契约先行有没有兑现，数据回写协议基线。本期不处理的缺口（含「退回 contract 裁决」类）逐条落 `docs/roadmap.md`（残余账本），不许只留在代码注释或验收清单里——注释不是队列，没人会回来读它（实测：一处契约缺口带着两条修法和倾向死在组装点注释里）。

5. **回旋镖对账**：把 plan/breakdown 阶段的预测（判据、影响面、耗时、「无风险」结论）与实测逐条对账，差异写进卡。预测错误不是过失，是校准数据——但**不对账才是**。

## 棘轮

本次接线让某接缝的存量直调下降 → 在同一变更集里提请调低该接缝预算。预算调整与产生它的重构同变更集，审计自洽。

## 交棒（集成完成 ≠ 完成）

合并只是 acceptance 的入场券。收尾必须显式交棒——「下一步：acceptance，真机清单 N 条待执行」写进 ledger/集成报告；会话断在此处，未执行的验收清单在 ledger 登记「未执行」——孤儿必须有标记。实测教训：写得最细的真机验收清单（14 条契约对账 + 6 小节真机）零执行、账本无分节，项目以机内全绿冒充了它自己定义的完成。

## 红线

并入主线、归档收口是协调者裁决，执行者到「集成分支就绪 + 报告」为止。
