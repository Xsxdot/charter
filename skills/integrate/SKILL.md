# Integrate：集成

**前置**：全部工程子卡已完成 review 与子卡阶段技术验收；各故事批次在父卡「待批次」期间由协调者组织实际合流、演示和已有故事回归，逐批留下提交、环境、结果、未核销承诺与下一批基线。每批工作可以委托，但**不得反复派发父卡 `integrate` 节点**：handoff 的该节点轮次按卡累计，且成功边无条件进入最终验收；它不能表示“还有下一批”。**本节点只在全部批次完成后派发一次终局集成**，共同基线与适用契约版本须可取得。并入主线的裁决留协调者。

## 做五件事

1. **终局合流 + 全量**：确认各批合流提交和回归证据可取得，合入最后尚未合的分支；跑**全量**测试——这是三段律里全量的法定位置之一。此处红的先定位归属，跨卡接缝缺陷由集成负责，单卡局部回退对应子卡。

2. **边界与契约对照**：有图项目跑全量与分支视图对照，fail 清单清零。逐条核已冻结的共享/外部面和已有稳定契约；无新增冻结物时核 spec 的依赖方向与真实代码消费链，不强找 Ticket 0。集成才暴露的类型或行为错配记协议缺陷并追溯具体遗漏点；若发现确需新增独立共享接缝或对外承诺，回 contract 冻结后再派相关工作。

3. **生产闭环对账**：逐行核对 breakdown 中全部必交故事的「触发者 → 权威事实/载体 → 消费者 → 可观察结果 → 实现责任」在生产代码中成立，并与故事/原型版本对应；已由 Wave 0 交付的故事核其已验基线与各批回归，不要求新子卡。只有接口/空壳/测试替身或测试调用而无生产调用方，按未完成处理；按缺口性质回实现、breakdown、spec，命中新增冻结判据才回 contract，不得靠全量测试绿放行。

4. **缺陷记账**：「集成阶段新发现缺陷数」逐个记录（现象、根因、属于原承诺遗漏/假设错误/边界变化/新需求哪类）。本期不处理的缺口逐条落 `docs/roadmap.md`（残余账本），但已承诺故事的欠交不能只转修复卡便宣称父卡完成。

5. **回旋镖对账**：把 plan/breakdown 阶段的预测（判据、影响面、耗时、「无风险」结论）与实测逐条对账，差异写进卡。预测错误不是过失，是校准数据——但**不对账才是**。

## 棘轮

本次接线让某接缝的存量直调下降 → 在同一变更集里提请调低该接缝预算。预算调整与产生它的重构同变更集，审计自洽。

## 交棒（集成完成 ≠ 完成）

集成只是最终验收的入场券。逐批演示与回归证据已在父卡「待批次」期间入账；本节点报告须显式标明「阶段：最终验收；故事：S1…Sn；各批证据索引；所引 plan 版本；下一步：最终验收；真机清单待核」。会话断在此处，未执行的验收清单在 ledger 登记「未执行」——孤儿必须有标记。实测教训：写得最细的真机验收清单零执行、账本无分节，项目以机内全绿冒充了它自己定义的完成。

## 红线

并入主线、归档收口是协调者裁决，执行者到「集成分支就绪 + 报告」为止。
