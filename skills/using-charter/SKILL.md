# Using Charter

charter 以用户故事验证结果、按子系统保持代码责任、让 Agent 的自主决定对人可见。

**动手前先定位节点。**开发请求先判断所在节点、调用对应 skill 再开始；哪怕 1% 可能适用也先调用确认。

## 节点地图

```
bug/测试失败/诡异行为 → implement（排查节：无根因不许修）→ review → finish
需求/想法 → spec（收尾定级）
  ├─ L1 微改（plan 增量为零 + 验收一眼可核）→ implement → review → finish（spec 即 plan）
  ├─ L2 单子系统 → plan → implement → review → finish
  └─ L3 跨子系统 → plan（拆分、接缝、需冻结的外部承诺）
      ├─ 未扇出：同 L2
      └─ 扇出：首故事子卡先走完一轮合入父卡分支，其余分批同序列（一批 ≤ 2）
         → 父卡 review（全部故事终验）→ 父卡 finish
```

`architecture-law` 是参考法：spec / plan / review 按需查阅，不自动注入。契约冻结是 plan 的条件节，只为新增/变更的共同依赖接缝或对外承诺写。扇出是例外：只在既有边界上，新缝先串行长出。人工 move 与 `card dispatch --step` 不校验列，本图**非机器保证**，靠 review/finish 证据纪律把关。

**一律建卡**（2026-10-20 用户定）：进流程的请求不论级别先 `handoff card add`，L1 不例外——「小活可无卡」实测滑成全由自己做。finish 时残余落 `docs/roadmap.md`。

定级判据与判决见 spec「定级」节与头部；判错走**跨流迁移**（带产出显式迁移留痕），不推倒重建。

## 交回物纪律

1. **执行者交回物首节固定「偏离与自主决定」**（卡 note / 报告 / 交棒声明）：①与已批准 plan/spec 不一致处；②自行拍板内容与理由；③是否在 plan「决策权限」授权内。无偏离写「无」，不得省略；未进该节的偏离视同未披露。
2. **产出型节点（spec/plan/implement）产出物末节「读数与证据」**：只收原始命令与输出，一行一条；裁决与结论回写正文；不再建独立台账文件。review 只读，命令与输出进裁决表。

## 红旗

| 念头 | 事实 |
|---|---|
| 「太简单，不用走节点」 | spec 可只几句话；跳过的不是仪式，是判据。 |
| 「记得那个 skill 说什么」 | skill 会演进，读当前版本。 |
| 「先探索代码再说」 | 事实调查、排查第 0 步正是探索——节点内的工作。 |
| 「用户催得急」 | 急 = 走轻档，不 = 跳节点。 |
| 「级别判错了，重建卡吧」 | 跨流迁移带产出走；重建断审计链。 |
| 「有规则不让我做 X」 | 引出原文与出处，引不出即不存在。 |

用户显式指令优先于本套件。
