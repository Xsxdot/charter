# Using Charter

charter 以用户故事验证结果、按子系统保持代码责任、让 Agent 的自主决定对人可见。

**动手前先定位节点。**开发请求先判断所在节点、调用对应 skill 再开始；哪怕 1% 可能适用也先调用确认。

## 节点地图

```
bug/测试失败/诡异行为 → implement（排查节：无根因不许修）→ review → finish
需求/想法 → spec（收尾定级）
  ├─ L1 微改（plan 增量为零 + 验收一眼可核）→ implement → review → finish（spec 即 plan）
  ├─ L2 单子系统 → plan（产出骨架）→ implement → review → finish
  ├─ 跨子系统各改内部、不动契约面 → 每个子系统一张 L2，挂同一集成父卡并行
  └─ L3 动跨子系统契约面 → plan（拆分、层表、骨架、楼层图、契约面冻结）
      ├─ 未扇出：同 L2
      └─ 扇出：骨架合入父卡分支后子卡按依赖图分批
         → 父卡 review（全部故事终验）→ 父卡 finish
卡落集成分支；全量在集成分支；main 快进到全绿提交（用户点头）
```

`architecture-law` 是参考法：spec / plan / review 按需查阅，不自动注入。契约冻结是 plan 的条件节，只为新增/变更的共同依赖接缝或对外承诺写。扇出是例外。人工 move 不校验列，本图**非机器保证**，靠 review/finish 证据纪律把关。

**一律建卡，轻档除外**：进流程的请求不论级别先建卡，L1 不例外；轻档四判据全中才不建卡（见 spec「定级」节）。finish 时残余落 `docs/roadmap.md`。

定级判据与判决见 spec「定级」节与头部；判错走**跨流迁移**（带产出显式迁移留痕），不推倒重建。

## 交回物纪律

1. **执行者交回物首节固定「偏离与自主决定」**（卡 note / 报告 / 交棒声明）：①与已批准 plan/spec 不一致处；②自行拍板内容与理由；③是否在 plan「决策权限」授权内。无偏离写「无」，不得省略；未进该节的偏离视同未披露。
2. **plan / implement 的「读数与证据」随卡走**：只收原始命令与输出，一行一条；无随卡存储才进仓，且只留指针与一行读数，不贴原始输出；有独立运行记录的条目只写指针；spec 的读数留在 spec 末节，随 spec 进仓。裁决与结论回写正文；不再建独立台账文件。review 只读，命令与输出进裁决表，裁决表同样随卡走。

## 给人的与给 agent 的

每样产出问三句：人要对它做决定或需要知道吗——**给人的**，经协调者一个口子给人，决定留一份进仓；以后别的卡的 agent 需要吗——**跨卡存活的**，进仓，尽量是代码形态；只在本卡内 agent 之间交接吗——**随卡走的**，挂在卡上。

**给人的只有六类**：①批准方向（spec 的故事、范围、待拍板岔口）；②确认形态（原型与界面）；③裁决偏离（越权、范围变化、与原话对不上）；④批准例外与不可逆的事（上调超线基线、豁免、部署、删除）；⑤放行进主线（附带里面有什么、哪些未验）；⑥验收结果（现状与未验证项）。其余在 agent 之间解决，除非升级成③或④。**每条自成一体**：不打开仓库里任何文档就能决定；一条只问一件事，带选项、推荐与后果；用户原话逐字带着走，转述单独标明。

## 红旗

| 念头 | 事实 |
|---|---|
| 「太简单，不用走节点」 | spec 可只几句话；跳过的不是仪式，是判据。 |
| 「记得那个 skill 说什么」 | skill 会演进，读当前版本。 |
| 「先探索代码再说」 | 事实调查、排查第 0 步正是探索——节点内的工作。 |
| 「用户催得急」 | 急不改判据：轻档四判据全中才不建卡，其余照走节点。 |
| 「级别判错了，重建卡吧」 | 跨流迁移带产出走；重建断审计链。 |
| 「有规则不让我做 X」 | 引出原文与出处，引不出即不存在。 |

用户显式指令优先于本套件。
