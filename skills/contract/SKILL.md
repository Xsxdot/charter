# Contract：契约落地与冻结

**角色**：落地与查证可派执行者；协调者裁定冻结范围，改变用户结果或对外承诺的产品取舍才请用户拍板。

**入口判据**：本轮确有新增/变更的独立工作单元共同依赖的接缝，或新的对外兼容承诺，才进入本节点。已有稳定契约从一开始遵守并引用版本，不为重述它再冻结；同一工作单元内可逆的内部方法不进本节点。Wave 0 后的冻结以其已验提交和分工草案为依据；若新的外部承诺是 Wave 0 真实运行的前提，只提前冻结该缝，并在 Wave 0 中验实际行为。无冻结对象直接去 breakdown/plan，不产空 contract 或 Ticket 0。

## 两段

**1. 落地（机械，可派）**：先核对 spec 的批准状态与本次冻结理由、生产者、独立消费者和适用基线。Wave 0 后进入时核对已验提交、故事/原型版本和分工草案；前置外部承诺则核对对侧规范或协商结果，不虚构尚未运行的 Wave 0 证据。存量签名对着源码查证，新建面在最小可编译骨架或协议金样本中产生，产出只覆盖受影响接缝的契约增量。

查证纪律三条：

- **依赖库的既成行为也是契约**：读限、超时、保活、握手时序这类库默认行为，逐条读依赖源码钉死并带出处（文件:行）——它们与签名同等承重，凭印象写即错。
- **对侧常量查执法**：契约对侧的每个常量（错误码、状态名、字面值），查证**谁真的发出、谁真的消费**。零使用的常量标注「疑似漂移」，不得作为事实源头照抄——对侧代码里的死常量可能带着一条假注释存活多年。
- **可执行冻结优先于纸面冻结**：能算出金样本向量的（哈希、密钥派生、编码格式），算出来写成测试；跨实现一致性靠测试锁定，不靠「逐字节一致」的声明。命中跨仓/跨进程 wire 契约时，可执行冻结的另一形态是**消费方产出契约用例、提供方回放**（CDC 思路）——不建专项基建，随触及该契约的卡绞杀式落地。

**2. 冻结（提交，不可逆性在此）**：

- 骨架只在新建面确需供两侧独立编译/消费时建立：接口、类型、事件及必要接线须可编译，消费方契约断言或协议金样本须能发现错配。Ticket 0 不写业务行为、不返回硬编码成功；Wave 0 的真实竖切归 implement/review/acceptance，不能在本节点用假结果替代。
- **契约增量文档即冻结物**，review 节点按它逐条对账。
- **冻结即提交是本节点的法定机械动作**（仓库的首个 commit 也不例外），无需请示；push 与并入主线才归用户裁决。
- **冻结清单条目原子化（双向）**：一条 = 一支可独立判 pass/fail 的断言；复合句（「吊销**与停用**主动断连」）必须拆开——下游对账是逐条打勾的，复合条目会被核了半条、漏了半条地无声放行。反向同禁：不许一条打包整个 wire 形状（一条含多键/多子语义），一条勾盖十个断言与复合句是同一种失明。粒度判据：**单独可判 pass/fail 且失败可定位**。
- **冻结物边界**：冻结清单只收**接缝断言**与命中三重闸门的决定。单包实现选择（私有函数处置、内部命名、遍历顺序这类改了对契约对侧不可见的决定）不入清单（实测：一份契约膨至 86 条，大量为此类——契约被用成了实现规格书）。查证期顺手确立的实现级决定落文档末尾**「移交 plan」附区**：不占冻结条目名额、不参与逐条打勾对账；plan 出稿时吸收，并在区头标注「已由 plan〈文档〉吸收（日期）」销区。移交区不是第二冻结清单——plan 从不吸收、或条目数逼近冻结清单本体，即为倾倒场信号，停下来重划边界。

## 拍板记录：三重闸门

契约决定写成拍板记录（一段即可），但**只记同时满足三条的**：

1. **难逆转**——回头要动多个子系统；
2. **无上下文会惊讶**——后人看到会想「修掉」这个故意为之的设计；
3. **真取舍**——存在被否掉的像样方案。

少一条就不写（防拍板记录变成会话日记）。被否掉的方案与显式的「不做」一并记录。**尤其要记「反过来写不会有任何测试变红」的决定**——步骤顺序、参数默认值这类只活在流程描述里的裁决，没有拍板记录时后人一次「顺手优化」就能无声推翻。

## 收尾自检：法定产出核对（交棒前逐项过，缺一不得交棒）

每项要**本轮的新鲜证据**（命令输出或文件指认），「应该有了」不算：

1. 契约增量文档落盘：逐条有冻结理由、生产者/消费者、语义与兼容边界；已有签名带源码出处与提交，新建面引用本轮骨架或协议版本；
2. 若需要 Ticket 0，骨架本轮编译通过并贴命令与退出码；不需要则不造空壳；
3. 命中可执行冻结的条目（哈希、密钥派生、编码格式）有金样本/消费方契约断言且本轮跑过；
4. 命中三重闸门的决定都有拍板记录；一个没命中就写「无命中」——空着与没审过不可区分。

**缺项没有静默出口**：要么就地补齐，要么把欠账逐条写进交棒声明、由协调者显式认账。静默带账离开本节点，等于把契约错配预定给集成阶段——那正是本节点存在的理由的反面。

## 纪律

- **边干边落台账**（纪律见网关「台账纪律」节；派发时作为附录随本块注入）。

- 已冻结契约的变更 = 重新走本节点 + 审核；尚未冻结的单工作单元内部方法可在批准边界内演化，不以它冒充契约变更。
- 落地阶段发现 spec 的语义定不下去（两个子系统对同一规则的归属有分歧）→ 退回 spec，不许自选。
- 交棒：前置外部承诺 → Wave 0 plan；Wave 0 后的协作冻结或轻档冻结 → breakdown。接口搬移等若改变已有故事证据，受影响故事须重验，不能沿用旧绿。
