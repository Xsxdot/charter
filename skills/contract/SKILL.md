# Contract：契约落地与冻结

**角色**：落地（查签名）可派执行者，机械；拍板归协调者 + 用户。

## 两段

**1. 落地（机械，可派）**：开工前先核对上游状态位——spec 头部状态行须已回写「已批准」，不一致先回写再引用，否则流程状态只活在会话记忆里、断点即失真。然后把 spec 的契约语义翻译成精确签名/端点/类型。每个签名都要对着现状代码查证——它们是代码事实，不是设计发挥。产出：契约增量文档，精确到可编译。

查证纪律三条：

- **依赖库的既成行为也是契约**：读限、超时、保活、握手时序这类库默认行为，逐条读依赖源码钉死并带出处（文件:行）——它们与签名同等承重，凭印象写即错。
- **对侧常量查执法**：契约对侧的每个常量（错误码、状态名、字面值），查证**谁真的发出、谁真的消费**。零使用的常量标注「疑似漂移」，不得作为事实源头照抄——对侧代码里的死常量可能带着一条假注释存活多年。
- **可执行冻结优先于纸面冻结**：能算出金样本向量的（哈希、密钥派生、编码格式），算出来写成测试；跨实现一致性靠测试锁定，不靠「逐字节一致」的声明。命中跨仓/跨进程 wire 契约时，可执行冻结的另一形态是**消费方产出契约用例、提供方回放**（CDC 思路）——不建专项基建，随触及该契约的卡绞杀式落地。

**2. 冻结（提交，不可逆性在此）**：

- 有图的项目：契约条目（允许的依赖方向、组装点、预算）写进 `codegraph/target.json`，**冻结即提交该文件**。此后对照闸门按它执法。结构树不在这里——子系统与领域的归属住在最优图 `codegraph/best.json`，改结构树是改**应然架构**，与冻结契约面是两件事。
- **绿地项目不降档：建图是本节点的法定产出**——子系统清单、依赖方向、窄缝入口在此刻最清楚，`best.json`（结构树）与 `target.json`（契约面）初版都在此落盘。「缺图所以降档」只适用于存量项目。建图时**一并声明架构形态**（一行分层声明，落项目 CLAUDE.md 或图 meta，如「平铺领域包，无横向分层」或「controller/service/dao 三层」）；无声明即适用架构法缺省合法形态，终审的「架构形态一致」检查按此声明对账。
- **骨架符号入图**：Ticket 0 引入的新符号随骨架**同一提交**写进本分支视图 diff（`codegraph/diffs/<分支>.json`）——下游 breakdown/plan 以 `--view <分支>` 叠加查询才命中得到新契约符号，图覆盖债不该由自己冻结的符号构成。分支未引入新符号则合法无视图，不造空文件；无图项目跳过。
- 骨架先行（Ticket 0）：接口/类型/事件的空壳落码，**编译必须通过**——契约错配要在编译期暴露，不留给集成阶段。**Ticket 0 只落空壳与直通镜像**（签名、类型、常量、逐行照抄既有同形方法的接线）；凡越过空壳、实现了可观测行为的（哪怕是查证时顺手写完的），其冻结语义必须当场有一支能变红的测试锁住，否则逐条写进交棒欠账——「欠账：无」与「已实现但零测试」不得并存。
- 存量无图项目：契约增量文档即冻结物，review 节点按它人工对账。
- **冻结即提交是本节点的法定机械动作**（仓库的首个 commit 也不例外），无需请示；push 与并入主线才归用户裁决。
- **冻结清单条目原子化**：一条 = 一支可独立判 pass/fail 的断言；复合句（「吊销**与停用**主动断连」）必须拆开——下游对账是逐条打勾的，复合条目会被核了半条、漏了半条地无声放行。

## 拍板记录：三重闸门

契约决定写成拍板记录（一段即可），但**只记同时满足三条的**：

1. **难逆转**——回头要动多个子系统；
2. **无上下文会惊讶**——后人看到会想「修掉」这个故意为之的设计；
3. **真取舍**——存在被否掉的像样方案。

少一条就不写（防拍板记录变成会话日记）。被否掉的方案与显式的「不做」一并记录。**尤其要记「反过来写不会有任何测试变红」的决定**——步骤顺序、参数默认值这类只活在流程描述里的裁决，没有拍板记录时后人一次「顺手优化」就能无声推翻。

## 收尾自检：法定产出核对（交棒前逐项过，缺一不得交棒）

每项要**本轮的新鲜证据**（命令输出或文件指认），「应该有了」不算：

1. 契约增量文档落盘，每个签名带现状代码出处（文件:行）；
2. 目标图已更新**且已提交**（绿地项目含初版建图）——交棒声明与冻结物同提交时写「随本提交冻结」即可，提交后无需回填哈希；引用**早前**的冻结物才必须给 `git log` 可查的哈希；Ticket 0 引入新符号的，本分支视图 diff 同提交落盘；
3. Ticket 0 骨架**本轮编译通过**——贴编译命令与退出码，不引用早前的绿；
4. 命中可执行冻结的条目（哈希、密钥派生、编码格式）都有金样本测试且本轮跑过；
5. 命中三重闸门的决定都有拍板记录；一个没命中就写「无命中」——空着与没审过不可区分。

**缺项没有静默出口**：要么就地补齐，要么把欠账逐条写进交棒声明、由协调者显式认账。静默带账离开本节点，等于把契约错配预定给集成阶段——那正是本节点存在的理由的反面。

## 纪律

- 契约变更 = 重新走本节点 + 审核，没有「顺手改一下接口」。
- 落地阶段发现 spec 的语义定不下去（两个子系统对同一规则的归属有分歧）→ 退回 spec，不许自选。
- 交棒：breakdown。

**符号锚**：项目有代码图时，文档引用现状代码推荐 `file#Symbol` 符号锚（行号会漂，符号锚配 `codegraph resolve` 查询时决议）；出稿自检跑 `codegraph resolve --doc <本文档>`，坏锚即修。
