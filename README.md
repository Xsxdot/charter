# charter

契约先行、分子系统并行的开发流程套件。流程中的每个节点是一个 skill，同一份正文有两个消费端：

1. **本地**：Claude Code 插件——SessionStart hook 注入网关 `using-charter`，节点 skill 按需加载，subagent 跑流程时逐节点注入纪律。
2. **handoff**：工作流节点的纪律块——每个节点 skill 的正文同步进 handoff 纪律块库，派发时由 agentd 注入执行者。

## 结构

入口只有两条（网关直接分流，无分诊节点）：bug → debug；需求/想法 → spec（定级与选档在 spec 收尾定稿）。

```
skills/
├── using-charter/     # 网关（hook 注入）：节点地图 + 依赖分档 + 红旗
├── spec/              # 需求成形：事实调查 + 对话纪律 + 定级选档 + 契约语义与接缝（L3）
├── contract/          # 契约落地与冻结：签名与库行为查证 + 建图 + Ticket 0 + 拍板三重闸门
├── breakdown/         # 拆解：跨子系统单 agent 出稿、协调者拍板；子卡四段式 + DAG
├── debug/             # 排查：红色反馈回路 + 无根因不许修 + 根因后分流
├── plan/              # 实现计划：零上下文格式 + 四项检查 + 日志注释步骤 + 测试范围声明
├── implement/         # 实现：TDD 铁律 + 测试三段律 + 日志注释 + 修复熔断
├── review/            # 审查：双轴不合并 + 维度化裁决表 + plan 对账
├── acceptance/        # 验收：复跑→变异→真机→才归档；API 事实 vs 行为事实
├── integrate/         # 集成（L3 重档）：全量 + 契约对照 + 接缝缺陷记账 + 回旋镖对账
├── finish/            # 收尾：合并归人 + 基准回灌 + 文档对齐
├── architecture-law/  # 架构法·子系统与领域章（法条 + 判据数字，零案例）
└── defect-families/   # 缺陷族法（通用五族 + 序列化边界 + 枚举白名单）
```

## 术语（两级）

- **子系统**：并行协作与契约冻结的单元——只以契约面对外、独立生命周期、有消费者（判据见架构法第一条）。L3 = 改动跨 ≥2 个子系统的契约面。内部有几个领域与它是不是子系统无关。
- **领域**：子系统内部按业务概念聚合的模块（domain/model 的 domain），不配契约冻结的成本；长大后可升格为嵌套子系统（递归，上限 3 级）。

## 设计原则

- **规则与知识分离**：本仓库只装不变的纪律与法条；项目知识（子系统划分、契约面、缺陷史）活在各项目仓库的最优图（`codegraph/best.json` 承载子系统与领域结构）、契约面（`codegraph/target.json`）及领域文档里。
- **硬/软依赖分档**：contract/breakdown 缺目标图时，存量项目明说降档；绿地项目不降档——建图是 contract 的法定产出。
- **法条零案例**：判据数字即先例（≥5 文件、≥40 文件、≥20 方法、3 级嵌套），不引任何真实项目路径。
- **凡红线必留正当出口**：每条禁令配显式例外，防红线诱发绕过。
- **判决一次、时刻正确**：定级不设分诊节点——在 spec 定稿、信息足够时只判一次；判错走跨流迁移，带产出走。
- **出口自检**：每个产出型节点（spec/contract/breakdown/plan/implement）交棒前核对法定产出清单，完成声明要新鲜证据；缺项没有静默出口——要么补齐，要么把欠账显式写进交棒声明由下游认账。
